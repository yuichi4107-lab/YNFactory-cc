# 無料ミニ診断 実施手順書

作成日: 2026-07-12
対象: GEO監査「無料ミニ診断」（整体院・接骨院向けAI検索露出診断）

---

## 0. 本書のスコープ（最重要・最初に読む）

本書が扱うのは、営業文面（`GEO監査\営業\個別化文面_30社.md`）で約束した**無料ミニ診断のみ**である。

| 項目 | 無料ミニ診断（本書の対象） | 参考: 有料ライト診断（3万円・対象外） |
|---|---|---|
| 質問数 | 10問（30問マスターから抽出） | 10質問 |
| 対象AI | ChatGPT・Gemini・Perplexity・Google AI Overviews（4種すべて） | 同上想定 |
| 競合比較 | 2〜3院 | 3社 |
| 改善提案 | 3項目 | 10項目 |
| 顧客側の時間負担 | ヒアリング10分のみ | 別途 |
| 費用 | 0円 | 30,000円 |

**厳守事項**:
- 質問数は必ず10問（30問マスターの全問を使わない）。
- 競合比較は2〜3院まで（4社以上と比較しない）。
- 改善提案は3項目ちょうど（多く出しすぎない）。
- 顧客への時間負担はヒアリング10分のみ。実測・採点・レポート作成は顧客の時間を使わない（担当者側の作業）。
- 費用は一切請求しない。

以降のステップで数量を変更してよい箇所はない。数量に関する判断が必要な場面（例: 競合が1院しか把握できない等）が出た場合は、担当者（オーナー）に確認してから進める。

## 1. 全体フロー概要

```
①申込受領 → ②ヒアリング(10分) → ③実測(4AI×10問) → ④採点 → ⑤レポート生成 → ⑥送付 → ⑦フォロー
```

| ステップ | 担当 | 所要時間目安 | 使用ツール | 入力 | 出力 |
|---|---|---|---|---|---|
| ①申込受領 | オーナー | 5分 | メール／フォーム／LINE／Instagram DM（返信が来たチャネル） | 返信メッセージ | ヒアリング日程調整の返信 |
| ②ヒアリング | オーナー | 10分（顧客対応）＋5分（記録整理） | 電話・オンライン通話・チャット、`ヒアリングシート.md` | 顧客の回答 | 記入済みヒアリングシート |
| ③実測 | Claude Code | 30〜45分（4AI×10問＋記録） | ブラウザ操作（Playwright）／Web検索、`スコアシートテンプレート.csv` | ヒアリングシート、30問マスター | 記入済みスコアシートCSV |
| ④採点 | Claude Code | 10分 | `スコア算定基準.md` | 記入済みスコアシートCSV | AI別スコア・総合スコア |
| ⑤レポート生成 | Claude Code | 10分 | `report_generator.py`（工程2成果物） | スコアシートCSV・院情報 | 顧客名入りHTMLレポート |
| ⑥送付 | オーナー | 5分 | メール／フォーム／LINE／Instagram DM（申込時と同じチャネル） | HTMLレポート | 送付完了 |
| ⑦フォロー | オーナー | 都度 | メール等 | 顧客からの反応 | 商談移行 or クローズ |

合計所要時間目安: オーナー対応 約25分（顧客対応10分含む）、Claude Code作業 約50〜65分。
**「返信が来たその日」に着手すれば、当日〜翌営業日中にレポート送付まで完了できる分量。**

## 2. ステップ①: 申込受領

**担当: オーナー**

1. 返信が来たチャネル（メール／フォーム／LINE／Instagram DM）を確認する。
2. 返信内容から以下を確認する。
   - 顧客が無料ミニ診断に前向きか（日程調整の返信か、質問への回答か等）
   - ヒアリング希望日時（複数候補があれば早いものを優先）
   - 連絡が取れるチャネル・宛先（レポート送付先の確定）
3. ヒアリング日程を確定し、顧客に返信する（電話・オンライン通話・チャットいずれでも可、顧客の負担が最小のものを選ぶ）。
4. 確定したら、送信管理表（既存の営業オペレーションのファイル）にステータスを更新する（本書のスコープ外の既存運用に準拠）。

**チェック**: ヒアリング日時・実施方法（電話/オンライン/チャット）・レポート送付先メールアドレスの3点が確定していること。

---

## 3. ステップ②: ヒアリング（10分）

**担当: オーナー**

> **ヒアリング前チェック（約束時間の確認）**: 送信済み文面の所要時間表記は案件により異なる。ヒアリング前に `営業\個別化文面_30社.md` の当該院セクションで約束した所要時間を確認し、その時間枠を確保すること。**No.1 ほがらか整体院（メール文面）のみ「15分程度のオンラインヒアリング」と約束済みのため15分枠で実施する**（フォーム/DM/LINEの29社は「10分」表記で統一済み）。

1. `ヒアリングシート.md` を開き、記入欄をコピーして当該顧客用の記入済みシートを作成する（保存先: 本パイプラインとは別に、顧客ごとの案件フォルダを用意している場合はそこに保存。専用フォルダがない場合は `診断パイプライン\実施記録\<院名>\` を都度作成して保存する）。
2. 電話・オンライン通話・チャットのいずれかで、ヒアリングシートの項目を10分以内で聞き取る。
3. 聞き取った内容をその場で記入する（後回しにすると記憶が薄れるため、通話中またはチャット記録から直接転記する）。
4. ヒアリング終了後、記入漏れがないか確認する。特に以下は実測に必須のため必ず埋める。
   - 院名（正式名称・表記ゆれがあれば併記。例: 「17(いちなな)整骨院」）
   - 所在地（実測で使う `{地域名}` に採用する市区町村名。例: 宇都宮市）
   - 強み症状・悩み（実測で使う `{症状・悩み}`。例: 腰痛、産後の骨盤矯正）
   - 競合として認識している院（2〜3院、正式名称）
   - レポート送付先

**チェック**: ヒアリングシートの必須項目（4章参照）がすべて埋まっていること。空欄がある場合は再度顧客に確認する。

## 4. ステップ③: 実測（4AI×10問）

**担当: Claude Code**

### 4-1. 実測前の準備

1. ヒアリングシートから `{地域名}` `{症状・悩み}` `院名` `競合院名（2院分）` を確定する。
2. 「10. 10問抽出ルール」（本書6章）に従い、30問マスターから10問を選定し、プレースホルダーを実際の値に差し替えた「実施用10問リスト」を作成する（質問文はこの時点で確定し、以降変更しない＝表現ゆれ防止）。
3. `スコアシートテンプレート.csv` をコピーし、当該案件用のスコアシート（例: `<院名>_スコアシート.csv`）を作成する。質問No・質問文・カテゴリ列を実施用10問リストの内容で埋めておく（言及有無等の結果列は未記入のまま）。

### 4-2. 実測共通ルール（全AI共通）

- **原則1回のみ実施**: 同一質問は表現を変えず、原文どおりの質問文で1回だけ入力する。複数回試して都合の良い回答を選ぶことはしない。
- **再実施が許される場合**: (a) AIがエラー・ネットワーク不調で回答を返さなかった場合、(b) 明らかに質問内容と無関係な回答（誤入力・システムメッセージ等）が返った場合、のみ再実施可。再実施した場合はスコアシートの「再実施フラグ」に◯を付け、「再実施理由」欄に理由を記録する。
- **実施日時の記録**: 各質問の実施直後に、スコアシートの「実施日時」列へ `YYYY-MM-DD HH:MM`（Asia/Tokyo、実施時点の日時をツールで取得）を記録する。全10問×4AIを同一日中に完了することを原則とする（日をまたぐと同一AIでも回答が変動し比較の前提が崩れるため）。
- **レート制限対応**: 短時間に連続入力するとレート制限・一時ブロックが発生する場合がある。1AIあたり10問の間隔は数秒〜数十秒空け、レート制限メッセージが出た場合は数分待ってから再開する（待機は再実施に該当しない）。
- **新規セッション・シークレット利用**: 各AIとも、可能な限り新規チャット／シークレットウィンドウで実施し、過去の会話履歴や検索履歴が回答に影響しないようにする（Google AI Overviewsは特に個人の検索履歴の影響を受けやすいため必須）。
- **記録する情報**: 各質問について「回答本文の該当箇所」を保存する（スクリーンショットまたはテキストのコピー）。実施記録フォルダ（`診断パイプライン\実施記録\<院名>\`）に保存し、スコアシートの「備考」欄にファイル名を記す。

### 4-3. ChatGPT（chatgpt.com）

- **ログイン要否**: ログイン要（無料アカウントで可）。無料プランの現行モデルで実施する。
- **手順**:
  1. `https://chatgpt.com/` にアクセスし、無料アカウントでログインする。
  2. 新規チャットを開始する（既存の会話履歴が影響しないよう新規スレッドを使う）。
  3. 実施用10問リストの質問文を1問ずつそのまま入力し、回答を待つ。
  4. 回答本文をコピーし、記録する。
- **無料/有料プランでの差**: 有料プラン（モデル選択・Web検索併用等）では回答精度・情報源の扱いが変わるため、必ず無料プランのデフォルトモデルで統一する。使用モデル名が画面に表示される場合はスコアシートの「備考」に記録する。
- **注意点**: ChatGPTはWeb検索機能が有効な場合と無効な場合で回答の情報源（引用有無）が大きく変わる。可能であれば「検索」機能を明示的に使わず標準モードで実施し、標準モードで有効な検索連携がある場合はその挙動を「備考」に記録する。

### 4-4. Gemini（gemini.google.com）

- **ログイン要否**: ログイン要（Googleアカウント）。
- **手順**:
  1. `https://gemini.google.com/` にアクセスし、Googleアカウントでログインする。
  2. 新規チャットを開始する。
  3. 実施用10問リストの質問文を1問ずつそのまま入力し、回答を待つ。
  4. 回答本文をコピーし、記録する。
- **注意点**: Geminiは位置情報・過去のやり取りを考慮して回答することがあるため、可能であれば位置情報の許可はオフにし、新規チャットで実施する。無料プランのデフォルトモデルで統一する。

### 4-5. Perplexity（perplexity.ai）

- **ログイン要否**: ログイン不要（ゲストモードで利用可）。ログインするとレート制限が緩和される場合があるが、無料枠の標準的な使われ方に合わせ、ログインなし（ゲスト）を基本とする。ゲストでレート制限に達した場合のみ無料アカウントでログインして継続し、その旨を「備考」に記録する。
- **手順**:
  1. `https://www.perplexity.ai/` にアクセスする。
  2. 検索モードは既定（Auto/Quick等の標準モード）のまま、Pro検索・追加ソース指定は使わない。
  3. 実施用10問リストの質問文を1問ずつそのまま入力し、回答を待つ。
  4. 回答本文および表示されている引用元（出典リンク）を記録する。
- **注意点**: Perplexityは回答に引用元リンクが明示されることが多いため、引用元の種類（公式サイト／口コミサイト／地域まとめサイト等）を必ず記録する。ゲストモードは1日あたりの利用回数制限があるため、レート制限に達した場合は時間を空けて再開する。

### 4-6. Google AI Overviews（Google検索）

- **ログイン要否**: ログイン不要。ただしログイン状態・検索履歴・位置情報によって表示内容が変動するため、**シークレット（プライベート）ウィンドウ**で実施する。
- **手順**:
  1. シークレットウィンドウで `https://www.google.com/` にアクセスする。
  2. 検索窓に実施用10問リストの質問文をそのまま入力して検索する。
  3. 検索結果ページ上部にAI Overview（AIによる概要）が表示された場合、その本文と、表示されているリンク（出典）を記録する。
  4. **AI Overviewが表示されない質問がある**（Googleの表示判定によりすべての質問で出るとは限らない）。表示されなかった場合は、スコアシートの「言及有無」欄に「AI Overview非表示」と記録し、採点上は「言及なし」と同じ扱い（0点）とする（スコア算定基準.md参照）。
- **注意点**: 地域設定（Google検索の地域）を診断対象院の所在地に近い設定にする（検索結果右下の設定、または `&gl=jp` 等のURLパラメータではなく、通常のブラウザ設定に委ねる）。過度な地域偽装は行わない。

### 4-7. 実測不可時の代替（AI別の除外・按分ルール）

以下のいずれかに該当し、あるAIでの実測が実施できない場合、そのAIを「実測不可」として当該案件の採点対象から除外する。

- ログインができない（アカウント停止・二段階認証不可等）
- サービス障害・メンテナンス等でアクセス自体ができない
- レート制限が解除されず、当日中に10問すべての実施ができない

**対応方針**:
1. スコアシートの当該AI行すべてに「実測不可」と記録する（言及有無列に記載し、素点は空欄のまま集計対象外とする）。
2. 総合スコアは、実測できたAI（3種以下）のみの単純平均で算出する（4分の1ではなく実施できた数で割る）。
3. レポートの「対象AI」欄に、実測できなかったAIとその理由を明記する（例: 「※Gemini はメンテナンスのため本診断では実測不可でした」）。
4. 実測不可が2AI以上に及ぶ場合は、レポート送付前にオーナーへ状況を報告し、日を改めて再実測するか判断を仰ぐ。

## 5. ステップ④: 採点

**担当: Claude Code**

1. `スコア算定基準.md` の点数化ルールに従い、記入済みスコアシートの各行（質問×AI）に「素点（0〜10点）」を算出して記入する。
2. AI別スコア・総合スコアを算出する（計算式は `スコア算定基準.md` 参照）。
3. 算出結果を確認し、明らかな入力ミス（言及有無と素点の矛盾等）がないか見直す。

**チェック**: スコアシートの全行に素点が入り、AI別スコア4種（または実測できた数）と総合スコアが算出されていること。

## 6. ステップ⑤: レポート生成

**担当: Claude Code**

1. 工程2で実装する `report_generator.py` に、記入済みスコアシート（CSV）とヒアリングシートから抽出した院情報（院名・地域・強み症状・競合院名等）を入力する。
2. 顧客名入りのHTMLレポートを生成する（診断サマリー／AI別スコア表／競合比較表／改善チェックリスト／免責事項の構成。10問／競合2〜3院／改善3項目のスコープに縮小されたもの）。
3. 生成されたHTMLをブラウザで開き、崩れ（文字化け・タグ崩れ・数量の誤り）がないか目視確認する。

※ 本手順は工程2成果物を前提とする。工程2が未完成の間は、`サンプル診断レポート.html` の構成を参考に、手動でHTMLまたは簡易ドキュメントを作成して代替してもよいが、その場合も質問数10問・競合2〜3院・改善3項目のスコープは厳守する。

**チェック**: レポート内の質問数表記が「10問」、競合比較が2〜3院、改善提案が3項目になっていること。サンプル固有の「SAMPLE REPORT」バッジ・架空データ注記が実運用レポートに残っていないこと。

---

## 7. ステップ⑥: 送付

**担当: オーナー**

1. 生成されたHTMLレポートを、申込受領時に確認したチャネル（メール推奨。メール以外の場合はPDF化や添付可否を確認）で顧客に送付する。
2. 送付メッセージには、診断結果の要点（総合スコア・改善ポイント3つの概要）を簡潔に添え、詳細はレポート本文を参照する形にする。
3. 送付完了後、送信管理表にステータス（診断完了・送付済み）を更新する。

**チェック**: レポートが正しいファイル形式・宛先で送付されていること。免責事項（表示・順位を保証しない旨）が含まれた状態で送付されていること。

---

## 8. ステップ⑦: フォロー

**担当: オーナー**

1. 送付後、返信がなければ3〜5営業日を目安に一度フォローの連絡を行う（改善提案について質問があるか、有料診断・改善支援への関心があるかを尋ねる）。
2. 顧客から反応があれば、有料プラン（ライト診断3万円等、別スコープ）の案内へ移行するか判断する。
3. 一連の対応結果を送信管理表・案件記録に反映し、クローズまたは商談継続のステータスを更新する。

## 9. 10問抽出ルール（30問マスターからの抽出）

`質問テンプレート30問.md`（6カテゴリ・30問）から、以下の**固定10問**を無料ミニ診断で使用する。

**カテゴリ配分は「おすすめ／比較／料金／口コミ・評判／近くの」の5カテゴリ×各2問＝10問とする**（症状・シーン別カテゴリは独立して抽出せず、{症状・悩み}の差し込みはおすすめ・料金カテゴリ内の質問で担保する）。この5カテゴリ配分は、営業文面（`個別化文面_30社.md` No.1 ほがらか整体院宛メール文面）が明示している「貴院に関する10問のAI検索質問セット（おすすめ／比較／料金／口コミ／近くの、の5カテゴリ）」という約束と完全に一致させるためであり、既に送信済みの文面と実施内容にズレが出ないようにするための必須の整合である。

| カテゴリ | 抽出数 | 質問No（30問マスター基準） | 質問文 |
|---|---|---|---|
| おすすめ | 2 | Q1 | {地域名}でおすすめの整体院はどこですか？ |
| おすすめ | | Q3 | {症状・悩み}に強いおすすめの整体院を{地域名}で教えてください。 |
| 比較 | 2 | Q8 | {地域名}の整体院と接骨院の違いを教えてください。 |
| 比較 | | Q11 | {地域名}で人気の整体院{院名}と{競合院名1}、どちらが評判がいいですか？ |
| 料金 | 2 | Q13 | {地域名}の整体の相場料金はいくらくらいですか？ |
| 料金 | | Q16 | {症状・悩み}の施術にかかる整体の料金相場を教えてください。 |
| 口コミ・評判 | 2 | Q18 | {地域名}の整体院で口コミが多いところはどこですか？ |
| 口コミ・評判 | | Q19 | {地域名}の整体院で評判が良い理由は何ですか？ |
| 近くの | 2 | Q23 | 近くの整体院を教えてください。{地域名}にいます。 |
| 近くの | | Q24 | {地域名}駅周辺で今すぐ予約できる整体院はありますか？ |
| **合計** | **10** | | |

### 差し込みルール

- `{地域名}`: ヒアリングシートで確認した院の所在地（市区町村名。例: 宇都宮市）。
- `{症状・悩み}`: ヒアリングシートで確認した院の強み症状・得意分野（例: 腰痛、産後の骨盤矯正）。1つに絞れない場合は最も強みとして訴求している症状を1つ選ぶ。Q3・Q16の2問に差し込むことで、5カテゴリ構成のままでも症状軸の確認を担保する。
- `Q11`（比較カテゴリ）: 元の30問マスターでは「A院とB院」だが、無料版では診断対象院の院名と、ヒアリングで確認した競合院のうち最も認知度が高い（顧客が最初に挙げた）1院名に置き換える。競合が1院しか確認できなかった場合はQ11を実施せず、代わりに比較カテゴリの控え問（Q9「{地域名}にある整体院を口コミ評価で比較してください。」）を使用する。
- 質問文は上記の形でヒアリング後・実測前に一度確定し、実測中は変更しない（4-2章の表現ゆれ防止ルールに従う）。

### この10問を固定にする理由

- 別の実施者・別のタイミングでも同じ10問を使うことで、スコアの再現性・比較可能性を担保する（案件ごとに担当者の裁量で質問を変えると、スコアの意味が案件間で揃わなくなるため）。
- 「おすすめ／比較／料金／口コミ・評判／近くの」の5カテゴリを各2問という配分は、営業文面が既に明示している構成そのものであり、返信してきた顧客に対して約束と異なる質問構成で実施してしまうリスクをなくす。
