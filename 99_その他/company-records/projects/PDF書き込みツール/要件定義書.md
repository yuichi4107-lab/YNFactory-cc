# 要件定義書

対象: 日本語で書き込めるAdobe Acrobat風PDF書き込みツール（ローカルWebアプリ）

## ゴール

Google Drive上のフォルダに置いたまま `python -m http.server` で起動できる、ビルド工程なしの静的Webアプリとして、PDFに日本語テキスト・フリーハンドペン・蛍光ペンで書き込みができ、書き込み内容を日本語フォント埋め込み済みの新規PDFとして保存できるツールが、Chrome（Windows/Mac）上で完成していること。

## スコープ

### やること（v1機能）
- PDF読み込み: ファイル選択ダイアログ、およびドラッグ&ドロップでのPDF読み込み
- ページ表示: pdf.jsによるページ描画、ページ送り（前/次・ページ指定ジャンプ）、ズーム（拡大縮小）
- 日本語テキスト書き込み: 任意位置への配置、テキスト編集、移動、削除、フォントサイズ変更、色変更
- フリーハンドペン: 色・太さ変更、undo（元に戻す）
- 蛍光ペン: 半透明のマーカー描画
- 保存: 書き込み内容をpdf-lib + fontkit + 同梱NotoSansJPフォントでPDFのコンテンツストリームに焼き込み、全ページ対応で新規PDFとしてダウンロード
- 動作環境: ビルド不要（npm/node_modules/webpack等の工程なし）、単一フォルダ構成、pdf.js・pdf-lib・fontkitおよびフォントファイルはすべて `pdf-annotator/vendor/` にローカル同梱（CDN依存なし）
- 配置先: リポジトリルート直下 `pdf-annotator/`

### やらないこと
- 既存PDF本文（元のテキスト・画像）の編集・削除
- AcroFormによるフォーム作成・入力
- 電子署名
- OCR（画像内文字の認識）
- 複数ファイルの一括処理
- Chrome以外のブラウザでの動作保証
- サーバーサイド処理・アカウント機能・クラウド保存

## 完了条件

- [ ] `pdf-annotator/` フォルダを `python -m http.server` で起動し、ブラウザでアクセスするだけで動作する（ビルドコマンド不要）
- [ ] ネットワーク（CDN）が不通の状態でも、pdf.js・pdf-lib・fontkitがすべてローカル同梱ファイルから読み込まれ正常動作する
- [ ] ファイル選択およびドラッグ&ドロップの両方でPDFを読み込める
- [ ] 複数ページPDFでページ送り・ページジャンプ・ズームが正しく動作する
- [ ] 日本語テキスト（ひらがな・カタカナ・漢字）をPDF上の任意位置に配置・編集・移動・削除でき、フォントサイズと色を変更できる
- [ ] フリーハンドペンで自由に線を描画でき、色・太さを変更でき、undoで直前の操作を取り消せる
- [ ] 蛍光ペンで半透明の帯を描画できる
- [ ] 書き込み後、保存（ダウンロード）した新規PDFを、書き込みツール以外の別のPDFビューア（例: Chrome標準ビューア、Adobe Acrobat Reader等）で開いても、日本語テキストが文字化けや欠落なく正しく表示される
- [ ] 全ページに書き込みがある状態で保存しても、全ページ分の書き込みが保存後PDFに反映されている
- [ ] 保存後PDFのファイルサイズ・ページ数が異常でない（元PDFのページ構成が保持されている）
- [ ] コンソールエラーが出ずに一連の操作（読み込み→書き込み→保存）が完了する

## 工程1: 骨格（vendor同梱＋PDF表示）

### 完了条件
- [ ] `pdf-annotator/` フォルダがリポジトリルート直下に作成されている
- [ ] `pdf-annotator/vendor/` にpdf.js（表示に必要な一式：pdf.js本体、pdf.worker、cmapsなど日本語PDF描画に必要なリソースを含む）がローカル同梱されている
- [ ] `pdf-annotator/vendor/` にpdf-lib、@pdf-lib/fontkit、NotoSansJP-Regular.ttf（またはOTF）が配置されている（工程3で使用するが、この工程でファイル配置までは完了させる）
- [ ] `index.html` 等をブラウザで開き、CDNへのリクエストが一切発生しないことをネットワークタブ等で確認できる
- [ ] `python -m http.server` で起動し、ファイル選択でPDFを開くと1ページ目が表示される
- [ ] ドラッグ&ドロップでもPDFを開ける
- [ ] ページ送り（前へ/次へ、ページ番号ジャンプ）が正しく動作する
- [ ] ズームイン/ズームアウトが正しく動作する

- [ ] npm/node_modules/ビルドコマンドが一切不要である

## 工程3: 保存（日本語フォント埋め込み）

### 完了条件
- [ ] 「保存」操作で、工程2までの書き込み内容（テキスト・ペン・蛍光ペン）がすべて反映された新規PDFがダウンロードされる
- [ ] 保存処理はpdf-lib + fontkitでNotoSansJPフォントを埋め込み、注釈ではなくページのコンテンツストリームへ直接描画する方式で行われている
- [ ] 保存後PDFを本ツール以外の別ビューア（Chrome標準PDFビューア、Adobe Acrobat Reader等、複数で確認）で開いても日本語が文字化けなく正しく表示される
- [ ] 全ページに書き込みがある状態で保存しても、全ページ分が正しく反映される（一部ページのみ反映される不具合がない）
- [ ] 書き込みのないページは元のPDFページ内容がそのまま保持される
- [ ] テキストのフォントサイズ・色、ペンの色・太さ、蛍光ペンの半透明表現が保存後PDFでも見た目として再現されている
- [ ] 保存後PDFのページ数が元PDFと一致する
- [ ] 保存処理中・完了後にコンソールエラーが出ない
- [ ] オフライン（CDN不通）環境でも保存処理が正常に完了する

## 備考

- 工程間の依存: 工程1が85点以上で合格するまで工程2に着手しない。工程2が合格するまで工程3に着手しない（CLAUDE.md品質ループ準拠）。
- 各工程は最大5回まで実行→品質チェックを繰り返す。5回を超えて合格しない場合はユーザーへ相談する。
- pdf.js組み込みのFreeText注釈エディタはCJK文字でAppearance Stream生成に既知バグ（Issue #20117）があるため、本ツールでは使用しない。pdf.jsは表示専用に限定し、書き込みはCanvas/DOMオーバーレイの自前実装、保存はpdf-lib+fontkitのコンテンツストリーム直接描画方式で行う（調査結果に基づく決定済み方針）。
- 対象ブラウザはChrome（Windows/Mac）のみとし、他ブラウザでの動作確認・対応は本v1のスコープ外とする。
- フォントライセンス: NotoSansJPはSILオープンフォントライセンスであり同梱・再配布に問題がないことを工程1のvendor配置時に確認する。
