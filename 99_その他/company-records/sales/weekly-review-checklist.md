# 週次レビュー実行チェックリスト

- **作成日**: 2026-06-09
- **対象工程**: 工程4（運用リズムの仕組み化）
- **目的**: 毎週月曜の10分で「営業が前進しているか」を必ず確認する

---

## 週次レビューの実行手順

### A. 起動（1分）

```
/weekly-sales-review
```

または sales-briefing 実行後に月曜プロンプト「Y」を選択する。

スキルが自動で以下を実行するため、オーナーは**確認・承認・入力**だけすればよい:
- DASHBOARD_SALES.md からの数値読み込み
- 警告A〜Gの自動チェック
- KGI残日数の計算・表示

---

## B. 確認項目マスターリスト

### B-1: DM送信の実績確認

- [ ] 先週のDM送信数は何通か (`DASHBOARD_SALES.md §1` で確認)
- [ ] 今週の目標値（5〜20通）に対して進捗はどうか
- [ ] DRY_RUN=false になっているか（初回起動時のみ確認。以後は毎週不要）
- [ ] 送信リストのpending件数は十分あるか（ゼロならリスト補充が必要）

### B-2: DM返信率の確認

- [ ] 先週の返信数は何件か（Gmail `info@yn-factory.com` で確認）
- [ ] 返信率 = 返信数累計 ÷ 送信数累計 × 100 を計算（スキルが自動計算）
- [ ] 返信率 < 1% の場合: スキルが提案する件名変更・文面改善アクションを確認する
- [ ] 返信率 < 1% が2週連続の場合: 業種絞り込みまたは本文冒頭3行の変更を今週中に実施

### B-3: ウェビナー申込数の確認

- [ ] 今週の新着申込数は何名か（Peatix管理画面で確認）
- [ ] 申込数累計は目標（5名）に対して何名か
- [ ] 次回開催日は確定しているか（未確定なら今週中に設定）
- [ ] 開催まで14日以内の場合: 告知・SNS投稿・DM内告知文の追加を実施

### B-4: Calendly予約・商談の確認

- [ ] 今週のCalendly新着予約は何件か（Calendly管理画面で確認）
- [ ] 今月の商談実施数は何件か（`DASHBOARD_SALES.md §1` で確認）
- [ ] 商談実施後24h以内に提案書ドラフトを生成したか
- [ ] 提案送付済み案件のフォロー状況を確認（`§6 フォロー待ち` を参照）

### B-5: 提案・成約の確認

- [ ] 先週の提案書送付数は何件か
- [ ] 提案送付後3〜7日経過した案件のフォローは完了しているか
- [ ] 成約またはお断りの連絡はあったか（ある場合は `§6 フォロー待ち` を更新）
- [ ] MRR に変動はあったか（成約があれば `§1 MRR` と `§3 MRR進捗バー` を更新）

### B-6: KGI進捗の確認

- [ ] KGI期限（2026-07-31）まで残り何日か（スキルが自動表示）
- [ ] ウェビナーKGI（2026-07-15まで1回）まで残り何日か
- [ ] 現在のペースでKGIに到達できるか（商談3件・DM100件・ウェビナー1回）
- [ ] 到達できない場合: スキルが提案する具体的アクションを確認して今週の必達に組み込む

---

## C. 今週の必達アクション確定（最重要）

**weekly-sales-review スキルが自動提案する推奨アクションを確認・修正・確定する。**

確定したアクションは以下の2箇所に登録される（スキルが自動更新）:

1. `DASHBOARD_SALES.md §6（アクション待ち一覧）`
2. `.company/reviews/YYYY-WXX-sales.md` のレビュー記録

**ルール:**
- 必達アクションは最低1個、最大3個
- 前回未完了のアクションは自動で引き継がれる（消えない）
- アクションは精神論ではなく「何を・いつまでに・どのファイルを見て・どう実行するか」まで記載

---

## D. 停滞リカバリ手順

**「先週アクションがゼロだった」「2週間送信が止まっていた」場合はこの手順で再起動する:**

### D-1: ブロッカーの特定（5分）

1. `LAUNCH_CHECKLIST.md` を開いて未完了の工程（4b/5b/8b）を確認する
2. DRY_RUN=false 切替が完了しているか確認する:
   ```bash
   ssh yn-vps "grep DRY_RUN /opt/sales-ops/.env"
   ```
3. VPSパイプラインが正常動作しているか確認する（sales-briefingのステップ1コマンド実行）

### D-2: ブロッカーに応じた対処

| ブロッカー | 即時対処 |
|---|---|
| DRY_RUN=true のまま | `LAUNCH_CHECKLIST.md §工程8b` を実行（所要20分） |
| pending DMがゼロ | VPSでlist_builderを実行してリストを補充する |
| Calendly未設定 | `LAUNCH_CHECKLIST.md §工程5b` を実行（所要15分） |
| Peatix未公開 | `LAUNCH_CHECKLIST.md §工程4b` を実行（所要30分） |
| SSH接続エラー | `~/.ssh/config` の設定を確認（Host: yn-vps / 163.44.101.31） |

### D-3: 再起動宣言（気持ちの問題ではなく記録の問題として扱う）

1. `.company/reviews/YYYY-WXX-sales.md` に「停滞リカバリ」として理由・対処・再開日を記録する
2. `DASHBOARD_SALES.md §6` の「その他」欄に「再開アクション確定」として1件追加する
3. 今週の必達アクションを「最低1通送信する」の1個だけに絞る（欲張らない）
