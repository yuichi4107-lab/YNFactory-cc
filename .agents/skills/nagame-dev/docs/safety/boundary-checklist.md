# 境界ケース8カテゴリチェックリスト

## 概要

AI生成コードの約45%にセキュリティ脆弱性が含まれるという調査結果がある。
本文書は、実装・テスト時に見落としやすい境界ケースを8カテゴリに分類し、
各カテゴリで確認すべき具体的な項目を定義する。

例え話：自動車の出荷前検査と同じ。エンジンが動くだけでは不十分で、
ブレーキ・ライト・排気ガス・衝突安全性など、あらゆる角度から検査する。

---

## 1. 8カテゴリ一覧

| # | カテゴリ | 概要 | 主な被害 |
|---|---|---|---|
| BC-1 | 永続性・再起動 | プロセス再起動後にデータが消える | データ消失 |
| BC-2 | 認証・トークン | トークン期限切れ・リフレッシュ失敗 | 機能停止 |
| BC-3 | 文字コード | マルチバイト・絵文字・特殊文字 | 文字化け・クラッシュ |
| BC-4 | タイムゾーン | JST/UTC 混在、夏時間 | スケジュール誤動作 |
| BC-5 | 冪等性 | 同じ処理を2回実行した場合の安全性 | 二重投稿・二重課金 |
| BC-6 | エラー通知 | 異常時にユーザーへ通知が届くか | 障害の見逃し |
| BC-7 | データ量制限 | 大量データ・空データ・上限超過 | メモリ枯渇・タイムアウト |
| BC-8 | 外部障害 | 外部API・ネットワーク障害 | 連鎖障害 |

---

## 2. カテゴリ別チェック項目

### BC-1: 永続性・再起動

プロセスが再起動しても、データと状態が保持されるか。

- [ ] **メモリ上のデータ永続化**: インメモリのキャッシュやキューが再起動で消えないか
- [ ] **中断再開**: 処理の途中で再起動した場合、途中から再開できるか
- [ ] **ファイルロック**: 再起動時にロックファイルが残って起動できなくならないか
- [ ] **設定ファイル再読込**: 設定変更後に再起動で反映されるか
- [ ] **PID ファイル管理**: 古い PID ファイルが残ってデーモン起動を阻害しないか

### BC-2: 認証・トークン

外部サービスとの認証が長期間安定するか。

- [ ] **トークン期限切れ**: アクセストークンの有効期限が切れた場合の自動更新
- [ ] **リフレッシュトークン失敗**: リフレッシュトークン自体が無効になった場合の通知
- [ ] **認証情報のローテーション**: APIキーの定期変更に対応できるか
- [ ] **並行リクエスト時の認証**: 複数スレッドから同時にトークン更新した場合の競合
- [ ] **認証エラーのリトライ上限**: 認証失敗時に無限リトライしないか

### BC-3: 文字コード

日本語を含む多言語テキストが正しく処理されるか。

- [ ] **マルチバイト文字**: 日本語・中国語・韓国語が文字化けしないか
- [ ] **絵文字**: 4バイト UTF-8 絵文字がクラッシュや切り詰めを起こさないか
- [ ] **特殊文字**: `<>&"'\` 等がエスケープされているか（XSS/インジェクション対策）
- [ ] **NULL文字**: 入力に NULL バイトが含まれた場合の挙動
- [ ] **BOM**: UTF-8 BOM 付きファイルが正しく読めるか

### BC-4: タイムゾーン

時刻の取り扱いが一貫しているか。

- [ ] **JST/UTC 明示**: 全ての日時データにタイムゾーン情報が付与されているか
- [ ] **内部処理の統一**: 内部は UTC で統一し、表示時のみ JST に変換しているか
- [ ] **日付境界**: 日本時間 0:00 前後の処理が正しいか（UTC では前日）
- [ ] **スケジュール実行**: cron 等のスケジュールがどのタイムゾーンで設定されているか

### BC-5: 冪等性

同じ操作を2回実行しても安全か。

- [ ] **API リトライ安全性**: タイムアウト後のリトライで二重実行されないか
- [ ] **投稿の重複防止**: 同じ内容が2回投稿されないか（冪等キーの使用）
- [ ] **課金の二重発生**: 決済処理が2回走らないか
- [ ] **データベース操作**: INSERT が2回走っても重複レコードが作られないか（UPSERT等）
- [ ] **ファイル操作**: 同じファイルを2回処理しても内容が壊れないか

### BC-6: エラー通知

異常発生時に適切な通知が届くか。

- [ ] **通知先の設定**: エラー通知の送信先（メール・Slack等）が設定されているか
- [ ] **通知の抑制**: 同じエラーが大量発生した場合のアラート疲れ対策
- [ ] **通知内容の十分性**: エラーメッセージに原因特定に必要な情報が含まれているか
- [ ] **通知経路の冗長性**: 通知サービス自体が障害の場合の代替手段

### BC-7: データ量制限

想定外のデータ量に対する耐性。

- [ ] **空データ**: 入力が空の場合にクラッシュしないか
- [ ] **大量データ**: 想定最大量の10倍でもメモリ枯渇しないか（ページネーション等）
- [ ] **ファイルサイズ上限**: アップロードファイルのサイズ制限が設定されているか
- [ ] **レスポンスサイズ**: APIレスポンスが巨大な場合のストリーミング処理

### BC-8: 外部障害

外部サービスが停止した場合の耐性。

- [ ] **タイムアウト設定**: 全ての外部API呼び出しにタイムアウトが設定されているか
- [ ] **フォールバック**: 外部サービス停止時の代替動作が定義されているか
- [ ] **サーキットブレーカー**: 障害が連鎖しないよう遮断する仕組みがあるか
- [ ] **リトライ戦略**: 指数バックオフ等の適切なリトライが実装されているか
- [ ] **部分障害**: 複数の外部サービスのうち1つだけ障害の場合、他は正常に動くか

## 3. セキュリティチェックリスト

境界ケースとは別に、セキュリティ観点で必須の確認項目。

### 3-1: 秘密情報管理

- [ ] APIキー・パスワードは環境変数ファイルで管理されている（コードにハードコードされていない）
- [ ] 環境変数ファイルが `.gitignore` に含まれている
- [ ] ログ出力に秘密情報が含まれていない
- [ ] エラーメッセージに秘密情報が含まれていない
- [ ] ATM方式（use_apikeys.md）に準拠している

### 3-2: 入力バリデーション

- [ ] 全てのユーザー入力がサニタイズされている
- [ ] SQL インジェクション対策（パラメータ化クエリ）が実装されている
- [ ] XSS 対策（HTML エスケープ）が実装されている
- [ ] コマンドインジェクション対策が実装されている
- [ ] パストラバーサル対策が実装されている

### 3-3: エラーメッセージ

- [ ] エラーメッセージにスタックトレースが含まれていない（本番環境）
- [ ] エラーメッセージにファイルパスが含まれていない（本番環境）
- [ ] エラーメッセージに内部IPアドレスが含まれていない
- [ ] ユーザー向けエラーメッセージと開発者向けログが分離されている

### 3-4: 依存関係監査

- [ ] 依存パッケージに既知の脆弱性がないか確認済み（`npm audit` / `pip audit` 等）
- [ ] 依存パッケージのバージョンが固定されている（lock ファイル）
- [ ] 不要な依存パッケージが含まれていないか確認済み
- [ ] ライセンスの互換性が確認されている

## 4. AI生成コードの脆弱性統計

### 注意すべき事実

AI が生成したコードの約 **45%** にセキュリティ脆弱性が含まれるという調査結果がある。
特に以下のカテゴリが多い。

| 脆弱性タイプ | 発生頻度 | 対策 |
|---|---|---|
| 入力バリデーション不足 | 高 | §3-2 チェック必須 |
| 秘密情報のハードコード | 高 | §3-1 チェック必須 |
| エラーハンドリング不足 | 中 | BC-6, BC-8 チェック必須 |
| 認証・認可の不備 | 中 | BC-2 チェック必須 |
| 暗号化の不適切な使用 | 低 | 暗号化処理は人間レビュー必須 |

### AI生成コードレビュー時の追加チェック

- [ ] AI が「この程度なら大丈夫」と判断した箇所を重点的にレビュー
- [ ] AI が生成したセキュリティ対策コード自体が正しいか検証
- [ ] AI が省略した例外処理がないか確認
- [ ] AI が使用したライブラリのバージョンが最新の安全なバージョンか確認

## 5. チェックリスト運用ルール

### いつ使うか

| タイミング | 必須カテゴリ | 推奨カテゴリ |
|---|---|---|
| 実装完了時 | 全8カテゴリ + セキュリティ全項目 | - |
| バグ修正後 | 修正箇所に関連するカテゴリ | 回帰確認として全カテゴリ |
| 外部API追加時 | BC-2, BC-8 + セキュリティ §3-1 | BC-4, BC-7 |
| リリース前 | 全8カテゴリ + セキュリティ全項目 | - |

### 記録方法

チェック結果は以下の形式で記録する。

```
[BC-1] 永続性・再起動: 5/5 PASS
[BC-2] 認証・トークン: 4/5 PASS, 1 HOLD（リフレッシュトークン→次フェーズ）
[SEC-1] 秘密情報管理: 5/5 PASS
...
```

HOLD 項目は Finding Ledger に転記し、対応期限を設定する。
