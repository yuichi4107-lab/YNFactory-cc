# GenSpark Claw連携

## 役割
GenSpark Claw（AIブラウザエージェント）へのタスク受け渡しを管理する。
Claude Codeでは対応できないブラウザ操作・外部サービス操作をGenSpark Clawに委託する。

## 現在の委託対象タスク
- note記事の公開

※ タスクの種類は都度追加していく。

## 指示書の共通ルール
- **`publish_at` フィールド**: 公開日時を指定する。GenSpark Clawはこの日時で予約投稿を行う
  - 形式: `"YYYY-MM-DD HH:MM"`（JST）
  - **30分単位で指定**（10:00, 10:30, 11:00...）— noteの予約投稿UIが30分刻みのため
  - `publish_at` あり → 指定日時に予約投稿（**即時公開は厳禁**）
  - `publish_at` なし → 即時公開
- Claude Codeが指示書を作成する際は、オーナーに公開日時を確認してから `publish_at` を設定する

## 【重要】予約投稿の失敗防止（2026-04-12追加）

**背景**: 2026-04-11に7件のnote記事を予約投稿指示したが、すべて即時公開になった。
GenSpark Clawが「公開」ボタンと「予約投稿」ボタンを取り違えた疑い。かつ報告は「予約投稿完了」と虚偽の内容だった。

**再発防止ルール**:
1. **指示書には具体的UI手順を必ず記載**（`_template.md` の「note予約投稿の正しい手順」セクション参照）
2. **検証ステップを必須化**: 予約投稿後にトップページで非表示であること・予約タブに表示されていることを確認
3. **虚偽報告厳禁**: 即時公開になってしまった場合は「エラーあり」として正直に報告させる
4. **Claude Code側の巡回チェック**: `done/` 巡回時、`公開方法: 予約投稿` と記載されていても念のためオーナーに最終確認を促す（特に初回/新タスクタイプ）

## 【重要】ローカルファイル参照禁止（2026-04-28追加）

**背景**: 2026-04-26にAIリテラシー記事5本を委託したが、すべて「原稿コンテンツが見つかりませんでした」でエラー終了。原因は指示書が `docs/note/...md` などローカルパスを参照していたため、ブラウザベースのGenSpark Clawが読み取れなかったこと。

**禁止ルール**（指示書作成者=Claude Code向け）:
1. **原稿本文・テキストコンテンツは、指示書内に直接埋め込む** — `docs/`、`outputs/`、相対パス等のローカルファイル参照は絶対NG
2. **画像はGoogle Drive 公開URL（または同アカウントのプライベートマイドライブURL）で指定** — `03_成果物/outputs/...` のローカルパスは NG
3. **画像位置は本文中にマーカー行（例: `【画像位置N: filename.png】`）で示す** — markdownの `![alt](path)` 記法は使わない（GenSpark Clawがファイル取得に行って失敗する）
4. **ダウンロード手順を明記**: Drive URL → 右クリックでダウンロード → noteへアップロード、までを指示書に書く

**指示書のセルフチェックリスト**（投入前に確認）:
- [ ] `docs/`、`03_成果物/outputs/` などローカルパスがどこにも残っていないか
- [ ] 原稿本文が指示書内に丸ごと含まれているか
- [ ] 画像は Drive URL + ファイル名で指定されているか
- [ ] markdown `![](path)` 記法が残っていないか

## フォルダ構成

```
genspark/
├── CLAUDE.md
├── _template.md
├── queue/          # 未着手タスク（Claude Codeがここに配置）
├── in-progress/    # GenSpark Claw作業中
├── done/           # GenSpark Claw完了報告（Claude Codeが巡回して処理する）
└── archive/        # 処理済み（進捗反映後に移動）
```

## 運用ルール

### タスクの流れ
1. **Claude Code** が `queue/` に指示書を作成
2. **GenSpark Claw** が `queue/` の指示書を読み取り、作業を開始
3. 作業開始時にファイルを `in-progress/` に移動
4. **GenSpark Claw** が完了後、結果報告を `done/` に保存
5. **Claude Code** が `done/` を巡回 → プロジェクト進捗に反映 → `archive/` に移動

### done/ 巡回ルール（Claude Code向け）
- **巡回タイミング**: `/company` 起動時
- **巡回時にやること**:
  1. `done/` 内のファイルをすべて読む
  2. 各タスクの結果を確認し、関連プロジェクトの進捗を更新
  3. 処理済みファイルを `done/` → `archive/` に移動
  4. オーナーに結果サマリーを報告

### ファイル命名規則
`YYYY-MM-DD-task-name.md`

### ステータス管理
- `queue/` にある = 未着手
- `in-progress/` にある = GenSpark Claw作業中
- `done/` にある = GenSpark Claw完了・Claude Code未処理
- `archive/` にある = 処理済み（進捗反映完了）
