# 要件定義書：GEO監査「無料ミニ診断」実施パイプライン

作成日: 2026-07-12
対象事業: GEO監査（整体院・接骨院向けAI検索露出診断）
背景: 営業文面を30社へ順次送信中（1社送信済み）。返信が来た時点で「無料ミニ診断」を即座に実施できる状態にするため、実務パイプラインを事前整備する。

---

## ゴール

返信が来たその日に、営業文面で約束した内容（10分ヒアリングのみ・AI検索での言及有無・競合2〜3院との簡易比較・改善ポイント3つ・費用ゼロ）を過不足なく満たす「無料ミニ診断」を、担当者（Claude Code含む）が手順書どおりに動くだけで実施し、顧客名入りHTMLレポートとして送付できる状態にする。

## スコープ

### 無料ミニ診断のスコープ定義（最重要・全工程の前提）

営業文面（`GEO監査\営業\個別化文面_30社.md`）が明示的に約束している内容は以下の4点のみ:
1. 10分程度のヒアリングのみ（顧客側の負担）
2. AI検索での言及有無
3. 競合2〜3院との簡易比較
4. 改善ポイント3つ
5. 費用は一切かからない

一方、既存資料には以下の別スコープの成果物が存在し、無料版と混同してはならない:
- `質問テンプレート30問.md`（6カテゴリ・30問）＝ AI検索質問の**マスターセット**。無料・有料共通の出題プールであり、無料版はここから**10問相当を抽出したサブセット**を使う。30問フルセットをそのまま無料版に使うと、有料「標準改善15万円」パッケージ（30質問・競合5社）と区別がつかなくなり、無料オファーの過大化＝有料商品の価値毀損になるため禁止する。
- `サンプル診断レポート.html`（30問・4AI・競合4社・改善7項目・30日ロードマップ）＝ **営業デモ用サンプル**であり、フォーマット（スコア表・競合比較表・改善チェックリスト・免責事項の構成）は流用するが、掲載する情報量（質問数・競合数・改善項目数）はそのまま無料版の分量にしてはならない。
- `実装計画_2026-07-05.html`の料金表「ライト診断3万円＝10質問・競合3社・改善10項目」＝ **有料**パッケージの定義。無料ミニ診断とは別物であり、無料版の改善項目数は3つ（有料ライト診断の10項目ではない）。

これらを踏まえ、本工程で確定する無料ミニ診断のスコープは以下のとおりとする:

| 項目 | 無料ミニ診断 | 参考: 有料ライト診断（3万円・別スコープ） |
|---|---|---|
| 質問数 | 10問（30問マスターから抽出、カテゴリ配分を手順書で規定） | 10質問 |
| 対象AI | ChatGPT・Gemini・Perplexity・Google AI Overviews（実測は担当者が全4AIで実施。顧客側の負担時間には影響しない） | 同上想定 |
| 競合比較 | 2〜3院 | 3社 |
| 改善提案 | 3項目 | 10項目 |
| 顧客側の時間負担 | ヒアリング10分のみ | （別途要件） |
| 費用 | 0円 | 30,000円 |

※質問数が同じ「10」でも無料版と有料版は競合数・改善項目数で明確に差がある点を手順書・レポート生成ツールの両方で維持すること。

### やること
1. 実施手順書（申込受領〜フォローの一連フロー、AI別実測方法・注意点を含む）の作成
2. スコア算定基準（記録項目→点数化ルール、サンプルレポートのスコア体系と互換）の明文化
3. スコアシートテンプレート（CSV、機械可読）の作成
4. ヒアリングシート（10分想定の質問項目＋記入欄）の作成
5. レポート生成ツール（Python標準ライブラリ、CSV/JSON＋院情報→顧客名入りHTML）の実装と、架空データによる動作確認

### やらないこと
- 実在顧客のデータを用いた実診断の実施（本工程は架空データでのテストまで）
- 有料版（ライト診断3万円・標準改善15万円・月額運用8万円）の実施手順・スコア基準の設計（別途必要になった時点で着手）
- 営業文面・送信管理・LINE/フォーム等の送信オペレーション自体の変更（既存の送信手順書のスコープ）
- Webスクレイピングの自動化・API連携（実測はClaude Codeによる手動ブラウザ操作／Web検索を前提とし、自動化ツールの開発は行わない）
- レポートのデザイン刷新（サンプルHTMLのCSS・構成を踏襲し、大幅なデザイン変更はしない）

## 工程1: 実施手順・基準・シート整備

### 完了条件
- [ ] 実施手順書に「申込受領→ヒアリング(10分)→実測→採点→レポート生成→送付→フォロー」の全ステップが、担当者が迷わず着手できる粒度（各ステップの担当・所要時間・使用ツール・入力/出力）で記載されている
- [ ] ヒアリング項目に、院名・地域・強み症状（得意な施術・悩み）・競合として認識している院（2〜3院）・公式サイト有無・Googleビジネスプロフィール(GBP)有無等、実測とレポート生成に必要な項目が過不足なく含まれている
- [ ] 実測方法が対象AI（ChatGPT・Gemini・Perplexity・Google AI Overviews）ごとに個別定義されており、ログイン要否、無料/有料プランでの回答差、レート制限・連投時の注意、実施日時の記録方法が明記されている
- [ ] 同一質問でも表現ゆれ（言い回しの違い）や複数回実施で回答が変動する点への対処方針（例: 1問につき原則1回実施し、原文どおりの質問文を固定して使う。明らかな異常回答時のみ再実施し、再実施した旨を記録する等）が明文化されている
- [ ] 10問の抽出方法（30問マスターのどのカテゴリから何問ずつ選ぶか、地域名・症状の差し込みルール）が手順書に明記されている
- [ ] スコア算定基準に、質問ごとの記録項目（言及有無／推薦順位／引用元の有無／誤情報の有無）と、それぞれの点数への変換ルール（配点・加減点条件）が明文化されている
- [ ] スコア算定基準が、サンプル診断レポートのスコア体系（4AI別スコア＋総合スコア、NN/100形式）と構造的に互換である（同じ計算式の入力次元が10問でも30問でも成立する設計）
- [ ] スコアシートテンプレート(CSV)に、院名・AI種別・質問No・質問文・言及有無・推薦順位・引用元・誤情報有無等、スコア算定とレポート生成に必要な列が過不足なく定義されている
- [ ] ヒアリングシートが10分間で完結する分量・質問数になっている
- [ ] 無料ミニ診断のスコープ（10問相当・競合2〜3院・改善ポイント3つ・費用ゼロ）が、実施手順書・スコア算定基準・ヒアリングシートの記載内容と完全に一致している（過大でも過小でもない）
- [ ] 全ドキュメントが日本語で作成されている

## 工程2: レポート生成ツール実装

### 完了条件
- [ ] `report_generator.py` がPython標準ライブラリのみ（またはこのPCに既にインストール済みのライブラリのみ）で動作する
- [ ] スコアシート（CSV/JSON）と院情報（院名・地域・強み症状等）を入力とし、`サンプル診断レポート.html`と同型の構成（診断サマリー／AI別スコア表／競合比較表／改善チェックリスト／免責事項）を持つ、顧客名入りのHTMLを生成する
- [ ] 出力HTMLの構成・分量が無料ミニ診断のスコープ（10問ベースのスコア表、競合2〜3院の比較表、改善ポイント3項目）に正しく縮小されており、サンプルの30問／競合4社／改善7項目／30日ロードマップをそのまま複製していない
- [ ] 免責事項（AI検索での表示・掲載順位を保証しない旨、効果効能の断定表現をしない旨、偽口コミ等を作成しない旨）がテンプレートに維持されている
- [ ] サンプル固有の表記（「SAMPLE REPORT」バッジ、「架空データ」注記等）が実運用時には出ない、または架空データテスト時にのみ明示される形になっている
- [ ] 動作確認用の架空データ（架空院名・架空競合2〜3院・架空スコア）でスクリプトを実行し、エラーなくHTMLファイルが生成されることを確認している
- [ ] 生成されたHTMLをブラウザ等で開いて崩れ（タグ閉じ忘れ・文字化け・レイアウト破綻）がないことを確認している
- [ ] スクリプトが院名・地域・スコア等の入力データを変えれば別の院にも再利用できる構造になっている（ハードコードされた固有名詞が残っていない）

## 備考

- 工程1のスコア算定基準は「10問版（無料）」を基準に設計するが、将来有料版（30問・競合3〜5社）にも同じ計算式の考え方を拡張できるよう、質問数・競合数に依存しすぎない点数化ロジック（例: 平均化・正規化した上で100点満点に変換する等）にしておくことが望ましい。ただし本工程の完了条件・品質基準はあくまで無料ミニ診断（10問相当）の範囲で判定する。
- 実測（AI検索への質問投入）はClaude Codeがブラウザ操作またはWeb検索機能を用いて手動実施する前提であり、API連携や自動スクレイピングの実装はスコープ外。
- 「17(いちなな)整骨院」等、送信文面側で確認済みの個別事情（チェーン該当性・LINE導線等）は本パイプラインの設計に影響しないため参照不要。
- 各工程は最大5回の実行→品質チェックのループを上限とし、超過時はオーナーへ相談する（プロジェクト共通ルール）。
- 工程1が85点以上で合格するまで、工程2（レポート生成ツール）には着手しない。
