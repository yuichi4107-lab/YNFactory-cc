# report_generator.py 使い方

作成日: 2026-07-12
対象: 無料ミニ診断レポート生成ツール（`実施手順書.md` ステップ⑤で使用）

---

## 1. 概要

`report_generator.py` は、記入済みスコアシート（CSV）と院情報（JSON）を入力として、
顧客名入りの「AI検索露出 無料ミニ診断レポート」HTMLを自動生成するツールです。

- Python標準ライブラリのみで動作（`pip install` 不要）
- スコア計算は `スコア算定基準.md`（2026-07-12版・基礎点8/5/3・満点10点）のロジックをそのまま実装しています
- 出力は無料ミニ診断のスコープ（10問・4AI・競合2〜3院・改善ポイント3項目）に固定されています

## 2. 実行コマンド

```
python report_generator.py --scoresheet <スコアシートCSV> --client <院情報JSON> --out <出力HTMLパス> [--test]
```

| 引数 | 必須 | 内容 |
|---|---|---|
| `--scoresheet` | ○ | `実施手順書.md` 4章の実測後に記入済みの案件用CSV（`スコアシートテンプレート.csv` をコピーして作成したもの） |
| `--client` | ○ | 院情報JSON（3章参照）。ヒアリングシートの内容から作成する |
| `--out` | ○ | 出力するHTMLファイルのパス |
| `--test` | 任意 | 架空データによる動作確認であることを示すバナーを表示する。**実顧客向けレポートでは付けない** |

### 実行例（架空データでのテスト生成）

```
python report_generator.py --scoresheet テスト用スコアシート.csv --client テスト用院情報.json --out テスト出力レポート.html --test
```

### 実行例（実案件でのレポート生成）

```
python report_generator.py --scoresheet 実施記録/はるか整体院_スコアシート.csv --client 実施記録/はるか整体院_院情報.json --out 実施記録/はるか整体院_診断レポート.html
```

`--test` を付けなければ、出力HTMLに「テストデータ」バナーは出ません。

## 3. 院情報JSON（`--client`）の書き方

`テスト用院情報.json` を雛形としてコピーし、案件ごとに値を書き換えてください。

```json
{
  "院名": "（院の正式名称）",
  "地域": "（ヒアリングで確認した市区町村名。実測時の{地域名}と一致させる）",
  "強み症状": "（ヒアリングで確認した強み症状・実測時の{症状・悩み}と一致させる）",
  "実施日": "（診断実施日。表示用の文字列でよい。例: 2026年7月12日）",
  "競合": [
    { "院名": "（競合1の院名）", "所在地": "（競合1の所在地）", "AIでの言及状況": "（比較・口コミ系の質問への回答内容から、担当者が確認した紹介のされ方を簡潔に記述。任意項目）" },
    { "院名": "（競合2の院名）", "所在地": "（競合2の所在地）" }
  ],
  "改善ポイント": [
    "（改善ポイント1）",
    "（改善ポイント2）",
    "（改善ポイント3）"
  ],
  "実測不可AI理由": {
    "Gemini": "（実測不可があった場合のみ記載。例: サービス障害のため実測不可）"
  },
  "送付先": "（レポート送付先。ツールの出力には使わないが記録用に保持）"
}
```

### 必須・制約

- `院名` `地域` `強み症状` `実施日` `競合` `改善ポイント` は必須。
- `競合` は**必ず2〜3件**。1件や4件以上だとエラーになり生成できません（無料ミニ診断のスコープ厳守のための安全装置）。
- `改善ポイント` は**必ず3件ちょうど**。2件や4件だとエラーになります。
- `実測不可AI理由` は、実測不可のAIがあった場合のみ記載する任意項目（`実施手順書.md` 4-7章参照）。
- `AIでの言及状況` は競合ごとの任意項目。省略した場合は「今回の比較質問の回答からは特筆すべき言及は確認されませんでした」という既定文が入ります。

## 4. スコアシートCSV（`--scoresheet`）の書き方

`スコアシートテンプレート.csv` をコピーし、`実施手順書.md` 4章の実測結果を記入したものをそのまま使います。
ツールが直接読み取るのは以下の列です。

| 列名 | 用途 |
|---|---|
| `AI種別` | `ChatGPT` / `Gemini` / `Perplexity` / `Google AI Overviews` のいずれか（この4種以外はエラーになります） |
| `言及有無` | `あり` / `なし` / `AI Overview非表示`（Google AI Overviews専用） / `実測不可`（そのAIで実測ができなかった場合） |
| `推薦順位` | `1位相当` / `2〜3位相当` / `言及のみ`（`言及有無`が`あり`の場合のみ必須） |
| `引用元種別` | `一次情報（公式サイト／GBP）` / `二次情報（口コミ・まとめサイト等）` / `引用なし`（`言及有無`が`あり`の場合のみ必須。文字列に「一次」「二次」を含んでいれば判定できます） |
| `誤情報有無` | `あり` / `なし` |
| `誤情報内容` | 誤情報がある場合の内容。レポート「4. 誤情報の確認結果」に反映されます |

**質問別素点はツール側で `スコア算定基準.md` の計算式に従って自動計算します**（CSVに手動で入れた値は使いません）。手計算の値と食い違う場合は、CSVの入力ミスの可能性が高いので見直してください。

### 実測不可（AI全体）の記入方法

あるAIが当日中に実測できなかった場合、そのAIの10行すべての `言及有無` に `実測不可` と記入してください。
ツールは、あるAIの全行が `実測不可` の場合に限り、そのAIをレポートの集計対象から自動的に除外し、
残りのAIのみで総合スコアを算出します（`スコア算定基準.md` 4章・`実施手順書.md` 4-7章の按分ルールと一致）。

## 5. 実行結果の確認方法

1. コマンド実行後、ターミナルに院名・総合スコア・AI別スコア・実測不可AI・誤情報検出件数が表示されます。エラーがあれば `[エラー]` から始まるメッセージが出て終了コード1で終わります。
2. 出力されたHTMLファイルをブラウザで開き、以下を目視確認してください。
   - 質問数表記が「10問」になっているか
   - 競合比較が2〜3院になっているか
   - 改善ポイントが3項目になっているか
   - 文字化け・レイアウト崩れがないか
   - 実顧客向けレポートの場合、「テストデータ」バナーが出ていないか（`--test` を付けていないか再確認）

## 6. よくあるエラー

| エラーメッセージ（一部） | 原因 | 対処 |
|---|---|---|
| `スコアシートCSVに必須列が不足しています` | CSVの列名が `スコアシートテンプレート.csv` と異なる | テンプレートをコピーして使う（列名を変更しない） |
| `未知のAI種別があります` | `AI種別` 列が4種以外の表記になっている | `ChatGPT` `Gemini` `Perplexity` `Google AI Overviews` のいずれかに修正する |
| `未知の「言及有無」表記です` 等 | `言及有無` `推薦順位` `引用元種別` `誤情報有無` の表記が想定外 | `スコア算定基準.md` 1章の選択肢どおりに記入する |
| `「競合」は2〜3院で指定してください` | 院情報JSONの `競合` が1件または4件以上 | 2〜3件に修正する |
| `「改善ポイント」は…必ず3項目にしてください` | `改善ポイント` が3件ちょうどでない | 3件に修正する |

## 7. 関連ファイル

- `スコア算定基準.md` — 点数化ルールの正本
- `スコアシートテンプレート.csv` — CSV入力の雛形
- `実施手順書.md` — 本ツールを使うステップ⑤の位置づけ
- `テスト用スコアシート.csv` / `テスト用院情報.json` — 架空データによる動作確認用サンプル（本ツールの入力例としてそのまま参照可）
- `テスト出力レポート.html` — 上記サンプルを `--test` 付きで生成した出力例
