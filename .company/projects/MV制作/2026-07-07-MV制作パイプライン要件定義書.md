# 要件定義書：MV（ミュージックビデオ）制作パイプライン仕組み化

作成日: 2026-07-07（更新: 2026-07-07 オーナー確定事項反映／オーナー視聴フィードバック反映）
作成者: requirements-definer

## オーナー指定品質基準（2026-07-07視聴フィードバック）

オーナーがパイロットMVを視聴し、以下3点を**恒久的な品質基準**として指定した。以降のMV制作すべてに適用する。工程3・工程5-6間・完了条件へ反映済み（詳細は各該当セクションを参照）。

1. **画風の統一（必須）**: アニメ調と実写風の混在は不可。1本のMV内でスタイルを必ず統一する。
2. **登場人物の統一性**: シーン間で人物が別人に見えるのは不可。特に**服装の統一を最優先**、髪型も統一感を持たせる。
3. **物理的に不自然な描写の検査と作り直し**: 例）靴の破綻（片方の靴に両足）、乗り物の進行方向矛盾（自転車を漕いでいるのに前進しない/後退する）、エスカレーター/エレベーターの方向と人物の向きの矛盾。生成後に**全クリップを検査**し、検出したら**再生成してから合成**する。承認ステップなしの全自動パイプラインであっても、この検査工程（品質ゲート）は省略しない。

## 0. 調査結果サマリ・確定事項（この要件定義の前提）

### 0-0. オーナー確定事項（2026-07-07）

以下はオーナー承認により確定。本書はこの前提で全面更新している。

1. **動画生成: Atlas Cloud を採用**（EvoLinkは動画では不採用）
2. **曲生成: Suno公式API を採用**（オーナーがAPI利用準備中）。EvoLink経由のSunoリセールは不採用
   - Suno APIキーが未着でもパイプラインが動くよう、工程1は **(a) Suno API呼び出しモード / (b) 手持ち音源ファイル(mp3/wav)＋歌詞テキスト投入モード** の2モード設計とする
3. **パイロット: 両方作る** — まず **60秒・9:16版** → 同じ曲で **3分フル・16:9版**。工程分割・完了条件をこの2段構えで定義する
4. **承認フロー: 全自動** — Telegram承認や節目確認は入れない。ワンコマンドで最後まで生成する設計とする（将来オプションとして触れる程度に留める）
5. **実装承認済み** — 本要件定義書の確定を受け、executorが `tools/mv-factory/` を実装するフェーズに進む

### 0-1. Suno公式APIの現状（→ 曲生成の方式に反映）

- 2026年7月時点、Suno Inc.は一般公開の開発者コンソール・セルフサービスAPIキー発行・公式SDKを提供していない。限定パートナー向けのベータアクセスのみが存在する状態。オーナーは現在このAPI利用を準備中とのことだが、**公式APIのエンドポイント・パラメータ・料金は現時点で一般公開情報が存在しない**。
- → 本書では Suno公式APIの呼び出し仕様・料金を「オーナー確認待ち（未確定）」として扱い、パイプライン設計はSuno APIの詳細に依存しない抽象化されたインターフェース（曲生成プロバイダーを差し替え可能な設計）とする。
- **EvoLink経由のSunoリセール（非公式サードパーティ）は不採用となったため、「非公式リセールに起因する商用利用の権利保証リスク」は回避済みとして整理する。** ただし以下は残論点として維持:
  - Suno生成楽曲そのものの著作権・商用利用条件（Suno公式サブスクプラン・EULAに依存）
  - AI音楽学習データを巡る業界全体の訴訟リスク（UMG/Sony係争継続、Warner Musicは2025年11月に和解済み）は、Suno公式APIを使っても解消されるわけではなく、Suno社のサービス利用規約・ライセンス条件に従う形で残る
- 出典: https://terms.law/ai-output-rights/suno/ , https://evolink.ai/blog/suno-api-pricing（他社比較の参考情報として）

### 0-2. 動画生成: Atlas Cloud採用の詳細

- **Atlas Cloud Seedance 2.0 API料金**: 情報源により表記に幅がある。
  - Atlas Cloud公式ブログでは Fast $0.081/秒、Standard $0.10/秒 という記載
  - 別ページでは「$0.09/秒 flat」「Fast $0.022/秒（Proティア比91%割安）」という記載も見られ、キャンペーン価格・ティア・モデルバリアント（mini/fast/standard等）で変動している可能性が高い
  - 本プロジェクトの実測値（`tools/seedance-api-compare/compare_seedance.py` での2026-07-07検証、720p 9:16・5秒生成成功）に基づく実務上の目安は **standard $0.112/秒**（メモリ記載の実測ベース）とし、コスト試算はこれを基準線とする。ただし**実際の請求額は都度Atlas Cloudの管理画面・請求書で確認し、本書の数値は目安として扱うこと**。
  - 出典: https://www.atlascloud.ai/blog/case-studies/seedance-2.0-pricing-full-cost-breakdown-2026 , https://www.atlascloud.ai/seedance-2 , `tools/seedance-api-compare/`
- **User-Agentヘッダー必須**: Atlas Cloud APIはリクエストに `User-Agent` ヘッダーを付与しないと拒否される仕様が確認済み（`compare_seedance.py`で対応済み）。実装時は必ずこのヘッダーを付与すること。
- **要チャージ**: Atlas Cloudには無料クレジットがなく、事前のカード登録・チャージが必要。EvoLinkと異なり残高切れで即停止するため、残高監視・アラートの仕組みを検討する（工程5の完了条件に含める）。
- **image-to-video対応**（Seedance 2.0共通仕様、Atlas Cloud経由でも同様と想定）:
  - 1〜2枚の参照画像を最初/最後フレームとして指定可能。1枚なら最初フレーム自動設定、2枚なら1枚目=最初フレーム・2枚目=最後フレーム
  - アスペクト比が画像と異なる場合は最初フレーム優先、最後フレームは自動クロップ
  - 対応アスペクト比: 16:9, 9:16, 1:1, 4:3, 3:4, 21:9, adaptive
  - 動画長: 4〜15秒の任意整数（デフォルト5秒）
  - 解像度: 480p/720pは全モデル対応、1080pはStandard版のみ
- → **参照画像によるキャラクター一貫性の担保は可能**（first-frame指定でキャラ・世界観画像を渡せる）。ただしクリップ間（シーン間）の一貫性は同一参照画像の使い回し＋プロンプト設計で担保する必要があり、完全な保証ではない。

### 0-3. 画像生成

既存の `openai-image-gen`（gpt-image-2）・`nanobanana2-image-gen` スキルが実績済みのため、**参照画像生成はこれら既存スキルを流用**する（EvoLink・Atlas Cloudの画像生成APIは使わない、重複実装を避ける）。

### 0-4. EvoLinkの扱い（経緯として保持）

- 検証の経緯として、EvoLinkはSeedance 2.0を720p standard $0.199/秒・カード不要の無料クレジットありで提供しており、初期検証に有用だった（`tools/seedance-api-compare/`に実装・比較記録あり）。
- **本パイプラインの本実装では動画生成にAtlas Cloudを採用**するため、EvoLinkは正式な採用先ではない。ただし `tools/seedance-api-compare/` のEvoLink実装はモデル比較・障害時のフォールバック候補として資産を残しておいてよい（今回のスコープでは新規使用しない）。

## 1. ゴール

**指定した曲テーマ・歌詞（またはSuno API生成、または手持ち音源）から、60秒・9:16のショートMVと3分・16:9のフルMVをワンコマンドで自動生成できるパイプライン「MV Factory」を構築し、今後複数のMVを効率的に量産できる仕組みを整える。**

## 2. スコープ

### やること
- 1曲=1プロジェクトディレクトリ方式で、テーマ・ジャンル・尺・アスペクト比等をYAML/JSON設定ファイルで指定 → **ワンコマンド実行**で完パケMVを出力する仕組みを設計・構築する（承認ステップなしの全自動）
- 工程: 曲生成（Suno API または 手持ち音源投入の2モード）→ 曲構成解析（セクション/BPM/尺）→ 絵コンテ・シーンプロンプト生成 → 参照画像生成（既存の画像生成スキル流用、任意）→ シーン動画生成（Atlas Cloud Seedance 2.0、image-to-video対応）→ 編集・合成（曲と映像の同期）→ 完パケMV出力
- **パイロット2本立て**: 同一曲から (1) 60秒・9:16のショート版 (2) 3分・16:9のフル版 を両方生成できる設計にする
- コスト試算・リスク（著作権含む）の明文化
- 全自動フローを前提とした設計（Telegram承認等は将来オプションとして言及のみ）

### やらないこと（今回のスコープ外）
- 実際のMV制作の実行（本要件定義はパイプラインの**設計**のみ。実行はexecutor工程で別途進める）
- リップシンク・歌唱アバターの生成（Wan 2.6等は将来検討、今回は不使用）
- SNS/YouTubeへの自動投稿までの統合（`post-sns`スキルとの連携は将来拡張として言及に留める）
- Telegram承認フローの実装（将来オプションとして設計に余地を残す程度に留め、今回は実装しない）
- Suno/EvoLinkの商用利用可否に関する法的判断の確定（リスクとして提示し、オーナー判断を仰ぐ）
- Suno公式APIの詳細仕様調査（一般公開情報がないため、抽象化インターフェースで吸収し、詳細はオーナーからの情報提供を待つ）
- EvoLinkでの動画生成の新規実装（経緯資産として保持するのみ）

## 4. 工程一覧

パイロットは同一曲データを使い回し、工程2までは共通、工程3以降は**60秒・9:16版**と**3分・16:9版**をそれぞれ独立に実行する2系統構成とする。

| 工程 | 中間成果物 | 入力 |
|---|---|---|
| 工程0: プロジェクト設定 | `project.yaml`（テーマ・ジャンル・尺2種・アスペクト比2種等） | オーナー入力 |
| 工程1: 曲生成 | `song.mp3`（またはwav）+ 歌詞テキスト + 生成メタデータ（**共通・1本のみ**） | project.yaml |
| 工程2: 曲構成解析 | `song_structure.json`（BPM・セクション区切り・尺・歌詞タイムスタンプ、**共通**） | song.mp3 |
| 工程3-A: 絵コンテ生成（60秒/9:16） | `storyboard_short.json` | song_structure.json + project.yaml |
| 工程3-B: 絵コンテ生成（3分/16:9） | `storyboard_full.json` | song_structure.json + project.yaml |
| 工程4: 参照画像生成（任意・共通） | `references/*.png`（キャラ・世界観の参照画像、両尺で共用） | storyboard（キャラ設定部分） |
| 工程5-A: シーン動画生成（60秒版） | `clips_short/scene_XX.mp4` | storyboard_short.json + references |
| 工程5-B: シーン動画生成（3分版） | `clips_full/scene_XX.mp4` | storyboard_full.json + references |
| **品質ゲート-A: 全クリップ検査（60秒版）** | **`qc_report_short.json`（画風/人物/物理破綻の検査結果）+ 合格クリップ一式（不合格分は再生成済み）** | **clips_short/*.mp4** |
| **品質ゲート-B: 全クリップ検査（3分版）** | **`qc_report_full.json`（画風/人物/物理破綻の検査結果）+ 合格クリップ一式（不合格分は再生成済み）** | **clips_full/*.mp4** |
| 工程6-A: 編集・合成（60秒版） | `final_mv_short_9x16.mp4` | song.mp3 + 品質ゲート-A通過後のclips_short/*.mp4 |
| 工程6-B: 編集・合成（3分版） | `final_mv_full_16x9.mp4` | song.mp3 + 品質ゲート-B通過後のclips_full/*.mp4 |

**工程間の依存関係**: 工程0→1→2は直列・共通（1本の曲を1回だけ生成）。工程2完了後、工程3-A/3-Bに分岐し、以降はそれぞれ独立に工程4（共用可）→5→**品質ゲート**→6と進む。工程4（参照画像）は両系統で同じ参照画像を使い回してよい（キャラ一貫性の観点でむしろ共用が望ましい）。**品質ゲートは工程5と工程6の間に必ず挟む。全クリップが画風統一・人物統一・物理的不自然描写の検査に合格するまで工程6（合成）には進まない。不合格クリップは工程5に差し戻して再生成する。**

**実行順序の推奨**: 先に60秒・9:16版（3-A〜6-A）を通しで完成させ、パイプライン全体の疎通を確認してから3分・16:9版（3-B〜6-B）に進む（オーナー指定の「まず60秒→同じ曲で3分」の順）。

## 6. リスク・制約

1. **Suno楽曲の著作権・商用利用リスク（残論点）**: 非公式リセール（EvoLink等）は不採用となり回避済みだが、Suno公式APIを使ってもSuno社自体のサービス利用規約・商用利用条件（サブスクプラン等）には従う必要がある。また、AI音楽学習データを巡る業界全体の訴訟（UMG/Sony継続中）は解消されていない。→ **収益化・公開前提のMVに使う場合はSuno公式の利用規約を確認の上、必要であればオーナーの明示承認を得ること。**
2. **Suno公式APIの仕様不確定**: 一般公開情報がないため、本書では抽象化インターフェースで対応。オーナーのAPIキー到着後、実際のエンドポイント・パラメータ・料金体系に応じて工程1の実装を確定させる必要がある（executor工程での追加調査が発生しうる）。
3. **動画URLの有効期限**: Atlas Cloud生成物のURL失効時間は要確認（EvoLinkは24時間だった実績あり）。パイプラインは生成完了検知後、即座にローカル/Driveへダウンロードする設計を原則とする。
4. **Atlas Cloudの要チャージ**: 無料クレジットがなく、残高切れで即座に生成が止まる。全自動（承認なし）パイプラインのため、残高不足時にサイレントに失敗しないよう、明確なエラーメッセージ・ログ出力が必須。
5. **User-Agentヘッダー必須**: Atlas Cloud APIコール実装時、User-Agentヘッダーを付与し忘れるとリクエストが拒否される。実装時の注意点として明記。
6. **モデルID・料金の変更リスク**: Seedance 2.0のモデルID・料金体系は変更されうる。モデルIDは設定ファイルに外出しし、コード変更なしで切替可能にする。
7. **キャラクター一貫性の限界**: image-to-video（first/last-frame）で1クリップ内の一貫性は担保できるが、クリップをまたいだ一貫性は同一参照画像の使い回し＋プロンプト設計に依存し、完全な保証ではない。
8. **全自動ゆえの失敗検知の重要性**: 承認ステップがないため、途中工程で不良（変な映像・ズレた同期等）が発生しても人間がリアルタイムに気づけない。品質検証（video-quality-checker流用）を最終工程に組み込むか、少なくとも完パケ後にサムネイル一覧等で事後確認できる仕組みを推奨する。
9. **著作権（音楽以外）**: 動画生成AIの学習データに起因する著作権リスク（既存キャラ・作風の意図しない模倣等）も一般論として存在する。
10. **画風・人物一貫性のAI生成限界**: Seedance 2.0はimage-to-videoで一定の一貫性を担保できるが、テキストプロンプトのみに依存するシーンや長尺クリップでは画風のブレ・キャラクターの別人化・物理的破綻が発生しうる。品質ゲート（工程5-6間）による事後検査と再生成が前提であり、1回の生成で完全な一貫性を保証するものではない。再生成ループが上限に達した場合、シーン自体の差し替えが必要になることがある点をコスト・納期の見積もりに織り込むこと。
