### 正規化ルール詳細（実装者向け）

```
三点リーダ統一  : … (U+2026) / ‥ (U+2025) / ... → ... (ASCII 3文字)
ダッシュ統一    : — (U+2014) / ― (U+2015) → - (ASCII ハイフン)
               ※ 長音記号 ー (U+30FC) は日本語として有効なためダッシュ統一の対象外とし、
                  NFKC 正規化の範囲に留める（音引きをハイフンに変換しない）
引用符正規化    : 〝 (U+301D) / 〟 (U+301F) / " (U+201C) / " (U+201D) → " (ASCII)
               : 「」→ そのまま保持（日本語括弧は正規化対象外）
               : 『』→ そのまま保持（同上）
波ダッシュ統一  : 〜 (U+301C) / ～ (U+FF5E) → ~ (ASCII チルダ)
```

> **設計補足 - ダッシュと長音記号の識別について**
> `ー`（U+30FC、カタカナ長音符）はセリフ内で「えーっ」「そーだ」のように使われる。
> ダッシュ（`—`/`―`）はナレーションや区切りで使われる。
> 文字コード上は異なるため、`ー` を統一対象から外し `—` と `―` のみハイフンに寄せる設計とする。

### fuzzy matching 設計

- **デフォルト**: 編集距離（Levenshtein 距離）が 2 以内であれば PASS 扱い
- **キャラ名・固有名詞**: 完全一致必須（誤字を看過しないため）
  - 実装指針: `character_defs.json` の `name` フィールド値が expected テキストに含まれる場合は fuzzy スキップ、完全一致で判定
- **`--strict-ocr` フラグ**: 指定時は従来の完全一致判定に戻す（fuzzy 無効）
