# 壁打ち: 組織が機能していない問題 → 自律実行型への転換

## 課題
- 「組織」という器は作ったが、結局オーナーが全部指示を出して全部やっている
- 部署は「フォルダ」になっており、自律的に動くトリガーがなかった
- 期待していた姿: 「やりたい」→ CEO振り分け → 各部署が作業 → 進捗報告を待つだけ
- 実際の姿: 「やりたい」→ 秘書が提案 → オーナーが承認 → オーナーが作業

## 決定事項

### 組織の設計方針
- 「フォルダ型組織」→「自律実行型組織」へ転換
- オーナーは「経営者」であり「作業者」ではない
- 組織は「オーナーが決めたことを自律的に実行する」仕組み

### 実行フロー（4フェーズ）
1. **Phase 1: ゴール確認（秘書）** — 成果物/仕組み/両方、スコープ、完了条件を確認 → オーナー承認
2. **Phase 2: CEO振り分け** — 振り分け計画作成 → オーナー承認 → チケット生成
3. **Phase 3: 自律実行（各部署Agent）** — 並列実行、MSごとに承認確認
4. **Phase 4: 進捗報告・完了（秘書）** — 報告、DASHBOARD更新

### ゴール確認の重要ポイント
- 「成果物を作るのか、成果物を作る仕組みを作るのか」を最初に明確にする
- 例: リール台本 vs リール台本量産スキル

### 3層構造
- **セッション中**: Agent並列実行で高速に進む
- **セッション間**: ファイルに状態保存 → 次回起動時に自動検出・再開
- **定期cron**: 承認不要なルーチンは無人で回す

### 承認ポリシー
- ゴール確認時に1回、CEO振り分け時に1回、マイルストーンごとに承認
- 全部任せっきりではなく、要所で確認を挟む

## 実装内容

- `secretary/CLAUDE.md`: 起動時チェック・ゴール確認フロー追加
- `ceo/CLAUDE.md`: 振り分け計画の構造化・チケット生成フロー追加
- `pm/tickets/_template.md`: 実行管理フィールド追加
- 全部署CLAUDE.md: 自律実行ルール追加
