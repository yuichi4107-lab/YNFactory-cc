## メモ・振り返り

### Sales OS 構築の教訓
1. **GoogleMaps旧ライブラリはLegacy API叩き**: 新規GCPプロジェクトでは Places API (New) が必須。`googlemaps` Pythonライブラリは Legacy API 用で REQUEST_DENIED になる → REST直叩きで PlacesApiNewClient 実装が必要
2. **Claude sonnet-4-6 は ```json``` フェンスで囲む癖あり**: JSONDecodeError 回避のため `_strip_code_fence` ヘルパーを必ず入れる
3. **AI 生成DMの架空署名問題**: 送信者情報をプロンプトに明示注入しないと Claude が架空名・架空メアドで署名欄を埋める → 特電法違反リスク。`sender_info` を Personalizer.__init__ で受け取る設計が必須
4. **Google Workspace のOAuth は別ルール**: Workspace管理者ポリシーで外部OAuth・IMAP/SMTPがブロックされているケース多し。個人Gmail OAuth + 「別のアカウントから送信」エイリアス方式が現実的
5. **DBはGoogle Drive配下禁止は Sales OS でも継続遵守**: /opt/sales-ops/data/ に配置、JP-DAYTRADE と同じ教訓

### JP-DAYTRADE 工程0→工程1 の重要教訓
1. **J-Quants は V1 廃止 → V2 x-api-key 方式**: 前回400 Incorrect の根本原因はスキーマ変更（email+pw→refresh_tokenフロー廃止）。V2公式Colabノートブック必読
2. **SQLite DBは絶対にGoogle Drive配下に置かない**: 書込中同期干渉で malformed 破損（483/608銘柄で発生）。ローカル C:/dev/ 必須
3. **Free プラン V2 API の追加制約**: /equities/bars/daily は1年範囲が上限、/equities/earnings-calendar は翌日分のみ（過去履歴は /fins/summary の DiscDate で代替）
4. **日足データでは板情報戦略はBT不可**: F6(寄り前売買比率)/F7(板厚み)は過去データ取れないので、バックテストでは F1-F5 + 出来高系 + モメンタム系のみ使える → 戦略設計の出発点をデイトレ板情報ではなく**日足完結型のスイング系**に切り替える判断が必要

### 化け株分析で判明した戦略シード
- **マクロパニック反発（勝率ほぼ100%）**: 2025-04-08/10 の関税ショック反発で19/19銘柄が+5%以上 → 日経-3%翌日の寄り成り戦略
- **セクター連動（AI半導体・防衛）**: 同日3銘柄以上+5% = セクターイベント、翌日出遅れ買いで乗れる
- **出来高爆発**: vol_x20 ≥ 10 の日は必ず材料あり（東邦チタニウム 20.7倍、大阪チタニウム 13.3倍）、翌日追従で捕捉可能
- **寄り弱→場中爆騰は日足では予測不可**: gap-0%でも+20%上がる日がある（サンバイオ・東邦チタニウム）→ 引け後のvol_x20とpct見て翌日判断
