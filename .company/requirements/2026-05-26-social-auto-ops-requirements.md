# note / X / Threads / Instagram 自動運用 要件定義

## 1. ゴール

note、X、Threads、Instagram の4媒体を、AI活用・AI導入商材への集客導線として連携させ、日々の記事・投稿作成、媒体別最適化、下書き保存、予約または投稿、結果記録、失敗時の再実行までを自動化する。

現在のnote 5アカウント運用は保留し、初期版ではAI領域に集中する。noteはAIテーマの発信アカウントを中心に扱い、他テーマ（お金、キャリア、スピリチュアル、恋愛）は今回の自動運用対象から外す。

最初の完成形は「1つの投稿企画から、note記事、X向け短文、Threads向け本文、Instagram向けキャプション＋画像を生成し、短文SNSからInstagram / noteへ誘導し、noteでしっかり伝えたうえでLPから申し込みにつなげる状態」とする。

## 1.1 集客導線

基本導線は以下とする。

1. X / Threads
   - 文字数制限のある短文SNSとして、問題提起・気づき・短い事例を投稿する。
   - 投稿内では、詳しい解説をInstagramまたはnoteへ誘導する。
   - プロフィール欄にはLP URLを設置し、直接申し込みの可能性も残す。

2. Instagram
   - 視覚的に理解しやすい図解・カルーセル・短尺動画の入口として使う。
   - 投稿内では、詳しい考え方や事例をnoteへ誘導する。
   - プロフィール欄にはLP URLを設置し、直接申し込みの可能性も残す。

3. note
   - 信頼形成の中心媒体として、AI活用・AI導入についてしっかり伝える。
   - 読者の課題、導入前の不安、導入後の変化、具体例、判断基準を丁寧に説明する。
   - 記事末尾からLPへ誘導し、相談・資料請求・申し込みにつなげる。

4. LP
   - 最終的な申込・問い合わせ・相談予約の受け皿にする。
   - 各SNSプロフィール、Instagram投稿、note記事末尾から到達できるようにする。

商材は「AIの活用・導入」とし、主な訴求は以下を想定する。

- 個人事業主・中小企業向けのAI活用支援
- 業務効率化、投稿作成、資料作成、営業支援、問い合わせ対応などの導入
- AIを使いたいが、何から始めればよいかわからない層への伴走
- 社内にAI活用を定着させるための設計・教育・運用支援

## 1.2 初期投稿頻度

初期運用では、量よりも継続性と導線の一貫性を優先する。

| 媒体 | 初期頻度 | 役割 |
|---|---:|---|
| X | 1日2〜3投稿 | 気づき、問題提起、短い事例、note誘導 |
| Threads | 1日1〜2投稿 | 少し長めの考え方、体験談、note誘導 |
| Instagram | 週3〜5投稿 | 図解、カルーセル、信頼形成、プロフィールLP誘導 |
| note | 週2本 | 深い解説、事例、LP誘導 |
| LP | 常設 | 申込、相談、資料請求の受け皿 |

標準の週間リズムは以下を想定する。

- 月曜・木曜: note記事を完成させる。
- note記事の完成日に、X 2〜3本、Threads 1本、Instagram 1本を展開する。
- noteがない日も、XとThreadsで短い気づきや事例を投稿する。
- Instagramは週3本から開始し、慣れてきたら週5本まで増やす。
- すべてのプロフィール欄にLP URLを設置する。
- note記事末尾には必ずLPへの自然なCTAを入れる。

## 3. スコープ

### やること

- 現在のX投稿機能を壊さず、共通投稿キューから呼び出せる形に整理する。
- Meta側の必要権限、トークン、IDを確認し、Instagram / Threads 投稿の最小実装を行う。
- `scripts/post_to_meta.py` を実装し、Instagram / Threads の投稿に対応する。
- AIテーマのnote記事生成、画像配置、下書き保存、履歴更新までを共通キューから扱えるようにする。
- 4媒体共通の投稿キューを作る。
- 投稿内容を媒体ごとに最適化する。
- 媒体ごとに役割を分け、X / Threads / Instagram は入口、noteは理解・信頼形成、LPは申し込み導線として設計する。
- 投稿・記事の末尾やプロフィール導線に、LPまたはnoteへの誘導文を自然に組み込む。
- 失敗時に、どの媒体が失敗したか、再実行できるかを記録する。
- 自動運用の最初の運用単位として、1日1回または指定時刻の投稿を登録できるようにする。
- 投稿前の承認あり運用を初期値にする。

### やらないこと

- 初回から完全無人で大量投稿すること。
- Instagramリール動画の自動生成・投稿まで含めること。
- Metaアプリ審査の代行や、外部画面でのオーナー判断が必要な設定変更を勝手に行うこと。
- Google Sheets / GAS 方式へ必ず寄せること。まずはローカルキュー方式を本線にし、必要なら後続でGAS連携する。
- noteの公開・予約公開を勝手に行うこと。初期版ではnoteは下書き保存までとする。
- 保留中の4テーマ（お金、キャリア、スピリチュアル、恋愛）の投稿自動化を今回の初期版に含めること。

## 4. 完了条件

- X / Threads / Instagram の認証状態を一覧で確認できる。
- AIテーマのnoteアカウント設定、履歴、保存先を一覧で確認できる。
- 共通キューに1件登録すると、note記事と媒体別投稿文が生成される。
- 各媒体の投稿文に、役割に合った誘導先が設定されている。
  - X / Threads: Instagram または note、プロフィールLPへの誘導
  - Instagram: note またはプロフィールLPへの誘導
  - note: LPへの誘導
- noteは対象アカウントに対して下書き保存、またはブラウザブロック時にローカル下書き保存と `draft-status.md` 記録ができる。
- Xは既存認証でテスト投稿または dry-run が通る。
- Threadsはテキスト投稿の dry-run または実投稿テストが通る。
- Instagramは画像付き投稿の dry-run または実投稿テストが通る。
- 投稿結果が `success / failed / skipped` で記録される。
- 失敗した媒体だけ再実行できる。
- `post-sns` スキルの対応状況が実装後の状態に更新される。
- 品質チェックで85点以上。

## 5. 品質基準

- 認証情報を画面・ログ・成果物に露出しない。
- 実投稿・下書き保存前に、投稿先・本文・画像・公開予定時刻を確認できる。
- noteはAIテーマの対象アカウントのログイン状態を確認し、アカウント不一致時は下書き作成を停止する。
- note画像は指定どおりChatGPT Pro側の gpt-image-2 を基本とし、OpenAI APIへ勝手にフォールバックしない。
- 文字数制限に合わせて媒体別に調整する。
- 短文SNSは売り込みすぎず、問題提起・気づき・事例・チェックリスト型で入口を作る。
- noteではAI活用・AI導入の必要性、具体例、判断基準、導入ステップを丁寧に伝える。
- LP誘導は押し売りではなく、相談・資料請求・無料診断などの自然な次アクションにする。
- Instagramは画像必須として扱う。
- note / X / Threads / Instagram のいずれかが失敗しても、他媒体の成功記録を壊さない。
- API仕様変更に備えて、プラットフォーム別処理を分離する。
- ログは短く、長いレスポンスやトークンは保存しない。

## 7. 初期方針

初期版は「ローカルキュー + 承認あり + dry-run重視」で進める。Google Sheets / GAS 連携は、SNS投稿基盤が安定してから追加する。

投稿元は当面、以下のどちらにも対応できる形にする。

- 手動入力した投稿企画
- note記事やKindle/マンガ制作物からの告知投稿

noteは「投稿元」と「連携対象」の両方として扱う。基本の流れは、note記事を中心コンテンツとして作成し、その要約・切り口違い・告知文をX / Threads / Instagramへ展開する形にする。

短文SNSから直接LPへ飛ばす導線も残すが、主導線は「短文SNS → Instagram / note → LP」とする。特にnoteは、AI活用・AI導入の価値を深く伝える中心媒体として扱う。

## 8. 承認事項

この要件定義で進めてよいか、オーナー承認を待つ。

承認後は、工程1から順に executor → quality-checker で進める。
