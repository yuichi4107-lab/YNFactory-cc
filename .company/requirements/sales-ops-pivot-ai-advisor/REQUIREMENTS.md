## ゴール

2026年6月末までに、AI活用アドバイザーとしての個別Zoom商談を経て L1/L2/L3 のいずれかで**初契約1件を獲得**し、月次経常収入（MRR）を最低4万円（L1）以上にする。また、初運用に必要なウェビナーコンテンツ（台本 + PPTX + 持ち帰り資料）と個別Zoom提案コンテンツ（台本 + PPTX + クロージング補助資料）を完成させ、即発表・即商談できる状態にする。

|---|---|---|
| MRR 20万円（2026-06-30） | **初契約1件獲得（MRR 4〜10万円）** | ウェビナー集客→個別Zoom→契約のリードタイム（2〜6週間）を考慮。6月末時点では初契約1件が現実的な達成水準。MRR 20万は2026-09月の目標に据え直す |

## スコープ

### やること

- 既存 212件の approval_queue を全件 `rejected_archive` ステータスでマーク（DBの履歴保全）
- DBスキーマ拡張（地方フィルタ用カラム、従業員数フィルタ、rejected_archive ステータス追加）
- AI活用アドバイザー向け新DMテンプレート作成（メール本文 + 件名バリエーション）
- 新ターゲットリスト構築ロジック実装（gBizINFO 主軸 + Google Maps 改良版 + 商工会議所名簿 Phase 2）
- ウェビナー集客基盤のセットアップ（LP / 申込フォーム / 自動メール / Zoom連携）
- 個別Zoom予約システムのセットアップ（Calendly または Cal.com）
- オファー資料作成（L1/L2/L3 説明書 + 補助金提案資料 + 契約書テンプレ）
- ウェビナーコンテンツ完成版作成（台本 + PPTX 30-50枚 + 持ち帰り資料PDF）― メインテーマ「人手不足対策×キャリアコンサルタント差別化」を最優先、追加2-3本は次フェーズ
- 個別Zoomコンテンツ完成版作成（30分台本 + PPTX 10-15枚 + クロージング補助資料）
- キャリアコンサルタント資格を活用した差別化要素をウェビナー・個別Zoom全体の通底メッセージとして組み込む
- VPS上の `run_list_builder.py` / `run_personalizer.py` を新方針に改修
- テスト5件生成 → オーナー確認 → 本番運用開始

### やらないこと

- 既存212件への追加アプローチ（全件却下し新方針でゼロ再構築）
- 首都圏（東京・大阪・名古屋・福岡）企業へのアウトバウンドDM
- 従業員30名未満・100名超の企業へのアプローチ
- AI/IT系企業・フランチャイズ大手へのアプローチ
- yn-tools ツール販売（月2,000円/ユーザー）を主訴求とするDM
- 軸A（フリーランス案件）・軸B（コンテンツ集客）の改修（今回スコープ外）
- 補助金申請事務の代行（提案資料作成のみ、実務は外注判断はオーナーへ）
- オフライン勉強会（6ヶ月以降フェーズ）
- Zoom Webinarプラン（Peatix / Zoom Pro で代替。必要なら後フェーズで検討）

## リスクとブロッカー

| リスク | 影響度 | 対策 |
|---|---|---|
| ~~Wantedly/リクナビのスクレイピング規約違反~~ | ~~高~~ | **規約違反確認済み・不採用決定**（Wantedly / リクナビNEXT / エン転職 / doda の4社すべてスクレイピング NG を法的確認。gBizINFO に切替済み） |
| gBizINFO APIのレート制限 | 中 | 1時間100リクエスト制限あり。バッチ取得時は sleep を挟み、1日の取得上限（2,400件）を超えないよう設計する。キャッシュ活用で再取得を最小化 |
| Claude API コスト増大（規模推定用） | 低 | 月150-1500円をオーナー承認済み。従業員数推定は gBizINFO の資本金・売上等から先にルールベース推定し、不明時のみ Claude API を呼ぶ設計で抑制 |
| ウェビナー集客ゼロ | 高 | 初回は小規模（5〜10名目標）。SNS・HP・Peatix掲載に加え、DM送付先への直接招待でカバー |
| Zoom Webinar有料プラン（$79/月）の要否 | 中 | 参加者50名以下なら Zoom Pro（$14.99/月）+ Peatix で代替可。50名超になったら切替検討 |
| Calendly無料枠の制限 | 低 | 無料プランは1イベントタイプ。初期は個別Zoom予約1本のみで十分。有料化は月10件以上の予約が安定してから |
| 補助金申請失敗時のクレーム | 中 | 提案資料に「申請は保証しない旨」を明記。「活用できる可能性がある」という訴求にとどめる |
| メールのスパム判定 | 高 | 既存の安全装置（1通/分・日次100通上限・特電法表記）を継続。新ドメイン送信は避けSPF/DKIM設定を確認 |
| DM返信率が低く商談化しない | 中 | 初月はA/Bテスト（件名バリエーション2本）でデータ収集。返信率2%未満なら文面全面見直し |

## MVP優先順位（4〜6週間で動く最小構成）

最初の4週間で動かすべき順序:

```
Week 1: 工程1（DB整理）+ 工程2（DM新テンプレ）
Week 2: 工程7（VPS改修）+ 工程8前半（テスト生成）
Week 3: 工程3b（リスト構築実装 — gBizINFO + a5 MVP）+ 工程8後半（本番稼働）+ 工程9（ウェビナーコンテンツ完成版）※必須
Week 4: 工程4（ウェビナー基盤）+ 工程5（Calendly）+ 工程10（個別Zoomコンテンツ完成版）※テスト運用に必要
```

工程6（オファー資料）はウェビナー開催の1週前までに整備すれば間に合う。
工程9・10 は工程6（L1/L2/L3詳細・契約書・補助金資料）に依存するため、工程6完了後に着手すること。

**工程3b MVP優先方針（2026-05-04 確定）**: gBizINFO + a5（Google Maps）の2ソースで先行実装する。a4（商工会議所）は Phase 2（手応え確認後）で対応。採用媒体4社（a3）は法的確認の結果スクレイピングNGが確定したため完全不採用。

**リード獲得ソース（更新版）**:
- 主軸: gBizINFO（経産省公式API、無料、業種・従業員数・都道府県フィルタ対応、法的リスクゼロ）
- 補完1: a5 Google Maps API（既存コード流用、市町村×業種フィルタ）
- 補完2（Phase 2）: a4 商工会議所（公開名簿のある5サイト: 新潟・鹿児島・長野・札幌・金沢）
- 不採用: a3 採用媒体4社（Wantedly / リクナビNEXT / エン転職 / doda — robots.txt/TOS でスクレイピング全面禁止）
