# 要件定義書: KDP絵本 1冊目ベース版制作

作成日: 2026-06-06
ステータス: approved_2026-06-06

## 1. ゴール

Amazon KDPで販売できる、3〜5歳向けのオリジナル絵本1冊目を制作する。

KDP版は単体で読者満足がある完成品にしつつ、巻末の控えめな案内から、名前・好きなもの・家族構成などを反映した「完全オリジナル版データ納品」へ展開できるベース商品として設計する。

## 2. 推奨企画

- 仮タイトル: おやすみ、きょうのきもち
- 対象年齢: 3〜5歳
- 購入者: 幼い子供を持つ親、祖父母、読み聞かせギフトを探す人
- テーマ: 寝る前の安心、感情の名前づけ、親子・家族の愛情
- 読後感: 静か、やさしい、安心する、何度も読める
- 差別化: 汎用版で「気持ちを寝かしつける」体験を提供し、個別版では子供の名前・好きなもの・家族メッセージに置き換えられる

## 3. スコープ

### やること

- 絵本企画、読者ニーズ、KDP販売方針の整理
- 32ページ構成のページ設計
- 本文テキスト作成
- キャラクター定義と絵柄ルール作成
- ChatGPT Images 2.0経路でのページ画像生成
- 文字を画像に焼き込まず、レイアウト工程で後載せする
- 表紙作成
- KDP用メタデータ作成
- KDPペーパーバック向けの印刷用PDF作成
- Kindle固定レイアウト向けEPUBまたはKPF相当の準備
- 個別版へつなぐ巻末CTAの文面設計
- 最終品質チェックと修正

### やらないこと

- 購入者ごとの個別版制作
- 個人情報・子供写真の受付フォーム構築
- KDPへの実アップロード作業
- Amazon広告運用
- 外部LP制作
- ハードカバー自費出版
- 既存キャラクター・商標・有名作品風の模倣

## 4. 既存スキルから流用する範囲

### theme-to-ebook から流用

- テーマリサーチ
- 企画決定
- `project.md` 作成
- KDP向けメタデータ作成の考え方

### ebook-to-manga から流用

- キャラクター定義 `character_defs.json`
- キャラクター参照画像生成
- ページ単位の画像生成・保存・QC
- 表紙生成
- 固定レイアウトEPUB構築の考え方
- `progress.json` による進捗管理

### kdp-cover-and-metadata から流用

- `書籍情報.md`
- `ジャンル・キーワード.md`
- `書籍紹介文_HTML.html`
- 表紙PNG/JPEGの保存ルール

### 流用しないもの

- 100ページ級マンガ構成
- コマ割りCSV
- 吹き出し・ナレーションOCR前提の品質チェック
- 「マンガでわかる！」タイトル規則
- OpenAI API / `OPENAI_API_KEY` / SDK直接呼び出し

## 6. 制作仕様

- ページ数: 32ページ
- 判型: KDPで扱いやすい正方形または縦長。初回推奨は 8.25 x 8.25 inch または 8 x 10 inch
- 色: フルカラー
- 画像: 文字なしで生成し、本文は後工程で配置
- 文章量: 1ページ 10〜40字程度、読み聞かせしやすい短文
- リズム: 繰り返しフレーズを入れる
- CTA: 巻末に控えめに掲載。KDP商品説明欄には外部URL・注文導線を入れない
- 著者名: 未指定の場合は Yuichi
- 出版社名: YN出版
- 画像生成: ChatGPT Images 2.0（Codex/ChatGPT側の画像生成経路）。APIは使わない

## 7. 工程分割

### 工程1: 企画・ページ設計

成果物:

- `research/theme_research.md`
- `project.md`
- `manuscript/page_plan.md`
- `progress.json`

完了条件:

- タイトル、対象年齢、購入者、読後感、販売方針が明確
- 32ページ全体の役割が定義されている
- 個別版へ差し替えやすい要素がページ設計に含まれている

品質基準:

| 評価項目 | 配点 |
|---|---:|
| KDP販売性と購入者像の明確さ | 25 |
| 3〜5歳向けの言葉・展開になっているか | 25 |
| 32ページ構成として無理がないか | 25 |
| 個別版への拡張性 | 25 |

合格基準: 85点以上

### 工程2: 本文・キャラクター・画像設計

成果物:

- `manuscript/story_text.md`
- `manuscript/character_defs.json`
- `manuscript/layout_notes.md`
- ページ別画像プロンプト

完了条件:

- 全ページ本文が完成している
- 主人公・家族・象徴キャラの外見と役割が定義されている
- 全ページの画像内容が文字なし前提で設計されている

品質基準:

| 評価項目 | 配点 |
|---|---:|
| 読み聞かせのリズム | 25 |
| 感情教育が説教臭くないか | 25 |
| 絵本として画面変化があるか | 25 |
| 画像生成しやすい具体性 | 25 |

合格基準: 85点以上

### 工程3: 画像生成・レイアウト・製本

成果物:

- `images/characters/*.png`
- `images/pages/page_NNN.png`
- `images/pages/page_NNN.jpg`
- `layout/interior_print.pdf`
- `KDP出版用/おやすみ、きょうのきもち.epub`
- `KDP出版用/interior_print.pdf`
- `KDP出版用/cover.png`
- `KDP出版用/cover.jpg`

完了条件:

- 全32ページの画像が揃っている
- 主要キャラクターの見た目が大きく崩れていない
- 画像内に不要な文字がない
- 本文が読みやすい位置・サイズで配置されている
- 印刷用PDFと電子版EPUBが作成されている

品質基準:

| 評価項目 | 配点 |
|---|---:|
| 画像の一貫性 | 20 |
| 文字の読みやすさ | 20 |
| ページ順・余白・塗り足しの安全性 | 20 |
| KDP向けファイル形式 | 20 |
| 表紙の訴求力 | 20 |

合格基準: 85点以上

### 工程4: KDPメタデータ・CTA・最終QC

成果物:

- `KDP出版用/書籍情報.md`
- `KDP出版用/ジャンル・キーワード.md`
- `KDP出版用/書籍紹介文_HTML.html`
- `QUALITY_REPORT.md`

完了条件:

- KDP登録に使える書籍情報が揃っている
- キーワード7枠候補がある
- 商品説明HTMLがKDP向けに整っている
- 個別版CTAがAmazonルール上リスクの低い表現になっている
- AI生成コンテンツ申告が必要であることを記録している

品質基準:

| 評価項目 | 配点 |
|---|---:|
| メタデータの完全性 | 25 |
| 商品説明の購入訴求 | 25 |
| CTAの安全性 | 25 |
| 最終成果物の不足なし | 25 |

合格基準: 85点以上

## 8. CTA方針

KDP商品説明欄には外部URL・注文ページ・フォーム誘導を入れない。

巻末ページでは、以下のような控えめな案内にする。

```text
この絵本を、お子さまの名前や好きなものに合わせて作る特別版も制作しています。
制作例は「YN出版 絵本 特別版」で検索してください。
```

電子版でリンクを使う場合も、フォーム直リンクではなく作者サイトまたは制作例ページに限定する。個人情報入力フォームへの直接誘導は避ける。

## 9. リスクと対策

| リスク | 対策 |
|---|---|
| AI画像の文字崩れ | 画像内に文字を入れず、後載せレイアウトにする |
| キャラクター一貫性の崩れ | キャラ参照画像と `character_defs.json` を作成してからページ生成する |
| KDP外部誘導で審査リスク | 商品説明欄にURLを入れず、巻末案内も控えめにする |
| 印刷で端が切れる | 塗り足し・安全余白をレイアウト工程で確認する |
| 子供写真・個人情報の扱い | 1冊目では収集しない。個別版は別工程で同意・保存期間・削除方針を定義する |
| 画像生成API利用の混入 | OpenAI API / SDK / `openai-image-gen` を使わず、ChatGPT Images 2.0経路のみ使う |

## 10. 承認後の開始条件

ユーザーが本要件定義を承認したら、工程1から実行する。

承認時に未指定の場合、以下をデフォルト採用する。

- タイトル: おやすみ、きょうのきもち
- 著者名: Yuichi
- 対象年齢: 3〜5歳
- ページ数: 32ページ
- 絵柄: 日本向け、やさしい絵本調、温かい色、丸みのあるキャラクター
- 形式: KDPペーパーバック用PDF + Kindle固定レイアウトEPUB
