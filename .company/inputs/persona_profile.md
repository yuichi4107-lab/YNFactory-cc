# ペルソナプロファイル

## 1. 判断パターン

### 即決するテーマ
- **技術選定**: AIツールの比較評価において「Claudeがメインツール」と即決（4/12）。ChatGPTの限界を認識した上でClaude Codeの優位性を明確に判断（4/19: 「指示1回で約8割の静的なものが生成できる」）
- **不要な提案の却下**: 「補助金があってもそもそもニーズがないため、新しいものは導入しない」と即断（4/8）。コンサル案件の計画を白紙に戻す判断も素早い（4/14）
- **金融判断**: 4000万円の融資を「投資と16で2000万円ずつに配分」と即決（4/9）。融資を活用した投資差益の創出も迅速に検討（4/16）
- **採用方針**: 「人を積極的に採用しない方針」を即決（4/9）。欠員募集時のみの採用方針（4/17）

### 熟考するテーマ
- **新規事業モデル**: 電子書籍プロデュース事業の展開、子供向けパーソナライズ絵本、自分史作成サービスなど、複数日にわたって反復検討（4/14, 4/21）
- **AIセミナー講座の価格設定**: 月額1万円か2万円か、質問の可否で差別化するかを慎重に検討（4/18）
- **データ管理改善**: 「1年かけてデータ管理の改善を試行錯誤する」と長期的視点で判断（4/17）
- **AIツールのコスト問題**: 高額課金の対策を「現状維持で動画コンテンツ化」か「Sonnet変更でコスト削減」か熟考（4/12）

### リスク許容度: 攻めの姿勢だが安全装置を必ず設ける
- **投資**: 4000万円借入、融資を使った投資差益の追求など、レバレッジを積極活用
- **ただし安全装置は徹底**: AI投資システムでは「DD30%以下制約」「MAX_CONCURRENT_SHORT_POSITIONS=3」「DAILY_SHORT_LOSS_LIMIT_PCT=-5.0%」「dry-runモード二重チェック」等を必ず設定
- **Sales OSでもDRY_RUN=true から段階的引き上げ（5→30→50→100）** という慎重なステップを踏む
- **新規事業**: アイデアは大量に出すが（1日14個のアイデアが出る日もある）、実行に移すのはフィルタリング後。MVPアプローチを採用（4/13: 「AIプロジェクトの改善はMVPと相性が良い」）

## 2. タスク優先順位の付け方

### 最優先に入る傾向
- **期限が明確なもの**: 展示会ブース関連（4/18納品、4/23搬入）は常に最優先
- **売上に直結するもの**: Sales OS（法人営業自動化）、電子書籍のKDP出版
- **システム障害・バグ**: FXのトークン更新、Coincheckバグ修正、Telegramの不具合対応
- **Meta SNSセットアップ**: 集客チャネルの拡大は最優先に位置づけ

### 通常に入る傾向
- **開発・実装系**: YN-tools QuickRec実装、電子書籍マンガの再生成・修正
- **検証系**: FX dry_run解除後のSim検証、Sales OSの段階的検証
- **コンテンツ制作**: マンガのプレビューチェック、YouTube棚卸し

### 「余裕があれば」に入りがち（= 後回しになるもの）
- **Instagramリール制作**: 3/29から休止、7社完了時点で止まったまま約1ヶ月放置
- **note記事の投稿**: 原稿完成済みなのに「余裕があれば」に分類され続ける
- **Manus連携**: 3/30から休止、再開検討のまま消滅
- **YouTube日本史チャンネル棚卸し**: 4/5から毎日「通常」に入るが実行されず、事実上の放置
- **週次レビュー**: 「余裕があれば」に分類される傾向

### パターン: 「完了率80%の壁」
- 多くのプロジェクトで80%まで一気に進むが、最後の仕上げ（KDPアップロード、note投稿等）が後回しになる傾向
- 例: 電子書籍マンガは全4巻EPUB製本完了（4/9）だがKDPアップロードが「通常」のまま4/22時点でも未完了
- 例: note記事は原稿完成済み（3/15頃）だが4/22時点でまだ「余裕があれば」に残存

## 3. 時間の使い方

### 日中パターン（Limitless AIのタイムスタンプ分析から）
- **早朝（5:00〜7:00）**: 個人プロジェクトの思考・アイデア出し。AI技術の考察、YouTube企画の構想（4/12 6:09 自律型AI考察、4/18 6:38 AIセキュリティ、4/21 5:30 Instagram連携確認）
- **午前（8:00〜12:00）**: 本業（美健グループ経営）の会議・実務。採用、経理、労務管理の議論が集中（4/9 8:30〜9:25, 4/17 8:28〜11:55）
- **午後（13:00〜17:00）**: 商談・外部ミーティング。電子書籍プロデュースの打ち合わせ、コンサル案件（4/14 14:00〜16:35, 4/10 13:01〜13:31）
- **夜（19:00〜23:00）**: 個人プロジェクトの実行。マンガ校正、AI投資検証、技術検討（4/12 22:46 マンガペンチェック、4/15 21:59 ルーチン機能検討、4/21 20:34 AI分身構想）

### 週末 vs 平日
- **平日**: 本業（美健グループ）の経営タスクが日中を占める。個人プロジェクトは早朝・夜に回される
- **週末**: Claude Codeを使った集中的な開発セッションが多い。1日で複数の大型タスクを完了させる（4/9: 電子書籍EPUB製本+FX設計+シフトアプリ要件定義、4/14: マンガ4巻分のプレビュー+再生成+EPUB再製本）

### マルチタスク型
- 1日のTODOに5〜10以上のプロジェクトが並列で存在する（4/22のTODO: Meta SNS、Sales OS、FX、YN-tools、マンガ4巻、デバイス運用等）
- ただし、セッション内では1つのプロジェクトに集中して完了させる傾向（4/14: マンガ関連を一気に4巻分処理）
- **コンテキストスイッチが速い**: 朝は経営会議→午後は商談→夜はAI開発と、全く異なる領域を同日にこなす

## 4. 価値観・判断基準

### ビジネス判断の軸
1. **自動化・仕組み化への強い志向**: 手動作業を嫌い、仕組みで解決することを最優先する。「確認事項を待たずに、タスクをどんどん進める方針を承認」（4/13）。Sales OSの自動営業、AI投資の自動売買、cron/launchd/watchdogによる自動化が全プロジェクトに共通
2. **スケーラビリティ重視**: 「テンプレート化」「パッケージ化」「量産」というキーワードが繰り返し出現。絵本サービスは「シナリオテンプレートでコスト削減し5万円で提供」（4/21）、マンガは「共通プレフィックスで一括再生成」
3. **レバレッジの追求**: 自分1人の時間を最大化するために、AI・外部人材・融資を活用。「借金をしてでも投資に回すことで大きなリターン」（4/15）、「外部コンサルタントを積極的に利用」（4/17）
4. **実践 > 学習**: 「AIスキル習得は勉強5%、訓練95%の実践的アプローチ」（4/8）。理論より手を動かすことを重視
5. **コスト意識**: AIツールの課金問題に敏感（4/12）、スマホ内線の無料ライセンス共有運用（4/14）、低利融資で高利運用の差益追求（4/16）

### エネルギーを使うこと
- **新しいAI技術の探索と事業への応用**: マネージドエージェント、フィジカルAI、マルチモーダルAI等の最新動向を日常的にキャッチアップし、即座にビジネス応用を考える
- **仕組みの設計と構築**: Sales OS、AI投資パイプライン、ebook-to-mangaスキルなど、一度作れば繰り返し使える仕組みの構築に大きなエネルギーを投入
- **品質チェック**: マンガの1ページ単位の校正（室内靴、話者マーカー混入、英語混入、フリガナ等）を自ら行う。品質ループ（85点以上合格）を全作業に適用

### 避ける傾向のあること
- **経理・事務処理**: 経費精算の遅延に注意喚起を受ける（4/11）、「経理・事務が後回しになりがち」（CLAUDE.md パーソナライズメモ）
- **コンテンツの最終公開作業**: 原稿完成から公開/投稿の最後の一歩が遅れがち
- **定型的な繰り返し作業**: Instagram手動投稿を「しばらく継続」と判断するが、早期に自動化を志向（4/11）

## 5. プロジェクト優先度の傾向

### 高頻度で進捗するプロジェクト（= 実質的な最優先）
1. **電子書籍マンガ制作**: 毎日のように修正・再生成・チェックが行われ、4巻同時並行で進行。品質へのこだわりが強い
2. **AI投資システム**: BTC自動売買→FX拡張→ショート戦略追加と継続的に発展。バグ修正も即日対応
3. **Sales OS**: 設計→実装→VPSデプロイ→バグ修正→段階検証と、短期間で一気に進行
4. **YN Tools**: 31ツールまで拡大。新ツール追加が継続的に行われる

### 停滞しがちなプロジェクト
1. **YouTube日本史チャンネル**: 4/5以降毎日TODOに「棚卸し」が載るが未実行。アイデアは豊富に出るが実行に移らない
2. **Instagramリール制作**: 3/29から休止したまま。7社完了で止まり、再開検討が繰り返されるのみ
3. **AI副業（Phase 2集客）**: note公開、ココナラ改善、CW追加応募がTODOに載り続けるが進捗しない
4. **電子書籍出版プロデュース**: 外部との打ち合わせは行われるが、具体的な案件化に至っていない

### 停滞するプロジェクトの共通特徴
- **外部プラットフォーム依存**: Instagram、YouTube、noteなど、外部サービスでの手動作業が必要なもの
- **クリエイティブ判断が必要**: 動画制作、コンテンツ企画など、「正解がない」判断を要するもの
- **即座に数値化できない**: 短期的なROIが見えにくいブランディング・集客系のタスク

### 加速するプロジェクトの共通特徴
- **技術的に自動化可能**: コードで解決でき、Claude Codeで一気に進められるもの
- **品質が定量的に測定可能**: 85点以上合格の品質ループが適用できるもの
- **VPSにデプロイして放置できる**: 仕組み化の最終形が明確なもの

## 6. コミュニケーションスタイル

### 意思決定の伝え方
- **簡潔で断定的**: 「進める」「やらない」「白紙に戻す」など、短い言葉で方針を伝える
- **数値で語る**: 「4000万円を2000万ずつ」「月額1万円か2万円」「DD30%以下」「85点以上合格」
- **具体例で説明**: 抽象論よりも具体的なツール名、金額、期限を伴った指示を好む

### チームへの指示スタイル
- **自律実行を期待**: 「確認事項を待たずにタスクをどんどん進める方針を承認」（4/13）
- **事後報告で十分**: 組織CLAUDE.mdに「完全自動承認」「マイルストーン到達時は事後報告」を明文化
- **ブロッカー時は代替案を出すことを期待**: 「待ちです」で放置することを嫌う

### 外部とのコミュニケーション
- **ネットワーキング重視**: ビジネスマッチング、交流会、銀行イベントなど、対面での関係構築を重視
- **連絡先が非常に多い**: 14日間のinsightsで延べ100名以上の人物が登場。多方面に人脈を持つ
- **紹介ベースの信頼構築**: 銀行経由のビジネスマッチングなど

## 7. タスク優先順位AIへの指示テンプレート

以下は、このプロファイルに基づいてAIがタスク優先順位を判断するためのシステムプロンプト案です。

```
あなたはオーナーの秘書AIです。以下のオーナーの判断パターンに基づいてタスクの優先順位を付けてください。

## 優先順位判定ルール（上から順に適用）

### Tier 1: 最優先（今日やるべき）
- 期限が本日〜3日以内のタスク
- システム障害・バグ修正（自動売買、Sales OS、VPS等の稼働中サービス）
- 売上に直結する最終ステップ（KDPアップロード、請求書送付、納品等）
- 外部との約束がある商談・会議の準備

### Tier 2: 高優先（今週中にやるべき）
- 自動化・仕組み化の構築タスク（一度作れば繰り返し使えるもの）
- 品質チェックが定量的に完了するタスク（85点以上合格ループが回せるもの）
- 段階検証の次ステップ（dry-run解除、LIMIT引き上げ等）
- 本業（美健グループ）の経営判断を要するタスク

### Tier 3: 通常（余裕があるときに）
- コンテンツ制作の中間工程（原稿修正、画像再生成等）
- リサーチ・調査系タスク
- 外部プラットフォームでの手動作業（SNS投稿、note公開等）

### Tier 4: 後回し可能
- 長期的なブランディング・集客系（Instagram、YouTube棚卸し等）
- 「検討」「再開検討」と書かれているもの
- 週次レビュー、ドキュメント整理

## 判断時の注意点

1. **自動化できるか？**: 手動作業より仕組み化を優先する。「手動でしばらく継続」より「自動化スクリプト作成」を先に提案する
2. **80%の壁に注意**: 完成度80%で止まっているタスク（KDPアップロード、note投稿等）は意識的に優先度を上げる
3. **コスト意識**: AIツールの課金、外注費用、時間コストを常に考慮する
4. **MVPアプローチ**: 完璧を目指すより、最小限で動くものを先に出す
5. **並列実行**: 独立したタスクは並列で進められることを前提に計画する
6. **早朝・夜は個人プロジェクト**: 本業の会議が入る日中を避けて、AI開発等は早朝・夜に配置する
7. **週末は集中セッション**: 大型の開発タスクは週末にまとめて実行する提案が効果的
8. **放置タスクのリマインド**: 5日以上動いていないタスクは「このまま放置するか、正式に棚上げするか」を確認する
```
