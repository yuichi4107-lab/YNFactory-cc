# 要件定義書 — NotebookLM YouTube 自動同期システム

作成日: 2026-06-04  
バージョン: 1.0

---

## ゴール

ConoHa VPS 上で cron 駆動の Python スクリプトを稼働させ、指定 YouTube チャンネルの新規動画を Playwright で NotebookLM ノートブックに自動追加する仕組みを構築し、通常運用（定期自動同期）状態にする。

---

## スコープ

### やること

- 監視対象 YouTube チャンネル 2 つ（AI仙人 / 株式会社AX）の動画 URL を取得する
- 初回実行時はチャンネルの全動画を対象とする
- 2 回目以降は未処理（新規）動画のみを対象とする
- Playwright（headless Chromium）で NotebookLM Web UI を自動操作し、動画 URL をソースとして追加する
- 処理済み動画 ID を SQLite で管理し、二重追加を防止する
- 処理結果（成功サマリ・失敗アラート）を Telegram bot で通知する
- VPS の cron で定期実行スケジュールを登録し、通常運用状態にする
- config.yaml へのチャンネル追記だけで監視対象を拡張できる構成にする

### やらないこと

- NotebookLM 公式 API の利用（存在しないため）
- Google アカウントの自動ログイン処理（手動ログイン済みプロファイルを転送して流用）
- 動画コンテンツのダウンロード・保存
- NotebookLM 上でのノートブック内容の読み取り・要約処理
- YouTube Data API v3 の利用（yt-dlp / feedparser で代替）
- Slack・メール等 Telegram 以外の通知チャネル対応
- Windows ローカル環境での本番稼働（開発・テストは許容）
- コンテナ化（Docker）— 既存 VPS 環境に直接配置

## リスクと対策

| # | リスク | 影響度 | 対策 |
|---|---|---|---|
| R1 | NotebookLM の Web UI 変更（セレクタ・フロー変更） | 高 | Playwright のセレクタを config.yaml または定数ファイルに集約し、変更箇所を最小化する。エラー時は Telegram アラートで即時検知する |
| R2 | Google ログアウト（セッション切れ） | 高 | ログインページへのリダイレクト検出で処理中断＋Telegram アラート送信。手動再ログイン後に `.auth/` を再転送する運用手順を README に記載する |
| R3 | YouTube RSS の最大 15 件制限（feedparser） | 中 | 初回は yt-dlp で全件取得。2 回目以降は RSS（15 件）で差分取得するが、15 件を超える大量投稿がある場合は yt-dlp にフォールバックするロジックを `youtube.py` に実装する |
| R4 | yt-dlp の YouTube 仕様変更による取得失敗 | 中 | yt-dlp を定期的に最新版に更新（`pip install -U yt-dlp`）。cron に月次更新スクリプトを追加する |
| R5 | NotebookLM のソース追加上限（1 ノートブックあたり） | 中 | ノートブックのソース件数を `state.py` で管理し、上限近接時に Telegram アラートを送る。超過時は新ノートブックを手動作成し `config.yaml` を更新する運用とする |
| R6 | VPS の IP が YouTube にレート制限される | 低 | yt-dlp 実行間に `time.sleep()` でウェイトを入れる。連続失敗時はバックオフして Telegram 通知する |
| R7 | `.auth/` が誤って git に追加される | 高 | `.gitignore` への記載を工程1完了条件に含める。工程2のコード品質チェックで確認する |

## 備考

- NotebookLM の notebook_id は対象ノートブックの URL（`notebooklm.google.com/notebooklm.google.com/notebook/xxxxx`）から取得する。工程4でログイン確認後に採番する
- Playwright のヘッドレス動作は VPS（GUI なし）で必須。`playwright.chromium.launch(headless=True)` を前提とする
- Telegram bot トークン・チャット ID は環境変数または `config.yaml` の別ファイル（`secrets.yaml`）で管理し、コードへの直接記載を禁止する
- 工程3以降のデプロイ作業は ConoHa VPS（163.44.101.31 / Ubuntu 22.04）を対象とする
- 各工程は前工程の品質チェック合格（85 点以上）後に着手する
