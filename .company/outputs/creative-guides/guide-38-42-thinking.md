# テーマ38：アイデア出しアシスタント

## このツールでできること

ブレスト（ブレインストーミング）の相棒として、テーマに対してたくさんのアイデアを出します。自分一人では思いつかない角度からの発想もしてくれるので、「発想が広がる」体験ができます。

## こんなときに使ってください

- 新しい企画のアイデアが欲しい
- 一人で考えていて行き詰まった
- いつもと違う視点でアイデアを出したい
- アイデアの数を出して、そこから選びたい

## 使い方

テーマを伝えるだけ。「自由に」「現実的に」「ぶっ飛んだ発想で」など方向性も指定できます。

### 入力例
```
社内の忘年会を盛り上げる企画。予算は5万円。参加者30人。
自由な発想でお願い！
```

## このツールが使うアイデア出しの手法

| 手法 | やり方 |
|------|--------|
| オズボーンのチェックリスト | 「大きくしたら？小さくしたら？逆にしたら？くっつけたら？」で発想を広げる |
| 異業種からのヒント | まったく違う業界のやり方を参考にする |
| 逆転発想 | 「最悪の○○は？」からヒントを得る |
| 掛け合わせ | 出てきたアイデア同士を組み合わせる |

## コツ

- **最初は「量」を出す** → 質より量。判断は後
- **「それ無理でしょ」は禁止** → どんなに突拍子もないアイデアもOK
- **出た後に「選ぶ」フェーズを分ける** → 出すフェーズと選ぶフェーズを混ぜない

# テーマ39：どっちがいい？アシスタント

## このツールでできること

「AとBどっちにしよう？」を、感覚ではなくロジカルに比較して決められるようサポートします。メリット・デメリットを表にして、点数をつけて比較します。

## こんなときに使ってください

- 2つ以上の選択肢で迷っている
- メリデメを整理したい
- 感覚ではなくデータで判断したい
- 上司に「なぜこれを選んだか」を説明する必要がある

## 使い方

迷っている選択肢と、何を大事にしたいかを伝えるだけ。

### 入力例
```
プロジェクト管理ツールを導入したい。
候補：Notion（無料プラン） vs Backlog（月額2,000円）
重視するもの：使いやすさ、コスト、チームで共有しやすいか
```

## 出力のイメージ

```
▼ メリット・デメリット
【Notion】良い点：無料、柔軟 ／ 悪い点：自由度が高すぎて迷う
【Backlog】良い点：タスク管理に特化 ／ 悪い点：月額費用がかかる

▼ 点数をつけて比較
| 基準 | Notion | Backlog |
|------|--------|---------|
| 使いやすさ | ★★☆ | ★★★ |
| コスト | ★★★ | ★★☆ |
| チーム共有 | ★★☆ | ★★★ |
| 合計 | 7点 | 8点 |

▼ おすすめ：Backlog
```

## 「まだ迷う」ときのヒント

- **「1週間後にどう思うか」を想像する** → 短期の感情に流されない
- **「やめたとき何を失うか」で考える** → 失うものが大きい方が大事
- **「とりあえず小さく試す」** → 両方試せるなら試してから決める

# テーマ40：ツッコミ想定アシスタント

## このツールでできること

プレゼンや提案の前に、「こう突っ込まれるかも」を先回りして準備します。想定される質問・反論と、その回答をセットで作ります。

## こんなときに使ってください

- 明日のプレゼンで何を聞かれるか不安
- 経営層への提案で反対されそう
- クライアントからの厳しい質問に備えたい
- 「本当にうまくいくの？」と言われたときの回答を準備したい

## 使い方

提案の内容と、誰に発表するかを伝えてください。

## 出力のイメージ

```
▼ まず聞かれること
Q：このプロジェクトの投資回収期間は？
A：6ヶ月を見込んでいます。根拠は…

▼ 厳しいツッコミ
Q：「前回の類似プロジェクトは失敗したよね？」
A：前回の失敗原因は○○でした。今回は○○を改善しており…

▼ 「分からないこと」への答え方
→ 「現時点では○○のデータが不足しています。○日までに調査し、ご報告します。」
```

## 回答のコツ

| コツ | 理由 |
|------|------|
| まず結論、次に理由 | 結論が先にないとイライラされる |
| 数字で示す | 「すごく効果があります」より「20%改善します」 |
| 分からないことは正直に | 嘘をつくより「○日までに調べます」の方が信頼される |
| 想定質問は多すぎるくらい準備 | 10個準備して3個しか聞かれなくてもOK |

# テーマ41：考え整理アシスタント

## このツールでできること

「頭の中がごちゃごちゃ…」を、ロジカルに構造化します。ロジックツリーやピラミッド構造を使って、問題を分解し、考えを整理します。

## こんなときに使ってください

- 問題が複雑で何から考えればいいか分からない
- 上司に説明したいけど話がまとまらない
- 「で、結局何が言いたいの？」と言われがち
- 論理的に考えるのが苦手

## 使われるフレームワーク

| フレームワーク | 使い方 | 向いている場面 |
|-------------|--------|-------------|
| ロジックツリー | 「なぜ？」「どうやって？」で問題を分解 | 原因を探りたいとき |
| MECE | モレなくダブりなく分ける | カテゴリ分けしたいとき |
| ピラミッド構造 | 結論→根拠の順に整理 | 説得力のある説明をしたいとき |
| So What? / Why So? | 「だから何？」「なぜそう言える？」 | 論理の飛躍をチェック |

### ロジックツリーの例
```
売上が下がっている ← メインの問い
├── 客数が減っている
│   ├── 新規が減っている → 広告を減らしたから
│   └── リピーターが減っている → 満足度が下がっているから
└── 客単価が下がっている
    └── 値引きキャンペーンを多用しているから
```

# テーマ42：トラブル対応アシスタント

## このツールでできること

仕事でトラブルが起きたとき、「何が原因で → どう対応して → どう防ぐか」を整理します。パニックにならず、冷静に対応するための構造化をお手伝いします。

## こんなときに使ってください

- トラブルが発生して対応を整理したい
- 原因を分析したい
- 再発防止策を考えたい
- 上司やクライアントへの報告書を作りたい

## トラブル対応の3ステップ

| ステップ | やること | 時間感 |
|---------|---------|--------|
| ① 応急処置 | まず被害を止める | 即時 |
| ② 原因分析 | なぜ起きたか突き止める | 数時間〜数日 |
| ③ 再発防止 | 同じことが起きない仕組みを作る | 数日〜数週間 |

## 「なぜ？」を繰り返す方法

根本原因を見つけるには「なぜ？」を5回繰り返します。

```
問題：お客様に間違った見積書を送ってしまった

なぜ？ → 古いバージョンのファイルを送ったから
なぜ？ → ファイル名が似ていて間違えたから
なぜ？ → ファイルの命名ルールがなかったから
なぜ？ → ファイル管理のルールを決めていなかったから
→ 【根本原因】ファイル管理ルールの不在
→ 【対策】命名規則を決め、最新版だけを共有フォルダに置く運用にする
```

## 報告の書き方

トラブル報告は以下の順番で書くと伝わりやすいです。

1. **何が起きたか**（事実）
2. **影響の範囲**（誰に・何に）
3. **応急処置**（すでにやったこと）
4. **原因**
5. **恒久対策**（これからやること）
6. **再発防止策**
