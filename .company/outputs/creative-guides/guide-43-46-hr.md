# テーマ43：求人票作成アシスタント

## このツールでできること

人を採用するための求人票を、応募したくなる魅力的な形で作成します。必須条件・歓迎条件・仕事の魅力を整理して、ターゲットに刺さる求人票にします。

## こんなときに使ってください

- 新しいポジションの求人票を書きたい
- 求人を出したけど応募が来ない（書き方を改善したい）
- 採用要件を整理したい
- 求人サイトに載せる文章を作りたい

## 使い方

募集するポジション・仕事内容・条件を伝えるだけ。魅力が伝わる求人票にまとめます。

## 応募が集まる求人票のポイント

| ポイント | NG例 | OK例 |
|---------|------|------|
| 仕事内容は具体的に | 「営業業務全般」 | 「法人向けSaaSの新規営業。月10〜15社に提案」 |
| 数字を入れる | 「急成長中の会社」 | 「創業3年で売上5億円を達成」 |
| 「やりがい」を伝える | 「やりがいのある仕事です」 | 「顧客の業務時間を平均30%削減するプロダクトに関われます」 |
| 必須と歓迎を分ける | 全部「必須」 | 本当に必要なものだけ必須にする（応募ハードルを下げる） |

# テーマ44：評価コメントアシスタント

## このツールでできること

人事評価のコメントを、具体的で公平で、読んだ本人がやる気になる形で作成します。

## こんなときに使ってください

- 半期ごとの評価コメントを書く時期
- 「頑張っていた」以上の具体的なコメントが書けない
- 改善点の伝え方に悩んでいる
- たくさんの部下の評価を効率的に書きたい

## 使い方

対象者の成果・良かった点・改善点を伝えると、評価コメントにまとめます。

## 良い評価コメントのルール

| ルール | NG例 | OK例 |
|--------|------|------|
| 具体的な事実で書く | 「頑張っていた」 | 「Q2の新規獲得件数が目標15件に対し22件を達成」 |
| 行動にフォーカス | 「積極性がある」 | 「チームミーティングで毎回改善案を提案していた」 |
| 改善点は前向きに | 「報告が遅い」 | 「報告のタイミングを1日早めることで、チーム全体の判断スピードが上がる」 |
| 次のアクションを示す | 「もっと頑張って」 | 「次期はリーダー経験として、○○プロジェクトの主担当を任せたい」 |

## 評価コメントの構成

```
① 成果の評価（数字で。目標に対してどうだったか）
② 行動・姿勢の評価（どんな行動が良かったか）
③ 強み（継続してほしいこと）
④ 成長ポイント（もっと良くなるために）
⑤ 次の期間へのメッセージ（期待と応援）
```

# テーマ45：研修プログラムアシスタント

## このツールでできること

社内研修の内容・流れ・タイムテーブルを設計します。対象者のレベルと目的に合わせて、効果的なプログラムを作ります。

## こんなときに使ってください

- 新人研修の内容を考えたい
- 部内のスキルアップ研修を企画したい
- ワークショップの進行を設計したい
- 限られた時間で効果的な研修にしたい

## 使い方

テーマ・対象者・時間・ゴールを伝えると、タイムテーブル付きのプログラムが返ってきます。

## 研修設計のコツ

| コツ | 理由 |
|------|------|
| 「講義」と「ワーク」を交互に | 聞くだけでは眠くなる。手を動かすことで定着する |
| 90分で1回休憩を入れる | 集中力の限界は90分 |
| ゴールを明確にする | 「研修後に○○ができるようになる」を先に決める |
| ワークは3〜5人のグループ | 少なすぎると議論が浅い、多すぎると発言できない人が出る |

## 研修の基本構造

```
① アイスブレイク（5〜10分）→ 緊張をほぐす
② 導入・全体像の説明（10分）→ 何を学ぶかの見通し
③ 講義パート（20〜30分）→ 知識のインプット
④ ワーク・演習（20〜30分）→ 手を動かしてアウトプット
⑤ 共有・フィードバック（15分）→ 他の人の考えを聞く
⑥ まとめ・質疑応答（10分）→ 振り返りと疑問解消
```

# テーマ46：フィードバック準備アシスタント

## このツールでできること

部下や同僚への面談（フィードバック）の準備シートを作ります。「何を・どう伝えるか」を事前に整理することで、建設的で前向きな面談にできます。

## こんなときに使ってください

- 部下に改善点を伝えたいけど、どう言えばいいか…
- 良かったことを具体的に褒めたい
- 面談の進め方を事前に準備したい
- 相手がモチベーションを落とさない伝え方をしたい

## SBI形式とは？

フィードバックの鉄板フレームワークです。

| 頭文字 | 意味 | 例 |
|--------|------|-----|
| S（Situation） | いつ・どこで（場面） | 「先週のクライアントミーティングで」 |
| B（Behavior） | 何をしたか（行動） | 「提案資料を当日の朝に急いで修正してくれた」 |
| I（Impact） | どんな影響があったか | 「おかげでクライアントから高評価を得られた」 |

### ポジティブフィードバックの例
「先週のクライアントミーティングで（S）、提案資料を朝イチで修正してくれたおかげで（B）、先方から『分かりやすい』と高評価をいただけました（I）。ありがとう。」

### 改善フィードバックの例
「今月の月次報告で（S）、提出が期限の翌日になっていたことが2回ありました（B）。チームの集計作業が遅れてしまったので（I）、来月は前日までの提出をお願いできますか。何か困っていることがあれば教えてください。」

## 面談の進め方

```
① アイスブレイク（2分）→ 「最近どう？」
② 良かったことを伝える（5分）→ SBI形式で
③ 改善してほしいことを伝える（5分）→ SBI形式で
④ 相手の意見を聞く（5分）→ 「どう思う？」
⑤ 今後のアクションを決める（3分）→ 具体的に
```

## やりがちなNG

| NG | なぜ悪いか | こうする |
|----|----------|---------|
| 「あなたはダメだ」 | 人格否定になる | 「この行動を変えるともっと良くなる」 |
| 具体例なしで「もっと頑張って」 | 何を頑張ればいいか分からない | SBI形式で具体的に |
| 改善点だけ伝える | やる気がなくなる | 必ずポジティブ→改善の順で |
| 一方的に話す | 相手の事情を聞けない | 相手の意見を聞く時間を取る |
