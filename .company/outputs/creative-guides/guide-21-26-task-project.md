# テーマ21：タスク分解アシスタント

## このツールでできること

「大きすぎて何から手をつけたらいいか分からない」仕事を、今日すぐ着手できるサイズのタスクに分解します。

## こんなときに使ってください

- 大きなプロジェクトを任されたけど、何からやるか分からない
- タスクが漠然としていて手が動かない
- チームでタスクを分担したい
- WBS（作業分解構成図）を作りたい

## 使い方

「何の仕事を分解したいか」「いつまでか」を伝えるだけ。

### 入力例
```
会社の採用サイトをリニューアルしたい。期限は来月末。デザイナー1人とエンジニア1人で進める。
```

### 出力のイメージ
大きなまとまり → 中くらいのタスク → 今日やれるサイズ、に3段階で分解されます。

## タスク分解のルール

| ルール | 理由 |
|--------|------|
| 1タスク＝30分〜2時間 | これより大きいとまだ分解が足りない |
| 動詞で始める | 「デザイン」ではなく「トップページのデザイン案を3つ作る」 |
| 完了条件を決める | 「何ができたら終わり」を明確に |
| 依存関係を明示 | 「Aが終わらないとBに着手できない」を把握する |

# テーマ22：優先順位整理アシスタント

## このツールでできること

やることが多すぎるとき、「何から手をつけるべきか」を整理します。アイゼンハワーの優先順位マトリクス（緊急×重要の4象限）を使って、タスクを分類します。

## こんなときに使ってください

- やることが多すぎてパニック
- 全部急ぎに見えてしまう
- 何を捨てていいか分からない
- 今週やるべきことを絞り込みたい

## 4つの分類

```
        重要
         │
  ★今すぐやる  │  ☆計画を立ててやる
 （緊急×重要）  │ （重要×急ぎじゃない）
─────────┼──────────
  △サッと済ます │  ▽やめる・後回し
 （緊急×非重要）│ （非緊急×非重要）
         │
        非重要
```

## 使い方

タスクの一覧をざっくり伝えるだけ。4つに分類して、おすすめの取り組み順を提案してくれます。

## 判断のコツ

- **「2分で終わるもの」はすぐやる** → 分類に関係なく先に片付ける
- **迷ったら「重要度」を優先** → 急ぎだけど大事じゃないことに振り回されない
- **「本当にやる必要ある？」を自問** → 意外と不要なタスクが混ざっている

# テーマ23：プロジェクト計画アシスタント

## このツールでできること

新しいプロジェクトの計画書を作ります。「何を・誰が・いつまでに・どうやって」を一つの文書にまとめるので、関係者全員が同じ認識でスタートできます。

## こんなときに使ってください

- 新しいプロジェクトを始めるとき
- プロジェクト計画書のフォーマットが欲しい
- キックオフミーティングの資料を準備したい
- 上司にプロジェクトの全体像を説明したい

## 出力に含まれるもの

- **概要**（目的・背景・成功条件）
- **スコープ**（やること・やらないこと）
- **体制**（誰が何を担当するか）
- **スケジュール**（フェーズ・マイルストーン）
- **リスク**（心配事と対策）
- **コミュニケーション**（定例・報告の頻度・使うツール）

## よくある失敗と対策

| 失敗 | 対策 |
|------|------|
| 「やらないこと」を決めていない | スコープ外を明記して期待値を合わせる |
| マイルストーンがない | 中間チェックポイントを設けて早期に軌道修正 |
| リスクを考えていない | 最低3つは洗い出して対策を決めておく |

# テーマ24：進捗報告アシスタント

## このツールでできること

プロジェクトの進捗報告書を、伝えるべき情報を漏れなくまとめた形で作成します。進捗バーやステータスアイコン付きで、一目で状況が分かります。

## こんなときに使ってください

- 上司やクライアントに進捗を報告するとき
- 週次/月次の進捗報告書を作るとき
- 「今どのくらい進んでるの？」と聞かれたとき
- プロジェクトが遅れている理由を説明したいとき

## 出力のイメージ

```
全体の進み具合：60% ■■■■■■□□□□
ステータス：🟡 ちょっと注意

▼ できたこと
▼ 今やっていること
▼ 困りごと・リスク
▼ 次にやること
▼ 相談したいこと
```

## 進捗報告のコツ

- **「順調です」だけはNG** → 具体的に何が進んだか書く
- **遅れているときほど正直に** → 早めに共有すればリカバリーできる
- **数字で示す** → 「だいたい進んでる」→「60%完了」

# テーマ25：リスク洗い出しアシスタント

## このツールでできること

プロジェクトや仕事の「起きるかもしれない問題」を事前に洗い出し、対策を整理します。「まさかこんなことが…」を防ぎましょう。

## こんなときに使ってください

- 新しいプロジェクトを始める前に
- 「何か見落としてないかな？」と不安なとき
- リスク管理表を作りたいとき
- 上司に「リスクは？」と聞かれたとき

## 7つのチェック観点

| 観点 | チェックすること |
|------|----------------|
| スケジュール | 遅れないか？見積もりは甘くないか？ |
| お金 | 予算オーバーしないか？ |
| 品質 | 要件の抜け漏れはないか？テストは十分か？ |
| 人 | メンバーが辞めないか？スキルは足りるか？ |
| 技術 | 技術的に実現できるか？ |
| 外部 | 法律・市場・取引先が変わらないか？ |
| コミュニケーション | 認識のズレはないか？ |

## 出力のイメージ

リスクごとに「起きる可能性」×「影響の大きさ」で危険度を色分けし、対策をセットで出力します。

# テーマ26：スケジュール設計アシスタント

## このツールでできること

ゴールと期限からバックキャスト（逆算）して、現実的なスケジュールを作ります。テキスト版のガントチャートと週ごとのタスクリスト付きです。

## こんなときに使ってください

- 「○月○日までに仕上げて」と言われたとき
- プロジェクトのスケジュールを引きたい
- マイルストーンを設定したい
- チームの作業を週ごとに割り振りたい

## 使い方

ゴール・期限・やること・使えるリソースを伝えると、バッファ付きのスケジュールが返ってきます。

## 出力のイメージ

```
▼ テキスト版ガントチャート
| タスク | 1週目 | 2週目 | 3週目 | 4週目 |
|--------|-------|-------|-------|-------|
| 企画 | ██ | | | |
| 制作 | | ██ | ██ | |
| テスト | | | | ██ |
```

## スケジュール設計のコツ

- **バッファは2割入れる** → 10日の作業なら12日でスケジュールを組む
- **クリティカルパスを把握する** → 「これが遅れたら全部遅れる」タスクを特定
- **並行でできるタスクを見つける** → 全部を直列にしない
