# テーマ27：業務改善アシスタント

## このツールでできること

「今のやり方、もっと良くできないかな？」を形にします。現状の問題を分析し、改善案を比較表付きの提案書にまとめます。

## こんなときに使ってください

- 毎回同じ作業に時間がかかっている
- 「もっと効率的にできるはず」と感じている
- 業務改善の提案書を書きたい
- どの改善案がベストか比較したい

## 出力のイメージ

```
▼ 今の状態と問題
▼ 改善アイデア（複数案を比較）
▼ 比較表（時間・コスト・品質・始めやすさ）
▼ 進め方（まず試す → 本格導入 → 効果検証）
▼ 効果の測り方
```

## 業務改善の進め方

1. **現状を数字で把握する** → 「なんとなく遅い」→「1件あたり30分かかっている」
2. **理想を定義する** → 「1件15分にしたい」
3. **ギャップの原因を特定** → なぜ30分かかるのか
4. **改善案を比較** → このツールの出番
5. **小さく試す** → いきなり全面導入しない
6. **効果を測る** → 本当に良くなったか確認

# テーマ28：業務フロー作成アシスタント

## このツールでできること

仕事の流れを「見える化」します。テキストベースのフロー図を作るので、誰がどの順番で何をするかが一目で分かります。

## こんなときに使ってください

- 業務の流れを整理したい
- 「この仕事、手順が複雑すぎない？」と感じたとき
- 新人に仕事の全体像を見せたい
- 承認フローを可視化したい
- 無駄なステップがないかチェックしたい

## フロー図の読み方

```
[○○] → 作業ステップ（誰が何をする）
<○○> → 判断ポイント（Yes/Noで分かれる）
  ↓   → 次のステップへ進む
```

### 例：経費精算フロー
```
[スタート] 経費が発生する
  ↓
[申請者] 経費精算書を作成する
  ↓
[申請者] 上司に提出する
  ↓
<判断> 上司が承認する？
  ├─ はい → [経理] 支払い処理をする → [完了]
  └─ いいえ → [申請者] 修正して再提出 → 上司に提出に戻る
```

## 活用のコツ

- **まず大まかな流れを作って、あとから詳細を足す** → 最初から完璧を目指さない
- **判断ポイントを見つけるのが大事** → ここがボトルネックになりやすい
- **「このステップ、いらなくない？」を探す** → 業務改善のヒントになる

# テーマ29：抜け漏れチェックアシスタント

## このツールでできること

提出前の資料・メール・企画書を「もう一人の目」でチェックします。誤字脱字から論理の矛盾、情報の抜け漏れまで、多角的にレビューします。

## こんなときに使ってください

- 大事な資料を提出する前に最終チェックしたい
- メールの内容に自信がない
- 企画書に抜けがないか確認したい
- 数字の整合性をチェックしたい

## チェックする観点

| 観点 | チェック内容 |
|------|------------|
| 5W1H | いつ・どこで・誰が・何を・なぜ・どうやって、が揃っているか |
| 論理 | 話のつじつまが合っているか |
| 数値 | 計算ミスがないか、グラフと表の数字が一致しているか |
| 表現 | 誤字脱字、敬語の間違い、トーンの統一 |
| 構成 | 結論が先にあるか、見出しが分かりやすいか |
| 形式 | 宛先・日付は正しいか、添付の言及漏れはないか |

## 出力のイメージ

```
▼ 総合判定：🟡 少し修正あり

▼ 指摘リスト
| # | 種類 | 場所 | 内容 | 重要度 |
|---|------|------|------|--------|
| 1 | 誤字 | 3段落目 | 「以上」→「異常」の誤変換 | 低 |
| 2 | 数値不一致 | 表3 | 合計が1,000万なのに本文に900万と記載 | 高 |

▼ こうするともっと良くなります
- 結論を冒頭に移動するとインパクトが上がります
```

# テーマ30：KPI設計アシスタント

## このツールでできること

「目標を数字で測れる形」にするお手伝いをします。「売上を伸ばしたい」→「3ヶ月で月商150万円」のように、具体的で測れるKPI（重要指標）を設計します。

## 「KPI」って何？

- **KGI**（最終目標）＝ 最終的に達成したいゴール（例：年間売上1,000万円）
- **KPI**（重要指標）＝ ゴールに向かって順調かどうかを測る数字（例：月間新規問い合わせ数30件）

KPIは「今日の行動がゴールに繋がっているか」を確認する道しるべです。

## こんなときに使ってください

- チームの目標を数値化したい
- 「がんばる」じゃなくて「何をどこまでやるか」を決めたい
- 目標の進捗を定期的にチェックする仕組みを作りたい

## 入力例
```
フリーランスとして月収30万円を安定させたい。今は月15〜20万円くらい。
```

## 良いKPIの5条件（SMART）

| 条件 | 意味 | NG例 | OK例 |
|------|------|------|------|
| Specific（具体的） | 何を？ | がんばる | 月間新規提案数 |
| Measurable（測れる） | 数字で測れる？ | たくさん | 10件 |
| Achievable（達成可能） | 現実的？ | 月商1億 | 月商30万 |
| Relevant（関連性） | 目標と繋がってる？ | SNSフォロワー数 | 問い合わせ件数 |
| Time-bound（期限付き） | いつまで？ | いつか | 3ヶ月以内 |

# テーマ31：SWOT分析アシスタント

## このツールでできること

ビジネスの「強み・弱み・チャンス・ピンチ」を4つの視点で整理します。新しいことを始めるとき、競合との差を考えるとき、戦略を立てるときに役立ちます。

## 「SWOT」って何？

| 頭文字 | 意味 | 自分で変えられる？ |
|--------|------|------------------|
| S（Strengths） | 強み | はい（内部） |
| W（Weaknesses） | 弱み | はい（内部） |
| O（Opportunities） | チャンス・追い風 | いいえ（外部） |
| T（Threats） | ピンチ・逆風 | いいえ（外部） |

## こんなときに使ってください

- 新しいサービスを始める前に現状を整理したい
- ライバルと比べて自分の立ち位置を確認したい
- 経営会議で戦略を提案するための材料がほしい

## SWOTの活用法

分析した後が大事です。4つを掛け合わせて戦略を導きます。

| | チャンス（O） | ピンチ（T） |
|--|-------------|------------|
| **強み（S）** | 強みでチャンスを掴む（攻め） | 強みでピンチをしのぐ（差別化） |
| **弱み（W）** | 弱みを補ってチャンスを活かす（改善） | 最悪を避ける（守り） |

# テーマ32：アンケート作成アシスタント

## このツールでできること

アンケートの設問設計と、集まった回答の分析をサポートします。「何を聞けば知りたいことが分かるか」を一緒に考えます。

## こんなときに使ってください

- 顧客満足度アンケートを作りたい
- 社内の満足度調査を設計したい
- イベント後のフィードバックを集めたい
- アンケート結果を分析してレポートにしたい

## 良いアンケートのコツ

| コツ | 理由 |
|------|------|
| 質問は10問以内 | 多すぎると回答率が下がる |
| 選択式を中心に | 自由記述だけだと分析が大変 |
| 1問で聞くことは1つ | 「AとBについてどう思いますか？」はNG |
| 回答時間は3〜5分以内 | それ以上は離脱する |
| 最後に自由記述を1つ | 想定外の声を拾える |

## 回答形式の選び方

| 知りたいこと | おすすめの形式 |
|------------|-------------|
| 1つだけ選んでほしい | 単一選択（ラジオボタン） |
| 複数選んでOK | 複数選択（チェックボックス） |
| 満足度を測りたい | 5段階評価（1:不満〜5:満足） |
| 自由に書いてほしい | 自由記述（テキスト欄） |
| 順番をつけてほしい | ランキング形式 |
