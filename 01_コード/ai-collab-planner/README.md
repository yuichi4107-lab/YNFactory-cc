# AI共同開発プランナー v0.14

Claude Code CLIとCodex CLIを使い、依頼内容から「要件定義書・実装プラン」を作成するWindows向けツールです。

**このツールは、2つの案のどちらが優れているかを選ぶツールではありません。立場の違う2つの案を作らせ、議論させ、両方の良いところを1つの要件定義へまとめるツールです。** どうしても両立しないトレードオフだけが「要判断」として残り、人間の判断へ回ります。

この版は要件定義までで必ず停止します。コードの実装、既存コードの変更、テスト実行、Git操作、デプロイは行いません。

## v0.14で変わったこと

v0.13までは、AIが順番に作業を渡していく一直線の流れで、議論が成立していませんでした。案を書いたAIは、自分の案が何を指摘されたか知る機会すらありませんでした。

v0.14では次を追加しました。

- **分岐点の抽出** … 依頼文だけでは決まらず、決めないと先へ進めない点をAIが洗い出します。後から覆すコストが大きい順に並べます
- **立場の設定** … 分岐点をもとに、AIが非対称な2つの立場を作ります。固定の対立軸は使いません（依頼によって的外れになるため）。立場ごとに「捨てるもの」を必ず書かせ、組み合わせる価値のある差を作ります
- **人間の承認** … 分岐点と立場を画面に出し、この内容で議論してよいか1回だけ確認します。ここで軸が間違っていれば後の工程がすべて無駄になるため、ここで止めます
- **相互検討ラウンド** … 各案の担当が、争点ごとに「取り込む／両立させる／両立しない」を選んで応答します。相手を論破するのではなく、相手の案から取り込める要素を探すのが任務です
- **調停** … 中立のAIが争点ごとに統合案を作り、「立場Aから採った要素」「立場Bから採った要素」の両方を埋めます。片方しか書けないものは統合ではなく選別なので、統合済みにできません
- **収束するまで繰り返す** … 未整理の争点がなくなるまでラウンドを回します。上限に達するか、議論が停滞したら打ち切ります

「要判断」（実在するトレードオフ）が残った状態は失敗ではありません。それが人間へ渡すべき成果です。

## 作成する内容

- 背景と目的
- 想定利用者と利用場面
- 現状と解決する課題
- 対象範囲と対象外
- 機能要件と非機能要件
- 画面、操作、業務の流れ
- データと外部サービス連携
- 完了条件と受入基準
- 制約、リスク、依存関係
- 未決事項と確認質問
- 段階的な実装プランとテスト方針
- 工程ごとのAIモデル選定

AIモデル選定では、Claude系かGPT系か、具体的なモデル、選定理由、代替候補を表にまとめます。

## v0.13で修正したこと

- 新しく作成したプロジェクトやGit未設定フォルダでも、Codexが要件定義を実行できるよう修正
- Codex CLIへ`--skip-git-repo-check`を指定
- Git確認を省略しても、Codexのサンドボックスは`read-only`のまま維持
- 「Not inside a trusted directory」で第二要件定義案が停止する問題を解消

## v0.12で変更したこと

- 統合済みの要件定義書を、別のAIが読み取り専用で最終チェック
- 依頼との一致、要件の抜け・矛盾、受入基準、未決事項、AIモデル選定を再確認
- 問題があれば最終チェック担当が本文へ反映し、修正済みの全文を完成版として保存
- 最終チェックでも実装やコード変更は行わない

## v0.11で変更したこと

- 計画後の自動実装を廃止
- 全AI呼び出しを読み取り専用に固定
- 最終成果物を要件定義書と実装プランへ変更
- 実装工程ごとのClaude系／GPT系の選定を必須化
- 実装候補モデルは計画に記載するだけで、実際には呼び出さない
- Gitリポジトリでなくても同じく要件定義まで実行可能

## v0.10までの主な改善

- `05_プロジェクト/<プロジェクト名>/`へ資料を保存
- 長い依頼文から短いプロジェクト名を自動提案
- Google Drive上の旧記録移行で`desktop.ini`等を安全に除外
- 移行失敗時も元データを変更せず、移行を飛ばして継続可能
- ローカルWhisperによる高精度日本語音声入力
- 通常精度の`small`と精度優先の`medium`を選択可能
- Whisperが使えない場合はWindows標準音声認識へ切り替え

## 必要なもの

- Windows 10または11
- Python 3.11以上
- Codex CLI（使用する構成にCodexが含まれる場合）
- Claude Code CLI（使用する構成にClaudeが含まれる場合）
- 各CLIへのログイン

高精度音声版には、マイク、初回セットアップ時のインターネット接続、Whisperモデル用の空き容量も必要です。

## 最初の準備

1. ZIPを新しいフォルダへ展開します。
2. `AIプランナー確認.bat`をダブルクリックします。
3. CodexとClaudeの検出・ログイン状態を確認します。
4. 音声版を使う場合は`音声認識を強化する.bat`を実行します。
5. 精度をさらに優先する場合は`音声認識高精度モデル準備.bat`も実行します。

## 起動方法

キーボード入力:

`AIプランナー起動.bat`

標準の高精度音声入力:

`AIプランナー音声起動.bat`

精度優先の音声入力:

`AIプランナー音声高精度起動.bat`

## 実行の流れ

1. 親フォルダを選択します。設定済みの場合は`G:\マイドライブ\YNFactory-cc`を使用します。
2. やりたいことを入力または音声で話します。
3. 提案されたプロジェクト名を確認します。
4. 作業レベルと、要件定義に使うAI構成を確認します。
5. AIが分岐点を洗い出し、2つの立場を設定します。
6. **画面に分岐点と立場が表示されます。この内容で議論を始めてよいか答えます。**
7. 立場Aの案と立場Bの案を、互いに見せずに作らせます。
8. 中立のAIが、2案の違いを争点表に整理します。
9. 各案の担当が争点ごとに応答し、中立のAIが統合案を作ります。決着するまで繰り返します。
10. 最終統合AIが要件定義書と実装プランにまとめます。
11. 別のAIが、抜け・矛盾・受入基準・モデル選定・統合の実質を最終チェックします。
12. 修正済みの完成版を保存し、実装せずに終了します。

分岐点がないと判定された場合と、作業レベルが「軽い・定型」の場合は、議論を行わず案→統合→最終チェックの3工程で終わります。

## 議論の終わり方

議論は次のいずれかで終わります。画面に理由が表示されます。

| 終了理由 | 意味 |
|---|---|
| 統合完了 | 未整理の争点がなくなった。最も望ましい終わり方 |
| 停滞 | 調停役が、これ以上議論しても進展しないと判断した |
| 停滞（進展なし） | 未整理の争点が前のラウンドから減らなかった |
| 上限 | 上限ラウンドに達した |

統合完了以外で終わった場合、残った争点は「要判断」として要件定義書の12章・14章に載ります。

## 所要時間の目安

議論を入れたぶん、v0.13より時間がかかります。AI呼び出しの回数は次のとおりです。

| 作業レベル | 最小 | 最大 | v0.13 |
|---|---|---|---|
| 軽い・定型 | 3回 | 3回 | 3回 |
| 通常 | 9回 | 12回 | 5回 |
| 複雑 | 9回 | 15回 | 5回 |
| 長期・高リスク | 10回 | 16回 | 5回 |

1回の呼び出しに数十秒から数分かかります。**最大回数まで待てるときにだけ「複雑」以上を選んでください。** 急ぐ場合は「軽い・定型」を選べば、v0.13と同じ速さで終わります。

上限ラウンド数は`config.toml`の`max_debate_rounds`で変更できます（初期値は通常2、複雑と長期3）。

主なファイル:

- `PLAN.md`: 旧版や外部ツールとの互換用。内容は`REQUIREMENTS.md`と同じ

議論の中身を追いたいときは`round1/mediation.md`を見てください。争点ごとに「立場Aから採った要素」「立場Bから採った要素」が並んでいます。

## モデル構成

`config.toml`で作業レベル別に設定します。

| 作業レベル | 分岐点抽出・立場設定 | 立場Aの案 | 立場Bの案 | 争点整理・調停 | 最終チェック | 上限ラウンド |
|---|---|---|---|---|---|---|
| 軽い・定型 | 行わない | GPT-5.6 Luna | 行わない | 行わない | Claude Sonnet | 0 |
| 通常 | Claude Sonnet | GPT-5.6 Terra | Claude Sonnet | Claude Sonnet | Claude Sonnet | 2 |
| 複雑 | Claude Opus | GPT-5.6 Sol | Claude Opus | Claude Opus | Claude Opus | 3 |
| 長期・高リスク | Claude Opus＋GPT-5.6 Solで補完 | Claude Fable | GPT-5.6 Sol | Claude Opus | Claude Opus | 3 |

「長期・高リスク」だけ、分岐点の抜けを別会社のモデルがもう一度確認します。抽出役1体の見落としが後の工程すべてを規定してしまうためです。

最終的なモデル割り当ては、依頼内容を比較したAIが工程別に選び直して`REQUIREMENTS.md`へ記載します。

## 安全設計

- AI呼び出しはすべて読み取り専用
- 実装担当モデルを実行しない
- 既存コードを変更しない
- Git commit、push、デプロイを行わない
- 要件定義書の必須見出しが欠けていたら停止
- AIがエラー文を成果物として返した場合は停止
- **議論は必ず有限回で終わる。** 上限ラウンドはプログラム側で強制するため、AIが「続行」と言い続けても止まります
- **調停役の「継続判定」「未整理件数」が読み取れない形式なら停止。** 黙って議論を続けることはありません
- **立場に「捨てるもの」が書かれていなければ停止。** 差のない2案を作っても、統合する意味がないためです
- **争点表の争点が最終文書から消えていたら停止。** 議論した論点が握りつぶされないようにします

## セキュリティ

このツールは「フォルダを読む → AIへ渡す → ファイルへ書く → 別のAIへ渡す」構造なので、対象フォルダの中身が多くの工程を経由します。次の安全装置を入れています。

### 認証情報が混ざったら止まります

AIの出力にAPIキー・トークン・秘密鍵らしき記述が見つかると、**その場で停止し、要件定義書を一切書きません。** `.env` の中身が要件定義書へ転記され、Google DriveやGitHubへ流れるのを防ぐためです。

止まったときの画面には、**検出した値そのものは表示しません**（画面表示やログ自体が漏洩経路になるため）。「OpenAI APIキー（12行目）」のように種類と位置だけが出ます。

対処: 対象フォルダから認証情報ファイルを外すか、AIが読まない場所へ移してから実行し直してください。

### AIへの指示文が混ざったら警告します

対象フォルダのファイルに「これまでの指示を無視して〜」のような文が仕込まれていると、それを読んだAIが誘導される可能性があります。分岐点抽出の結果にそうした文を見つけると、**承認画面の先頭に警告を出します。**

心当たりがなければ承認せず中止して、対象フォルダの中身を確認してください。この場合は自動停止しません（誤検知でツールが使えなくなるため）。ただし警告が出たときは、分岐点がなくても必ず承認を求めます。

**最終的な要件定義書に指示文が残っていた場合だけは停止します。** `AGENTS.md` と `CLAUDE.md` が「作業前に `01_計画/REQUIREMENTS.md` を読むこと」と定めているため、ここに指示文が残ると、以後のAIセッションが毎回それを読んでしまうからです。

### 調停役の数字を鵜呑みにしません

議論を続けるか終えるかは、調停役が出す「未整理件数」で決まります。この数字を自己申告のまま信じると、誘導によって議論を早期終了させ、「統合済みに見える要件定義書」を作らせることができてしまいます。

そこで、申告された件数と、統合案の表から実際に数えた件数を**突き合わせます。合わなければ停止します。**

### 設定ファイルの制限

`config.toml` の `codex` / `claude` は実行するコマンド名としてそのまま使われます。パス区切り・空白・記号を含む値は読み込み時に拒否します。

### 読み取り専用の担保

- Codexには `--sandbox read-only` を必ず渡します
- Claudeには `--permission-mode plan` と `--tools Read,Glob,Grep` と `--strict-mcp-config` を必ず渡します
- サンドボックスを外すフラグが混入していないことをテストで固定しています

### このツールで守れないこと

- 対象フォルダのファイルそのものの改ざん検知
- Codex CLI / Claude Code CLI 自体の脆弱性
- Google Drive / GitHub 側のアクセス制御
- このPCがすでに侵害されている場合（`config.toml` も `.py` も書き換えられるため、ツール単体では守れません）
- Google Driveの旧記録は、コピー検証後も元データを自動削除しない

## 音声入力について

v0.13は1回ずつ音声を入力する方式です。話し始めを検出し、話し終わった後の無音で自動停止します。常時待ち受けや呼びかけ起動には対応していません。
