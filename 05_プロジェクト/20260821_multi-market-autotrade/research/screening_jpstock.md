## 0. 本調査で新たに確定した事実（すべて一次ソース）

前提の一部を**上書きする重大な発見が4件**ある。以下は基準適用の土台になる。

### 0-1. 【重大・案Bを否定】立花証券e支店API は毎回のログインで人手の電話認証が必須

> 「e支店・APIもログイン要求時は、APIログイン認証専用電話番号へ電話していただき電話認証が必須となります。**APIでもログインする度に毎回電話認証が必要となります**」
> 「ログインで取得した仮想URLは、ログアウトや多重ログインをしない限り、**夜間の閉局まで有効**です」
> — https://www.e-shiten.jp/api/20250708.html （2025-07-08付、公式）

- 仮想URLは夜間閉局で失効する。したがって **毎営業日の朝に1回、人間が電話をかけないとAPIが使えない**（年間およそ245回）。
- 本プロジェクトの確定前提は「**完全自動発注（人手を介さない）**」であり、**案Bはこの前提を構造的に満たさない**。
- `execution_venues.md` が「2026-03-10付の特別な通知は未確認」としていた宿題への回答でもある。`00_intake_sheet.md` の「現時点の推奨はBまたはC」のうち **Bは消える**。

### 0-2. 【重大・案Aの前提が揺らぐ】kabuステーションも常時起動＋ログインが必要、二要素認証は未確認

- 公式FAQ（一次）: 「kabuステーション®APIをご利用になる際は、**常にkabuステーション®を起動しておく必要があります**」「**同一IPからのリクエストのみを受け入れます。そのため、同一PCでご使用ください**」 — https://kabucom.github.io/kabusapi/ptal/faq.html
- 公式手順（一次）: 利用条件は「ProfessionalプランかPremiumプランである必要があります」 — https://kabucom.github.io/kabusapi/ptal/howto.html
- **二要素認証**: 公式FAQ・公式手順には記載が**ない（＝未確認）**。一方、複数の個人ブログ（二次情報）が「2024年5月から二要素認証が必須になり完全自動ログインは困難」「Gmail APIで認証コードを自動取得するハックが要る」と記述している。
- 判定: **案Aの「完全自動発注」は公式に保証されていない**。非公式ハックに依存する構成は FP-009（外部APIの仕様変更でクライアントが全損）を再現する。

### 0-3. 【好材料】三菱UFJ eスマート証券の国内株手数料は 2026-05-18 から 0円（SOR注文条件）。API からもSOR発注可

### 1-1. JP-28 の S4 判定（数値で示す）

足切りで唯一「コストの計算だけで落ちた」戦略なので根拠を明示する。

- 対象を最も条件の良い 1306（純資産34兆円・最も流動性が高いTOPIX ETF）とする。
- 実測: 現在値 **424.1円**、呼値 **0.1円** → **1ティック = 0.0236%**。
- 引成で買い・寄成で売る往復で、片道1ティック不利に約定すると **往復 0.047%**。
- 毎営業日往復 → 年間約250往復 → **年 11.8%** のコスト。
- BACKTEST_PROTOCOL §5.2 のコスト2.0倍感度 → **年 23.6%**。
- カタログ自身が「1回あたり期待値が数bp」と記載している。仮に1回 +5bp（年12.5%）でも、コスト1.0倍でほぼ相殺、**2.0倍で確実に赤字**。
- 手数料が0円になった（§0-3）ことは救いにならない。効いているのはスプレッド/スリッページであり、手数料ではない。
- **→ S4 ×。** 併せて、始値が必要なため無料NAV系列では検証できず、年39,600円が乗る点も不利。

### 4-2. 推奨: **案C**

**決め手となった数値と事実（優先順）**

1. **案Bは確定前提を満たさない（一次ソース）。**
   立花証券e支店API は「ログインする度に毎回電話認証が必要」と公式に明記し、セッションは夜間閉局で失効する。**毎営業日1回、人間が電話をかける必要があり、年間約245回。** 「完全自動発注（人手を介さない）」という前提の下では、案Bは検討の土俵に乗らない。
   → https://www.e-shiten.jp/api/20250708.html

2. **案Aは固定費が期待リターンを完全に食う。**
   固定費 **年16,700〜36,000円** に対し、期待リターンは **年0〜12,000円**。
   - 最良ケース（VPS最安16,700円・リターン上限12,000円）でも **-4,700円**。
   - 中央値（VPS 26,000円・リターン6,000円）で **-20,000円**。
   - **固定費率5.6〜12.0% に対し、期待リターンは0〜4%。構造的に赤字。**
   - 損益分岐に必要なリターンは **年5.6〜12.0%**。JP-23 で年12%を出すには、公知のカレンダーアノマリーから月1%の超過リターンを取り続ける必要があり、一次ソースの裏付けがない。
   - さらに、日本株30万円のうち**保有しているのは年約60営業日（24%）だけ**なので、残り76%は現金として遊ぶ。実効的な資金効率で見れば固定費率はさらに4倍重い。

3. **案Aは完全自動発注が公式に保証されていない。**
   公式FAQは「常にkabuステーションを起動しておく必要」「同一IPからのリクエストのみ・同一PC」と定めるのみで、二要素認証への言及がない（未確認）。二次情報が示す Gmail API による認証コード自動取得は非公式であり、**FP-009（外部APIの仕様変更でクライアントが全損）を最も踏みやすい構成**。50万円規模の運用で、この不確実性を抱えた2台目のVPSを立てる合理性がない。

4. **通過6件のうち、プロトコル上 Green になりうるのは1件だけ。**
   C4（全期間100トレード以上・OOS30回以上）を満たすのは JP-23 のみ。**残り5件は「検証しても統計的に何も言えない」状態で実弾に出すことになり、FP-012（実装完了と収益が出るの混同）の再現になる。**

5. **フォワードゲートを通すのに2.5年かかる。**
   BACKTEST_PROTOCOL §7 は「最低3か月**かつ**取引回数30回以上（どちらも満たすまで延長）」を要求する。JP-23 は年12トレードなので、**30回に達するまで2年6か月**。つまりプロトコルを守る限り、日本株の実弾投入は2029年になる。**この期間、案Aなら固定費だけが年16,700〜36,000円流出し続ける。** 実弾に出さない案Cなら流出はゼロ。

6. **税制上、日本株を持つことによる横断的なメリットがない。**
   日本株の損益は暗号資産ともFXとも**一切通算できない**（措法37の11 と 措法41の14 は別制度）。3市場に分けることによる税務上の利点はなく、むしろ申告区分が1つ増える。

**→ 推奨は案C。日本株は実弾から外し、JP-23（および参考としてJP-11）のシグナル生成とペーパー検証のみを行う。50万円は暗号資産・FXに集中する。**

### 4-3. 案Cの具体設計

1. **検証（Phase 2〜3、費用0円）**
   - 1306 の無料NAV系列（2001-07-11〜、6,167営業日）で JP-23 を BACKTEST_PROTOCOL どおり検証する。IS 60% / OOS 25% / HOLDOUT 15%、探索N≤9、C1〜C6を全て記録。
   - C5（複数銘柄での再現）は 1306 / 1321 / 1475 の3本で確認する（1475 のヒストリカル入手性は要確認）。
   - 執行は**引成（終値）**に固定する。NAV系列には始値がないので、寄付執行を前提にした設計は採用しない。
2. **ペーパー運用（Phase 4〜、費用0円）**
   - 既存のLinux VPS上でシグナルだけを生成し、約定は仮想。3か月かつ30トレードに達するまで継続（＝2.5年）。
   - シグナル一致率・想定スリッページ・障害の記録は暗号資産/FXと同じ基盤に載せる（実装コストの増分はほぼゼロ）。
3. **資金配分**
   - 暗号資産 25万円 / FX 25万円 / 日本株 0円。日本株に割いていた30万円を2市場に回すことで、1銘柄あたりの資金が厚くなり、最小ロット制約が緩む。
4. **案A/Bへ移行する条件（事前に数値で決めておく＝FP-013対策）**
   - **M1**: 運用資金合計が **150万円**を超える（Windows VPS 年36,000円が資金の2.4%以下になる）。
   - **M2**: 三菱UFJ eスマート証券が、二要素認証なし、または公式にサポートされた自動ログイン手段でのAPI利用を明示する。
   - **M3**: 立花証券が電話認証の自動化手段を公式に提供する。
   - **M4**: JP-23 のペーパー検証が Green かつ 30トレード以上で、実現年率がバックテストの下限側95%区間に収まっている。
   - **M1 かつ M4**、加えて **M2 または M3** が揃ったときにのみ再検討する。それ以外の理由（「日本株もやりたい」「良さそうな戦略を見つけた」）では移行しない。

## 5. ETFという選択肢の評価

### 5-1. 単元制約はETFで事実上消える

| 銘柄 | 現在値（2026-08-21実測） | 売買単位 | 最低投資金額 | 30万円で買える単元数 | 粒度 |
|---|---:|---:|---:|---:|---:|
| **1306** NF TOPIX連動型 | 424.1円 | 10口 | **4,241円** | **70単元** | **1.4%刻み** |
| **1475** iシェアーズ・コアTOPIX | 418.0円 | 10口 | **4,180円** | **71単元** | **1.4%刻み** |
| 1321 NF 日経225連動型 | 68,330円 | 1口 | 68,330円 | 4単元 | 25%刻み |
| 1570 NF 日経レバレッジ | 69,060円 | 1口 | 69,060円 | 4単元 | 25%刻み |
| （参考）個別株 | 株価3,000円 | 100株 | 300,000円 | 1銘柄 | 100%刻み |

- **1306 / 1475 なら30万円で70単元。分割エントリー・部分利確・ポジションサイジングがすべて可能になり、「30万円では単元株2〜4銘柄しか持てない」という制約は実質的に解消する。**
- 1306 は 2026-04-01 に受益権分割を実施しており、それ以前は1口約4,200円だった。**この分割によって初めて小資金でも扱えるようになった**点は重要な変化。
- **1321 / 1570 は使うべきでない。** 1口68,000円台では30万円が4口にしかならず、粒度25%刻みで部分執行ができない。日経225連動が必要なら 1329（iシェアーズ・コア 日経225）等の低位銘柄を探すべき（本調査では未確認）。

### 5-2. データ制約はETFで大きく緩む（が、消えはしない）

| 項目 | 個別株の場合 | ETF（1306/1321/1570）の場合 |
|---|---|---|
| 10年日足の入手 | J-Quants Standard **年39,600円**（恒久。解約時はデータ廃棄義務あり／§0-5） | **運用会社の無料CSVで25年分（¥0）** |
| 配当込みトータルリターン | J-Quants Premium **年198,000円** | **無料CSVに「分配金再投資後基準価額」が含まれる（¥0）** |
| 分割・併合調整 | J-Quants側で調整（遡及再計算されるためスナップショット保存が必要） | **CSV側で調整済みと明記** |
| 生存バイアス | 日付ごとにマスタと株価を総なめして再構成（Standard必須）。上場廃止イベントマスタは法人向けのみ | **該当しない**（ETFは1本、指数側で構成銘柄が入替わる。ただしB4再構成バイアスは指数提供者側で処理済み） |
| **始値・高値・安値** | J-Quants 株価四本値で取得可（Standard） | **取れない。終値相当の1本値のみ** ← **最大の限界** |
| 分足・板 | アドオン年66,000円・過去2年のみ | **同じく不可** |

**→ ETFにすることで、日本株のデータ費用は 年39,600円 → ¥0 になる。これがETF案の最大の価値であり、S4のハードル13.2%を丸ごと消す。**
**→ 代償は「始値がない」こと。寄付執行・日中執行・ギャップ・ストップ高安を前提とする戦略は依然として検証できない。執行を引成に統一する設計変更が必須。**

### 5-3. 分散はETFに内包されるが、収益源は1つに縮む

- 1306 は TOPIX 約1,600銘柄に連動する。**個別銘柄リスクはゼロ**（倒産・不祥事・決算ショックの直撃がない）。「2〜4銘柄しか持てないので個別銘柄リスクが分散されない」という S8 の懸念は、ETFで完全に解消する。
- ただし**日本株の収益源が「市場βとそのタイミング」だけに縮む**。カタログのファクター系7件が狙っていたクロスセクショナルなアルファは、ETFでは一切取れない。
- 暗号資産・FXとの相関は低く、ポートフォリオ全体としての分散価値は残る。ただし §4 のとおり、その分散価値のために年16,700〜36,000円（案A）を払う合理性がない。

### 5-4. 規制面（S7）もETFで軽くなる

- ロングオンリーのETF戦略には**空売り価格規制が一切かからない**。JP-30などが抱えていた「発動履歴がJ-Quantsで取れずバックテストで再現できない」という問題（FP-003型）が構造的に発生しない。
- 値幅制限: ETFの制限値幅は基準価格に応じて設定され、個別株ほど張り付きにくい。ただし 2024-08-05 のような日には 1570 等のレバレッジETFが実質的に約定困難になった実績があり、**レバレッジ型は採用しない**のが安全。
- 税制は個別株と同一（申告分離20.315%、3年繰越、暗号資産・FXとは通算不可）。特定口座（源泉徴収あり）で申告事務はほぼ消える。

### 5-5. カタログ内でETF執行が可能な戦略

**対象にETF/指数を明記している10件**: JP-08, JP-09, JP-11, JP-13, JP-23, JP-25, JP-26, JP-27, JP-28, JP-30
（このうちJP-03はETF代替が示唆されているが「既製ETFの買い持ち」であり戦略ではない）

**そのうち足切りを通過した6件**: JP-08, JP-09, JP-11, JP-13, JP-23, JP-25
**そのうちC4（取引回数）を満たす2件**: **JP-23, JP-11**
**そのうち信頼度A/Bで一次ソースがある1件**: **JP-23**

**→ ETFに切り替えることで「単元制約」と「データ費用」は解決するが、それでも残るのは JP-23 一本である。ETFは制約を解いても、エビデンスと取引回数の不足までは解かない。**
