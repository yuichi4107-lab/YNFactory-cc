# バックテストプロトコル v1.0

- 作成日: 2026-08-21
- 適用範囲: 本プロジェクトで検討する全戦略（仮想通貨 / FX / 日本株）
- 位置づけ: **戦略の採否を決める唯一の手続き。** ここに書かれた手順を通らなかった戦略は、どれだけ理屈が良くても採用しない
- 根拠: `harness/failure_patterns.md` の FP-001〜004、FP-011、FP-012

> 旧システムが4か月で3回戦略を変え、どれも実弾検証に至らなかった最大の理由は、
> 「良い結果」と「信用できる結果」を区別する手続きが無かったことにある。
> このプロトコルは**戦略を落とすための仕組み**であり、通すための仕組みではない。

---

## 0. 大原則

| # | 原則 | 理由 |
|---|---|---|
| P1 | **探索したパラメータ数を必ず記録する** | 792通り試して1つ良いものが出るのは偶然の範囲。試行回数を隠すと、偶然と実力が区別できなくなる（FP-002） |
| P2 | **最終判定に使うデータには、判定の直前まで一度も触れない** | 一度でも見たデータは検証用として死ぬ |
| P3 | **コストは楽観側に丸めない** | 小資金ではコストが優位性を食い切る。不明なら悪い方の数字を使う |
| P4 | **検証できない戦略は採用しない** | 板情報が必要なら板データを用意する。無いなら戦略ごと落とす（FP-003） |
| P5 | **バックテストの合格は「実装してよい」の許可であって、「儲かる」の証明ではない** | フォワード検証を別ゲートとして必ず通す（FP-012） |

## 1. データ要件

### 1.1 最低検証期間と、必ず含めるべき相場

| 市場 | 最低期間 | 必ず含める局面 |
|---|---|---|
| 仮想通貨 | 5年以上（2021年の高値・2022年の下落・2023年の低ボラ局面を含む） | 強気相場 / 暴落（2022 LUNA・FTX） / 横ばい |
| FX | 10年以上 | 低ボラ期 / 2022年の急激な円安 / 中銀政策転換期 |
| 日本株 | 10年以上 | 2018年末・2020年3月・2024年8月の急落を含む |

- **旧システムの失敗**: 仮想通貨は「上昇相場優位期間」のみ、日本株は無料プランの2年のみで判定していた（FP-001、FP-004）
- 無料データで上記期間が確保できない場合、**期間を妥協するのではなく、有料データのコストを Phase 1c で見積もる**。それも無理なら、その市場の該当戦略は不採用にする

### 1.2 データ品質チェック（全戦略共通・実施必須）

- [ ] 欠損バーの割合と分布を出す（特定期間に集中していないか）
- [ ] 価格の異常値（前バー比で極端な飛び）を検出し、実際のイベントか配信エラーかを判定する
- [ ] 分割・併合・配当の調整が正しいか（日本株）
- [ ] 上場廃止・取引停止銘柄が母集団に含まれているか（**生存バイアス**）
- [ ] 取引所の停止・メンテナンス時間帯が反映されているか（仮想通貨）
- [ ] タイムゾーンとバーの確定タイミング（そのバーは実際に何時に確定するか）

## 2. バイアス排除チェックリスト

各戦略の検証コードに対し、以下を1件ずつ確認して記録する。1つでも未確認があれば結果を採用しない。

| # | バイアス | 具体的な確認事項 |
|---|---|---|
| B1 | **先読み（look-ahead）** | シグナル計算に、その時点で確定していない値を使っていないか。終値でシグナルを出して同じ終値で約定していないか |
| B2 | **生存バイアス** | 現在存在する銘柄・通貨だけで母集団を作っていないか。当時の上場銘柄で組んでいるか |
| B3 | **データスヌーピング** | 同じデータで何回パラメータを試したか。**試行回数を記録し、§4の補正を適用したか** |
| B4 | **再構成バイアス** | 指数構成銘柄などを「現在の構成」で遡って適用していないか |
| B5 | **約定の楽観** | 指値が「板にあれば必ず約定する」前提になっていないか。ストップ高・ストップ安・値幅制限で約定不能な状況を再現しているか（日本株） |
| B6 | **ギャップの扱い** | 損切りラインを飛び越えるギャップで、損切り価格ちょうどで約定させていないか（**寄り値で約定させる**） |
| B7 | **未来の知識** | 「この銘柄は後で大化けした」という知識で母集団を選んでいないか |

## 3. 分割設計（In-Sample / Out-of-Sample）

### 3.1 三分割を必須とする

```
[----------- 開発期間 IS 60% -----------][--- 検証 OOS 25% ---][-- 封印 HOLDOUT 15% --]
        パラメータ探索はここだけ            合否の一次判定           最終確認・1回のみ
```

- **HOLDOUT は Phase 2 の SRS 完成まで一切開かない**。開くのは実装直前の1回だけ。結果が悪ければ戦略を落とす（パラメータを再調整して開き直すことを禁止する）
- 分割は時系列順に行う。ランダム分割は時系列データでは無効

### 3.2 ウォークフォワード検証（必須）

- 学習窓を移動させながら、「直前N期間で最適化 → 次のM期間で運用」を繰り返す
- 推奨: 学習窓 2年 / 運用窓 3か月 / ローリング
- **判定**: 各運用窓の成績のばらつきを見る。全期間合計が黒字でも、**黒字の運用窓が半分未満なら不合格**（1回の大当たりで全体が黒字になっているだけ）

### 3.3 パージとエンバーゴ

- 学習期間と検証期間の境界に、**保有期間と同じ長さの空白（エンバーゴ）**を置く。保有中のポジションが期間をまたぐことによる情報漏れを防ぐ

## 4. 過剰最適化の統計的な検定

| # | 検定 | 合格ライン | 備考 |
|---|---|---|---|
| C1 | **試行回数の記録** | 必須 | 探索したパラメータ組合せ数 N を記録 |
| C2 | **Deflated Sharpe Ratio** | DSR > 0 かつ p < 0.05 | 試行回数 N を織り込んでシャープを割り引く。**N=792 のような総当たりでは通常のシャープはほぼ無意味になる** |
| C3 | **パラメータ感度の平坦性** | 最良パラメータの近傍±20%で成績が半分以下に落ちないこと | 山の頂点が針のように尖っている＝偶然。なだらかな高原＝本物の可能性 |
| C4 | **最低取引回数** | 全期間で100回以上、かつ OOS 単独で30回以上 | 回数が少ないと統計的に何も言えない |
| C5 | **複数銘柄での再現** | 対象が複数ある戦略は、**過半数の銘柄で同方向の結果**が出ること | 4通貨中1通貨だけ突出は不合格（FP-002） |
| C6 | **開始日ずらし** | 開始日を1週間ずつずらした20通りで、成績の符号が反転しないこと | 特定の開始日への依存を検出 |

## 5. コストモデル（楽観側に丸めない）

### 5.1 市場別の最低見積り

| 市場 | 手数料 | スプレッド/スリッページ | その他 |
|---|---|---|---|
| 仮想通貨（現物・板） | 往復で取引所の実料率（**販売所は使わない**。実質0.5%かかる／FP-007） | 成行は最良気配から最低0.1%滑る前提 | 建玉を持ち越すデリバティブは資金調達率を反映 |
| FX | 業者の提示スプレッドの**1.5倍**を基準 | 指標発表時は3倍に拡大する想定を別途検証 | スワップは実績値で日次計上。マイナススワップを無視しない |
| 日本株 | 証券会社の実料率（単元未満株は**別料率**であることに注意） | 成行は1ティック不利で約定する前提 | 貸株料・逆日歩（信用売り時）、受渡日の資金拘束 |

### 5.2 コスト感度分析（必須）

- コストを **1.0倍 / 1.5倍 / 2.0倍** にした3通りで再計算する
- **2.0倍で赤字に転落する戦略は不採用**。小資金では実効コストが想定より重くなるため、この余裕がない戦略は現実に耐えない

### 5.3 税の扱い

- バックテストの成績は**税引前**で記録し、別途、税引後の概算を併記する
- 課税区分は市場ごとに異なる（暗号資産・FX・株式）。Phase 1c で国税庁の一次ソースを確認する

## 6. 合否判定（RYG）

判定は **OOS 期間の数値**で行う（IS の数値は判定に使わない）。

| 判定 | 条件 |
|---|---|
| **Green**（実装候補として採用可） | §2の全チェック済 ／ §4 C1〜C6 全合格 ／ コスト2.0倍でも黒字 ／ OOS の最大DD ≤ 30% ／ ウォークフォワードの黒字窓が過半数 |
| **Yellow**（PoC・ペーパーのみ、実弾禁止） | 上記のうち1〜2項目が未達だが、原因が特定できており追加検証で解消しうる |
| **Red**（不採用） | 3項目以上未達、または §2 のバイアスが1つでも未解消、またはコスト2.0倍で赤字 |

- **Yellow を「ほぼGreen」と読み替えることを禁止する**（nagame-dev 黄金ルール4）
- Red を出すことは成功である。旧システムは Red を出すべき戦略に実装を進めた（FP-012）

## 7. フォワード（ペーパートレード）ゲート

バックテスト Green は、実弾投入の許可ではない。次のゲートを別に設ける。

| 項目 | 基準 |
|---|---|
| 期間 | **最低3か月**、かつ取引回数30回以上（どちらも満たすまで延長） |
| 判定 | 実現した成績が、バックテストの期待値の**下限側95%区間に収まっていること** |
| シグナル一致率 | ペーパー環境と検証環境で、同一時点のシグナルが**98%以上一致**すること（不一致は実装バグの証拠） |
| 約定品質 | 実際のスリッページが §5 の見積り以内に収まっていること |
| 障害 | 期間中に無停止で動き続けたこと。停止した場合は原因を解消して期間をリセット |

## 8. 稼働後の撤退基準（事前に決めておく）

**戦略を止める条件を、動かす前に数値で決める。** 動かした後に決めると、必ず「もう少し様子を見よう」になる（FP-013）。

| # | 撤退トリガー | 対応 |
|---|---|---|
| E1 | 最大DDが検証時のOOS最大DDの**1.5倍**を超えた | 即時停止・要因分析 |
| E2 | 直近30トレードの勝率が、検証時の95%下限を下回った | 縮小（ロット半減）して観察 |
| E3 | 同一エラーが**3回連続**で発生した | 即時停止・通知（FP-005、FP-006） |
| E4 | シグナル一致率が98%を下回った | 即時停止・実装バグとして扱う |
| E5 | 戦略の前提が崩れた（例: 取引所の手数料体系変更、規制変更） | 停止して再検証 |

**新しく良さそうな戦略が見つかったことは、稼働中の戦略を止める理由にならない**（FP-013）。停止は E1〜E5 のいずれかに触れたときだけ。
