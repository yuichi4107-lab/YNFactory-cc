## 1. 目的

**「ターン・オブ・ザ・マンス効果は、2022年以降も効いているのか」に白黒をつける。**
効いていれば実弾1万円で動かす。効いていなければ止める。

利益を狙うのが目的ではない。期待値は年率0〜6%、1万円に対して**年0〜600円**である。
これは金額としては無意味だが、**「自動売買システムを最後まで動かし切った」という事実**には価値がある。
過去4か月、それが一度もできていない。

## 3. 戦略の定義（CR-33）

```
毎月、月末の N 営業日前に BTC/JPY を買い、翌月の M 営業日目に売る。
N と M は検証で決める（初期値 N=1, M=3）。
保有していない期間はポジションを持たない。
損切り: 建値から -8%（後述の B-01 対応）
```

年24トレード。保有日数は月4日程度（年間の13%）。

**この戦略を選んだ理由は、儲かりそうだからではない。**
動かせるパラメータが窓の定義しかなく**過剰最適化のしようがない**こと、
論文の検証期間が2021年8月までで**2022年以降が完全なアウトオブサンプル**になること、
そして**検証コストが最小で白黒が最も早くつく**こと。この3点による。

## 4. 工程（8週間・40時間）

### S0: 検証（8時間）★ここで中止の判断をする

1. GMOコイン公開APIで BTC/JPY 日足（2018-09〜2026-08）を取得する
2. CR-33 を実装する（ロジックは10行程度）
3. **2018-09〜2022-07 を IS、2022-08〜2026-08 を OOS** として分離する
   （論文の検証期間が2021年8月までのため、2022年8月以降が真のOOSになる）
4. コスト 1.0倍 / 1.5倍 / 2.0倍 で計算する（往復0.1%＝年2.4%が基準）
5. N・M の探索は **3×3の9通りまで**。試行回数を記録する

**判定**
- **OOS でコスト2.0倍でも黒字 → S1 へ進む**
- **OOS で赤字 → 中止する。** 別の戦略に乗り換えない（FP-013）

> S0 で赤字が出たら、それは失敗ではない。**8時間で「やらなくていい」と分かった**ということである。
> 旧システムは同じ判断に4か月かけて到達できなかった。

### S1: ペーパートレード（16時間）

- シグナル生成（S0 のコードをそのまま使う。**再実装しない**）
- ペーパー executor（発注せず記録のみ）
- 日次通知（Telegram・1通）
- 停止機構（`data/STOP` ファイルの存在で全停止）
- **2週間の並走**。シグナルが検証と一致することを確認する

### S2: 実弾1万円（16時間）

- GMOコイン発注アダプタ（S1 の executor を差し替えるだけ）
- 安全装置5件（§5）
- **最初の1トレードは1,000円**。約定を確認してから1万円へ

## 5. 安全装置（レビューの Blocker を修正済み）

MVP-0 では5件に絞る。**それぞれレビューで指摘された欠陥を潰した形で定義する。**

| # | 装置 | 設定 | 修正した Blocker |
|---|---|---|---|
| SF-1 | 1トレードの損失上限 | **建値から -8% の損切り注文を必ず同時に出す。** Signal は `stop_price` を必須項目とし、これが無いシグナルは RiskGate が拒否する | **B-01**（損切り価格が存在しなかった） |
| SF-2 | 発注の再試行 | 冪等キーは「注文の意図」に対して発行し、**送信ごとに `attempt` 番号を付けた client_order_id を使う**。これにより再試行が取引所に届き、失敗カウンタが増える | **B-02**（冪等キーが再試行を弾き、無言で止まる） |
| SF-3 | ドローダウンによる停止 | **毎サイクル（1日1回）、価格を取得して評価額とDDを再計算する。** 約定の有無に依存しない。DD **25%** で全停止（CR-33 の想定DD 10〜20% の外側） | **B-03**（約定駆動でDDが更新されず発火しない）／**B-08**（閾値が想定DDの内側） |
| SF-4 | 連続失敗による停止 | 同一 **エラーコード**（メッセージ文字列ではない）が同一の注文意図に対して3回連続したら停止。**別注文の成功でリセットしない** | **B-04**（文字列判定で3回連続が永久に成立しない） |
| SF-5 | 停止機構 | `data/STOP` ファイルが存在すれば、起動時とサイクル開始時に発注せず終了する。**受信APIを持たない**（SSHでtouchするだけ） | **B-05**（kill switch の入力経路が存在しなかった） |

**口座残高の定義**（B-07 の解消）: MVP-0 は暗号資産の単一口座のみを扱う。
「口座残高」＝ GMOコイン暗号資産口座の JPY 残高 ＋ BTC 評価額。市場をまたぐ合算は発生しない。

**記録の形式**（B-06 の解消）: `orders` テーブルを持たず、**追記のみのイベントログ 1本**にする。
現在の状態はイベントから導出する。更新も削除もしないので、追記のみと状態管理が衝突しない。

**フォワード検証ゲート**（B-09 の解消）: 「3か月かつ30トレード」は撤回する。
MVP-0 では **S1 で2週間ペーパー並走 → S2 で実弾1,000円 → 1万円** と段階を刻む。
CR-33 は年24トレードなので、30トレードは13か月かかる。**待たずに小さく実弾に触れる。**

## 6. 中止条件（着手前に確定させる）

**動かす前に決める。動かした後に決めると必ず「もう少し様子を見よう」になる。**

| # | 条件 | 判定 |
|---|---|---|
| D-1 | 8週間で実弾に到達できない | 中止 |
| D-2 | 累積40時間を超えて実弾未到達 | 中止 |
| D-3 | S0 の OOS でコスト2.0倍が赤字 | 中止（別戦略に乗り換えない） |
| D-4 | 実弾開始から6か月で年率換算 +3.6% 未満 | 中止 |
| D-5 | 戦略の乗り換えが1回発生 | 中止（**FP-013 への直接の対策**） |
| D-6 | DD 25% で全停止した | 再開しない |
| D-7 | 障害対応が月3件または月10時間を超える | 中止 |

**中止は失敗ではない。** 中止条件を持たずに動かし続けることが失敗である。
