## ゴール

`gemini-2.5-flash-image` の日本語テキスト描画能力不足を根本解消するため、
Blind-OCR + Pillow合成フォールバック（A+Bハイブリッド）を `ebook-to-manga` スキルに
本実装し、全ページで合格率100%を保証するパイプラインに刷新する。

---

## スコープ

### やること

- テンプレ1〜7 の全コマ領域定義を JSON ファイルとして事前作成する（Step 5.5 の前提）
- Step 4 CSV 仕様に構造化データ列（panel_id / type / speaker / text）を追加する
- Step 5 の画像生成ループを「生成 → Blind-OCR判定 → N回失敗でフォールバック」に改修する
- Step 5.5（Pillow合成モジュール）をスキルの新規ステップとして追加する
- 改修後パイプラインの E2E 動作確認手順をスキル内に明記する

### やらないこと（Phase 2 以降）

- 顔検出（OpenCV / Mediapipe）による吹き出し位置の自動最適化
  - 理由: 吹き出し衝突の頻度は低く、Pillow 側で固定アンカーでも概ね許容範囲内
         実装コストが大きいわりにリターンが限定的なため Phase 2 に先送り
- コマ領域 JSON の自動検出（画像解析でテンプレを動的に認識する仕組み）
  - 理由: テンプレは 7 種類固定であり、手動定義で十分カバー可能
- Blind-OCR の部分一致（NFKC正規化後の編集距離による曖昧マッチ）
  - 理由: プロトタイプで完全一致で十分な精度が確認できた
- 他スキルへの転用・汎用ライブラリ化
  - 理由: 本作業は ebook-to-manga スキルの改修のみ

## 工程1: コマ領域 JSON 作成

### 概要

Pillow 合成時にコマへのテキスト配置座標を決定するための
テンプレ1〜7 全コマ領域定義 JSON ファイルを作成する。

保存先: `.claude/skills/ebook-to-manga/panel_regions.json`

### JSON 仕様

```json
{
  "template_1": {
    "1": [x1, y1, x2, y2]
  },
  "template_2": {
    "1": [x1, y1, x2, y2],
    "2": [x1, y1, x2, y2]
  },
  ...
  "template_7": {
    "1": [x1, y1, x2, y2],
    "2": [x1, y1, x2, y2],
    "3": [x1, y1, x2, y2]
  }
}
```

- 座標値はページ全体（W, H）に対する正規化比率（0.0〜1.0）
- panel_id は CSV の panel_id と対応する整数キー（文字列として格納）
- プロトタイプの実測値を参照基準とする:
  - テンプレ5: `PANEL_REGIONS_T5`（`hybrid_loop.py` 行102〜106）
  - テンプレ6: `PANEL_REGIONS_T6`（`composite_page5.py` 行66〜70）
  - テンプレ1〜4, 7 はテンプレ構成から合理的に推算して定義

## 工程3: Blind-OCR 判定モジュール仕様

### 概要

Step 5 内で使用する Blind-OCR 判定の仕様を skill.md に記述する。
プロトタイプ `blind_ocr_check.py` および `hybrid_loop.py` の実装をスキル仕様に昇格させる。

### 仕様内容

以下 3 点を skill.md に明記する:

1. **OCR プロンプト設計原則**
   - 期待テキストを一切 Gemini に提示しない（confirmation bias 排除）
   - 対象: 吹き出し（楕円・雲形）と ナレーションボックス（四角枠）のみ
   - 対象外: オノマトペ、背景看板、スマホ画面、服ロゴ
   - 出力形式: JSON のみ（`bubbles`: panel_id / type / detected_text）
   - temperature=0.0 固定、モデル: `gemini-2.5-flash`

2. **テキスト比較ロジック**
   - NFKC 正規化 + 空白・改行除去 → 完全一致判定（決定論的）
   - (panel_id, type) をキーとして期待値と検出値を突き合わせ
   - 1コマに同 type が複数ある場合は最初にマッチしたものを採用
   - 全テキスト項目が一致した場合のみ `PASS`、1項目でも不一致なら `FAIL`

3. **フィードバック注入**
   - FAIL 時: 不一致の (パネル番号, type, 期待テキスト, 検出テキスト) をプロンプト末尾に追記
   - 形式: `◆【前回失敗・最重要】` セクション

## 工程4: Pillow 合成モジュール仕様（Step 5.5 新規追加）

### 概要

N 回連続 FAIL 後のフォールバックとして実行する Pillow 合成の仕様を
Step 5.5 として skill.md に追加する。

### 仕様内容

以下を skill.md の Step 5.5 として記述する:

1. **発動条件**
   - Step 5 で `max_iter`（既定 3）回連続して FAIL した場合のみ発動
   - 通常の PASS では Step 5.5 はスキップ

2. **処理フロー**
   - clean regen: プロンプトから全テキスト・吹き出し・ナレーションボックス指示を除去し、
     キャラクター + 背景のみの画像を再生成
   - Pillow 合成: `panel_regions.json` からコマ領域を取得し、CSV の `コマ別テキストJSON` の
     全テキスト項目を縦書き（tategaki）でオーバーレイ

3. **合成ルール（プロトタイプ準拠）**
   - セリフ（dialogue）: 白楕円吹き出し + 三角テール + 縦書きテキスト（太字フォント・22pt相当）
   - ナレーション（narration）: 白四角ボックス + 縦書きテキスト（通常フォント・18pt相当）
   - 配置優先度: ナレーションを先にコマ右上に配置、次にセリフをコマ左側に配置
   - 縦書きルール: 長音符（ー/〜/…）は -90度回転描画
   - フォント: Windows 環境は `YuGothB.ttc`（Bold）/ `YuGothM.ttc`（Regular）を使用
     ※ 環境依存のため、フォントパスは `FONT_BOLD` / `FONT_REG` 変数で管理

4. **保存**
   - 出力: `pages/page_{NNN}_composited.jpg`（JPEG, quality=92）
   - 元の FAIL 画像は `pages/page_{NNN}_iter_{N}.jpg` として保持（監査用）

## 工程5: Step 5 ループ改修

### 概要

現行 Step 5（単純な生成 + 失敗ページのリトライ）を、
A（Blind-OCR判定）+ B（Pillowフォールバック）のハイブリッドループに全面改訂する。

### 改訂後の Step 5 フロー

```
ページごとに:
  iter = 1 .. max_iter (既定 3)
    [A] 画像生成（テキスト埋め込みプロンプト）
    [A] Blind-OCR（gemini-2.5-flash, temperature=0.0, 期待テキスト非提示）
    [A] プログラム比較（NFKC正規化 + 完全一致）
    if PASS → このページ完了、次ページへ
    if FAIL → フィードバック注入 → 次 iter へ
  iter 超過（max_iter 回全 FAIL）:
    [B] clean regen（テキスト無し）
    [B] Pillow 合成（CSV の コマ別テキストJSON から期待テキストを取得）
    → このページ完了（100%正確テキスト保証）
```

### 廃止される現行仕様

- 「全バッチ完了後、失敗ページがあればリトライする」（単純リトライ）
  → 上記ループ内の iter 管理 + フォールバックに置き換え
- 「問題のあるページは個別に再生成する」（手動確認ステップ）
  → 自動化されるため不要（Pillow合成後は自動的に合格とみなす）

### 維持される現行仕様

- 10ページずつのバッチ処理 + バッチ間 5 秒待機
- `progress.json` による進捗管理
- テキストページのスキップ
- JPEG 保存（quality=92）
