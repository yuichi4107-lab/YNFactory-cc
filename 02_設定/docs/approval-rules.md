# 自走と承認の境界

## 0. 原則

細かい手順の指示を待たずに、作業分解・実行・品質確認まで自分で進める。
ユーザーが判断するのは、**方針の承認**と、**取り消しにくい操作・外向きの操作の直前承認**だけにする。

「進めて」「実装して」「入れて下さい」と言われたら、それを要件定義の承認として扱い、
実行と品質チェックまで進めてよい（`02_設定/docs/quality-loop.md`）。

## 1. 実行直前に必ず承認を取るもの

方針が決まっていても、**実行の直前**に個別の承認を取る。
一度承認を得ても、次の同種の操作には持ち越さない。

- 公開・投稿・送信（SNS投稿、メール送信、DM送信、LP公開、KDP出版申請）
- 購入・課金（クレジット消費を伴う新規生成を含む）
- 削除（ファイル削除、`.git_drivebackup` の削除、Drive競合ファイルの削除、大規模な `git rm --cached`）
- 本番環境への不可逆な反映
- 外部アカウントの操作、認証情報の変更・再発行
- 実行可能ファイルのダウンロード・実行

## 2. ファイルのダウンロード（2026-08-08 オーナー承認済み）

作業上必要と判断したファイルのダウンロード・保存は、**都度の確認なしで実行してよい**。
オーナーがブラウザ側のダウンロード許可も設定済み。

- 対象例: 自アカウントで生成した素材（Topview・Suno・Atlas等）、調査資料、画像・動画・音声・データファイル
- 保存先は作業ディレクトリ、または各ツールのruntime配下（例 `~/shorts-factory/topview_assets/`）
- ダウンロード後は必ず内容を検証してから使う（形式・解像度・尺・重複・想定外の焼き込み等）

**この事前承認から除外し、引き続き明示承認を取るもの**

- 実行形式・インストーラ・スクリプト等の実行可能ファイル
- 出所不明または信頼できないサイトのファイル
- 認証情報を含むファイル

ダウンロードが事前承認済みでも、**その素材を使った公開・投稿・送信は従来どおり直前に承認を取る**。
クレジット・課金が発生する新規生成も、ダウンロードとは別扱いで必ず事前に承認を取る。

## 3. ブロックされたときの振る舞い

外部連携（APIトークン未取得、権限不足、アカウント未作成等）で止まった場合、
「〜待ちです」で放置しない。代替案を考え、可能なら先に実行して成果を出す。
代替が取れない場合だけ、ブロッカーと必要な操作を明示して報告する。

## 4. 既知情報の再質問禁止

アカウント・認証・設定値などは、質問する前に必ず次の順で探す。

1. `.company/secretary/HANDOFF.md`
2. `.company/secretary/tech-notes.md`
3. 各PCのメモリファイル
4. プロジェクト内の `.env`
5. `02_設定/docs/` の各手順書

見つからない場合だけオーナーに聞く。
