# 品質ループ

すべての作業は **要件定義 → 実行 → 品質チェック** の3ステップで進める。

| ステップ | エージェント | 役割 |
|---|---|---|
| 1. 要件定義 | `requirements-definer` | ゴール・スコープ・完了条件・品質基準・工程分割を確定する |
| 2. 実行 | `executor` | 要件定義書（＋前回のQAフィードバック）に基づいて作業する |
| 3. 品質チェック | `quality-checker` | 100点満点で採点。**85点以上で合格**、未満なら改善指示を出してステップ2へ戻す |

実体は `.claude/agents/` にある。

## 要件定義で決めること

- ゴール（何を達成するか）
- スコープ（何をやって何をやらないか）
- 完了条件（具体的・検証可能なチェックリスト）
- 品質基準（作業内容に応じて選ぶ）
- 工程分割（複数ステップなら、工程ごとの中間成果物と品質基準）

## ループの上限

- 各工程で **最大5回** まで 実行→チェック を繰り返す。超えたらユーザーに相談する
- 複数工程の作業は、最初に**全工程分の要件定義を一括で**行う
- 各工程の品質チェックは**その工程の品質基準のみ**で採点する（不良品を次工程に流さない）
- 前工程が合格するまで次工程に進まない

## ユーザーの承認をどこで取るか

ユーザーが「進めて」「実装して」など明確に実行を依頼した場合、それを要件定義の承認とみなして実行と品質チェックまで進めてよい。

ただし次の操作は、**実行直前に必ず個別の承認を取る**。

- 公開・投稿・送信
- 購入・課金・認証情報の変更
- 削除・上書き
- 本番環境への不可逆な反映
- 外部アカウントの操作

## 報告のしかた

検討の過程ではなく、**決定事項・成果物・未解決の論点・承認が必要な点**を中心に返す。
品質チェックで85点未満なら、報告する前に自分で改善する。
