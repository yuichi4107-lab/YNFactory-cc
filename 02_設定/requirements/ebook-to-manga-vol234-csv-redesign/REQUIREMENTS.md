## スコープ

### やること

- vol2・vol3・vol4 の既存 pages/ を日付付きアーカイブフォルダへ移動
- vol2・vol3・vol4 の comicle_output.csv を、manuscript のストーリーから再構築（1コマ最大30文字）

## 工程分割戦略（提案: CSV先行まとめ作成）

vol2・vol3・vol4 のCSV再構築を先にまとめて行ってから、画像生成をまとめてキューに投入する方式を推奨する。

**理由:**
1. CSV作成はClaudeがinlineで実行できる（外部依存なし）
2. 画像生成（codex-handoff）は各巻1バンドルずつ、Codex CLIを起動するユーザー操作が必要
3. CSVが3巻分揃ってからまとめてキュー投入することで、Codexの起動回数を最小化できる
4. vol2→vol3→vol4の順で直列生成（並列生成はAPIコスト・監視の煩雑化を避けるため）

### codex-handoff バンドル配置先

```
.company/codex/queue/manga-career-restart_vol2_{YYYYMMDD_HHMMSS}/
    manifest.json
    characters/         ← manuscript/characters/ から全6キャラPNGをコピー
    gen_manga_bundle.py ← .company/codex/_spec/gen_manga_bundle.py からコピー
    TASK.md
    csv/
        comicle_output.csv  ← vol2の新CSV
    templates/          ← テンプレ1-7.jpg をコピー
```

> 注: job-id 形式は `.company/codex/CLAUDE.md` の規定に従い `{book_id}_vol{N}_{YYYYMMDD_HHMMSS}` を使用する（`prod_` 接頭辞は付けない）。

1. `done/<job-id>/progress.json` を読み込む

## 備考

### codex-handoff フォルダ命名規則

`.company/codex/CLAUDE.md` の規定（`{book_id}_vol{N}_{YYYYMMDD_HHMMSS}`）に従い以下を使用する:
```
manga-career-restart_vol2_{YYYYMMDD_HHMMSS}
manga-career-restart_vol3_{YYYYMMDD_HHMMSS}
manga-career-restart_vol4_{YYYYMMDD_HHMMSS}
```

### vol1との並行進行について

vol1は `manga-career-restart_vol1_prod_20260425_201900` ジョブが `.company/codex/queue/` に存在しCodex処理中。
本要件定義書の作業はvol2から開始し、vol1のジョブとは干渉しない。

### ページ数上振れ時の判断ポイント

工程2（vol3 CSV）完成後にページ数が220枚を超える場合、コスト上限（$53）を超過する可能性がある。
この場合は executor が実測ページ数とコストをユーザーへ報告し、承認を得てから工程5（画像生成）へ進む。

### 旧生成スクリプトの扱い

vol2・vol4の `regen_*.py`、vol3の `regen_phase*.py` は今回の作業では使用しない。
アーカイブはせず各巻フォルダに残置する（混乱防止のため参照しないこと）。
