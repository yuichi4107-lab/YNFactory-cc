# Phase 8: 本番移行（Google SRE PRR 準拠）

## 目的

Phase 7 で検証済みのシステムを本番環境に移行する。
Google SRE の Production Readiness Review（PRR）フレームワークに基づき、10領域を評価して安全にリリースする。

---

### 1-1. アーキテクチャ

```markdown
## アーキテクチャ評価

### チェックリスト
- [ ] SDD の設計と実装が一致している
- [ ] 単一障害点（SPOF）がない、または許容範囲内
- [ ] コンポーネント間の依存関係が明確
- [ ] スケールアウト/スケールアップの方針が決まっている
- [ ] 障害時の影響範囲が特定されている

### 評価基準
- OK: 設計通り実装、SPOF 対策済みまたは許容範囲
- LOW-NG: 軽微な設計乖離あり、修正計画あり
- HIGH-NG: 重大な設計問題、根本修正が必要
```

### 1-2. 容量

```markdown
## 容量評価

### チェックリスト
- [ ] 想定される負荷量を見積もっている
- [ ] 現在のリソースで想定負荷を処理できる
- [ ] ディスク使用量の増加ペースを把握している
- [ ] メモリ使用量のピーク値を把握している
- [ ] API呼び出し回数が制限内に収まる

### 評価基準
- OK: 想定負荷の 2倍まで余裕あり
- LOW-NG: 想定負荷は処理可能だが余裕が少ない
- HIGH-NG: 想定負荷を処理できない
```

### 1-3. 信頼性

```markdown
## 信頼性評価

### チェックリスト
- [ ] エラーハンドリングが全コンポーネントに実装されている
- [ ] リトライ機構が実装されている
- [ ] 障害時の復旧手順が文書化されている
- [ ] データの整合性が保証されている
- [ ] 冪等性が確保されている

### 評価基準
- OK: 障害時に自動復旧可能、データ損失なし
- LOW-NG: 手動復旧が必要だが手順は明確
- HIGH-NG: 障害時にデータ損失の可能性あり
```

### 1-4. 監視

```markdown
## 監視評価

### チェックリスト
- [ ] 正常動作の確認方法が定義されている
- [ ] エラー発生時の検知方法が定義されている
- [ ] ログが適切に出力されている
- [ ] 監査ログが記録されている
- [ ] アラート条件が定義されている（該当する場合）

### 評価基準
- OK: 異常を自動検知可能、ログで原因追跡可能
- LOW-NG: ログはあるが自動検知は未実装
- HIGH-NG: 障害に気づく手段がない
```

### 1-5. セキュリティ

```markdown
## セキュリティ評価

### チェックリスト
- [ ] APIキーが環境変数ファイルのみで管理されている
- [ ] 入力バリデーションが実装されている
- [ ] セキュリティスキャン（bandit等）が PASS
- [ ] 依存パッケージに既知の脆弱性がない
- [ ] 機密情報がログに出力されない
- [ ] 環境変数ファイルが版管理から除外されている

### 評価基準
- OK: セキュリティチェックリスト全項目 PASS
- LOW-NG: MEDIUM 以下の指摘があるが対策計画あり
- HIGH-NG: HIGH の脆弱性がある、またはAPIキーの漏洩リスクあり
```

### 1-6. 自動化

```markdown
## 自動化評価

### チェックリスト
- [ ] ビルドが自動化されている
- [ ] テストが自動実行できる
- [ ] デプロイ手順が文書化（またはスクリプト化）されている
- [ ] ロールバック手順が自動化（またはスクリプト化）されている
- [ ] 定期タスクが自動化されている

### 評価基準
- OK: ビルド→テスト→デプロイが1コマンドで完了
- LOW-NG: 一部手動手順あり、文書化済み
- HIGH-NG: 手動手順が多い、文書化もない
```

### 1-7. 外部依存

```markdown
## 外部依存評価

### チェックリスト
- [ ] 外部APIの SLA/稼働率を把握している
- [ ] 外部API障害時のフォールバックが実装されている
- [ ] 外部API の料金/レート制限を把握し、制限内で運用可能
- [ ] 外部API の利用規約に違反していない
- [ ] 外部API のバージョン固定/互換性管理ができている

### 評価基準
- OK: 全外部依存に対してフォールバックあり
- LOW-NG: 一部の外部依存にフォールバックなし、影響は限定的
- HIGH-NG: 重要な外部依存にフォールバックなし
```

### 1-8. スケジュール

```markdown
## スケジュール評価

### チェックリスト
- [ ] リリース日が決定している（または柔軟に設定できる）
- [ ] リリース前の最終チェック項目が定義されている
- [ ] リリース後の監視期間が設定されている
- [ ] 問題発生時の対応体制が決まっている

### 評価基準
- OK: スケジュール通りにリリース可能
- LOW-NG: 軽微な遅延の可能性あり
- HIGH-NG: 大幅な遅延の可能性あり
```

### 1-9. 成長性

```markdown
## 成長性評価

### チェックリスト
- [ ] ユーザー数/データ量の増加に対応できる設計
- [ ] 新機能追加が容易な構造
- [ ] 設定変更だけで対応できる範囲が明確
- [ ] V2/V3 へのアップグレードパスが見えている

### 評価基準
- OK: 想定の 5倍まで設計変更なしで対応可能
- LOW-NG: 想定の 2倍程度で設計見直しが必要
- HIGH-NG: 現状で限界に近い
```

## 2. PRR 総合判定

### 判定マトリクス

| 条件 | 判定 | 次のアクション |
|---|---|---|
| 10領域全て OK | **承認** | 本番移行を実施 |
| HIGH-NG = 0、LOW-NG ≤ 3 | **条件付き承認** | 対策を実施しつつ移行 |
| HIGH-NG ≥ 1 または LOW-NG ≥ 4 | **延期** | 修正後に再評価 |

### 判定記録テンプレート

```markdown
## PRR 総合判定

### 判定: [承認 / 条件付き承認 / 延期]
```

## 3. 段階的ロールアウト

### 4段階展開

| 段階 | 対象 | 期間 | 監視項目 | 次段階の条件 |
|---|---|---|---|---|
| **Stage 1** | 1件（自分だけ） | 1-3日 | 基本動作、エラー有無 | エラーなし |
| **Stage 2** | 10%（テストユーザー） | 3-7日 | 性能、エラー率 | エラー率 1% 以下 |
| **Stage 3** | 50% | 7-14日 | 全指標 | 全指標正常 |
| **Stage 4** | 100% | 継続 | 全指標 | - |

### 各段階の監視チェックリスト

```markdown
### Stage [N] 監視チェックリスト

- [ ] 基本動作が正常（期待通りの出力が得られる）
- [ ] エラーが発生していない（ログにERROR/CRITICALがない）
- [ ] 処理時間が許容範囲内
- [ ] ディスク/メモリ使用量が許容範囲内
- [ ] 外部API呼び出しが制限内
- [ ] 監査ログが正常に記録されている

### 異常検知時のアクション
1. 即座に前段階にロールバック
2. 原因を調査
3. 修正後、再度同段階から展開
```

### CLI/個人ツールの場合の簡略版

```markdown
社長個人利用のCLIツールの場合:

Stage 1: DRY_RUN=true で実行し、出力を確認（1日）
Stage 2: DRY_RUN=false で1件だけ実行（1日）
Stage 3: バッチ実行（少量）（3日）
Stage 4: 通常運用
```

## 4. 監視とロールバック

### 監視項目

| # | 監視項目 | 正常値 | 異常値 | 検知方法 |
|---|---|---|---|---|
| 1 | エラー率 | 0-1% | 5%超 | ログ集計 |
| 2 | 処理時間 | SRS記載の基準内 | 基準の2倍超 | タイマー計測 |
| 3 | ディスク使用量 | 増加ペース安定 | 急増 | df コマンド |
| 4 | API呼び出し数 | 制限の50%以下 | 制限の80%超 | カウンター |
| 5 | 出力品質 | 期待通り | 品質低下 | サンプリング検査 |

### ロールバック計画

```markdown
## ロールバック計画

### RTO（復旧目標時間）: [N分/N時間]
### RPO（復旧目標時点）: [最後の正常状態]

### ロールバック手順

1. 異常を検知
2. 現在の処理を安全に停止（キルスイッチ or Ctrl+C）
3. 問題のあるバージョンを無効化
4. 前バージョンに切り替え
5. 前バージョンで正常動作を確認
6. 原因調査を開始

### ロールバック条件（以下のいずれか）
- エラー率が 5% を超えた
- 処理時間が基準の 3倍を超えた
- データの整合性が崩れた
- 外部APIの呼び出し制限に近づいた（80%超）
- セキュリティインシデントが発生した

### ロールバック不要の条件
- 一時的なネットワーク障害（リトライで回復）
- 外部APIの一時的なエラー（自動復旧）
- 非クリティカルなログ出力エラー
```
