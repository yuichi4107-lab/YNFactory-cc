# Phase 7: E2E 実行と自己検証

## 目的

Phase 6 で実装したコードを実際に動かし、「本当に動くか」を証拠をもって証明する。
AIの自己申告（「テスト通りました」）を信頼せず、決定論的センサーの結果のみを信頼する。

---

## 1. 自己実行テストの原則

### 信頼しないもの

| 信頼しない | 理由 |
|---|---|
| AIの「テスト通りました」発言 | 実行せずに言える |
| テスト結果の要約だけ | 全件実行していない可能性 |
| 「問題ないと思います」 | 思うだけでは証拠にならない |
| 前回のテスト結果 | コード変更後は無効 |

### 信頼するもの

| 信頼する | 理由 |
|---|---|
| テスト実行コマンドの標準出力 | 機械が出力した事実 |
| カバレッジレポートの数値 | 計測結果 |
| リントツールの出力 | 静的解析の結果 |
| E2E テストのログファイル | 実行時の記録 |

### 検証の鉄則

```
全てのテストは、実際にコマンドを実行し、
その出力結果をログに記録して初めて「検証済み」と言える。
```

```
1. 失敗したセンサーを特定
2. エラーメッセージを全文記録
3. 原因を分析
4. 修正を実施
5. 失敗したセンサーだけでなく、全センサーを再実行
6. 結果を再記録
```

## 3. 仕様ドリフト検出（Spec Drift Detection）

実装が仕様（SRS/SDD）から乖離していないかを検出する。

### SD-01: 定期チェック（週次）

```markdown
### SD-01 チェックリスト

- [ ] SRS の全 Must 要件が実装に反映されている
- [ ] SDD のコンポーネント構成と実際のディレクトリ構成が一致している
- [ ] ADR の決定事項が実装に反映されている
- [ ] CONSTRAINTS.md の制約が実装で守られている
- [ ] トレーサビリティマトリクスが最新状態

実行頻度: 週1回（またはリリース前）
```

### SD-02: 実装後チェック（毎回）

```markdown
### SD-02 チェックリスト

各コンポーネントの実装完了時に確認:

- [ ] コンポーネントのインターフェースが SDD 通り
- [ ] 入出力の型が SDD のデータモデル通り
- [ ] エラーハンドリングが SDD のプロセスビュー通り
- [ ] 横断的ルール（CC-01〜CC-05）が適用されている
- [ ] 対応する要件ID（FR-*）が全てカバーされている
```

### SD-03: テスト改竄検出

テストコード自体が「通るように書き換えられていないか」を検出する。

```markdown
### SD-03 チェックリスト

- [ ] テストの assert が具体的な値を検証している（`assert True` は禁止）
- [ ] テストが実際に対象コードを呼び出している（スタブだけのテストは不可）
- [ ] E2E テストが実際にシステムを起動して実行している
- [ ] モックの戻り値が現実的（空オブジェクトや固定値だけではない）
- [ ] カバレッジの数値が前回から不自然に下がっていない
- [ ] テストケース数が SRS の要件数と整合している
```

### テスト改竄の典型パターン（検出対象）

| パターン | 例 | 問題 |
|---|---|---|
| 空 assert | `assert True` | 何も検証していない |
| 固定値比較 | `assert result == result` | 自分自身と比較 |
| 例外握りつぶし | `try: ... except: pass` | エラーを無視 |
| テスト無効化 | `@pytest.mark.skip` の乱用 | テストを飛ばしている |
| モック過多 | 対象コードを一切呼ばない | テストの意味がない |

## 6. 完了ルール

### 絶対ルール: 1つでも未達なら「完了」と言わない

```
以下の全てを満たした場合のみ「Phase 7 完了」と報告できる:

1. 決定論的センサー8種が全て PASS
2. E2E テスト6シナリオが全て PASS（RYG = Green）
3. 仕様ドリフト検出（SD-01, SD-02, SD-03）が全て PASS
4. PROGRESS.md の DoD チェックリスト全項目チェック済み
5. テスト改竄の兆候がない

1つでも未達の場合:
→ 「Phase 7 検証中、未達項目: [具体的な項目名]」と報告する
→ 修正して再検証する
→ 修正できない場合は社長にエスカレーションする
```
