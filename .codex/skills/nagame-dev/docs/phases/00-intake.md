# Phase 0: 質問駆動型ヒアリング

## 目的

社長の頭の中にある「作りたいもの」を、曖昧さゼロの仕様に変換するための情報収集フェーズ。
質問によって要件を引き出し、全ての曖昧さを解消してから次フェーズへ進む。

---

## 1. 初期7質問（必須）

セッション開始時、以下の7問を必ず確認する。社長が既に情報を提供済みの場合はスキップ可。

| # | 質問 | 目的 | 回答例 |
|---|---|---|---|
| Q1 | **何を作るか？** | システムの全体像を掴む | 「YouTube動画を自動生成するパイプライン」 |
| Q2 | **誰の課題を解決するか？** | ユーザー像と課題を特定 | 「自分自身。動画制作に毎日3時間かかっている」 |
| Q3 | **MVPの範囲は？** | 最小限の完成形を定義 | 「台本から字幕付き動画が1本出れば十分」 |
| Q4 | **形式は？（Web/CLI/API等）** | 技術選定の方向性 | 「CLIで動けばいい。UIは不要」 |
| Q5 | **制約は？（予算/期間/技術）** | 現実的な制約を把握 | 「予算月5000円以内、今週中、Python希望」 |
| Q6 | **失敗したくない点は？** | リスク回避の優先順位 | 「API課金が暴走して高額請求が来ること」 |
| Q7 | **既存資料はあるか？** | 過去の検討結果を活用 | 「去年作りかけた仕様書がある」 |

### 実行手順

1. 7問を一度に提示する（1問ずつ出すと社長の手間が増える）
2. 回答が返ったら、各回答を「5段階分類」（後述）で仕分ける
3. 不明点があれば追加質問を行う

---

## 2. 12フェーズ段階質問

初期7問の回答を踏まえ、以下の12フェーズで詳細を掘り下げる。
全フェーズを一度に聞くのではなく、**1-2フェーズずつ順番に確認**する。

### フェーズ一覧

| # | フェーズ | 確認内容 | 主な質問例 |
|---|---|---|---|
| P1 | **目的と成功条件** | なぜ作るか、何をもって成功か | 「このシステムが完成したら、何が変わる？」 |
| P2 | **利用者と業務フロー** | 誰がどう使うか、現状の手順 | 「今の作業手順を1から教えてほしい」 |
| P3 | **スコープ** | やること/やらないこと/後回し | 「これはMVPに入る？入らない？」 |
| P4 | **機能要件** | 具体的な機能一覧 | 「ボタンを押したら何が起きる？」 |
| P5 | **データ** | 入出力、保存、形式 | 「どんなデータを扱う？どこに保存？」 |
| P6 | **外部連携** | API、サービス、認証 | 「外部サービスは何を使う？」 |
| P7 | **非機能要件** | 性能、可用性、セキュリティ | 「同時に何人が使う？落ちたらどうなる？」 |
| P8 | **受入基準** | 完成の判定条件 | 「何ができたら合格？」 |
| P9 | **テスト** | 検証方法、テストデータ | 「どうやって正しく動いていると確認する？」 |
| P10 | **実装計画** | 順序、優先度、マイルストーン | 「最初に何から作る？」 |
| P11 | **レビュー計画** | 誰がいつレビューするか | 「途中で確認したいタイミングは？」 |
| P12 | **最終文書化** | 成果物一覧、引き継ぎ | 「ドキュメントはどこまで必要？」 |

### 実行手順

1. P1-P2 を確認 → 回答を仕分け
2. P3 を確認（スコープ確定は早めに行う）
3. P4-P6 を確認 → 機能と連携の全体像を固める
4. P7-P9 を確認 → 品質基準を固める
5. P10-P12 を確認 → 進め方を合意

---

## 3. 回答5段階分類

社長の回答を以下の5段階に仕分け、次のアクションを決定する。

| 分類 | 判定条件 | 次のアクション | 表記 |
|---|---|---|---|
| **確定** | 明確な回答がある | そのまま要件として記録 | `[確定]` |
| **仮置き** | 方向性はあるが詳細未定 | 仮置き（★）として記録、後で確定 | `[仮置き★]` |
| **矛盾** | 他の回答と矛盾している | 矛盾を指摘して質問 | `[矛盾→質問]` |
| **選択肢提示** | 判断材料が不足 | 2-3個の選択肢を提示して選んでもらう | `[選択肢提示]` |
| **保留** | 今は決められない | Later として記録、次フェーズ以降で再確認 | `[Later]` |

### 仕分け例

```
Q1: 何を作るか → 「YouTube動画の自動生成」 → [確定]
Q3: MVPの範囲 → 「まだ決めてない」 → [選択肢提示]
Q5: 制約 → 「予算は月5000円」だが Q6 で「高品質API使いたい」 → [矛盾→質問]
```

### 仮置き（★）の運用ルール

- 仮置きは必ず `★` マークを付ける
- Phase 2（SRS）開始前までに全ての仮置きを確定させる
- 確定できない仮置きは Later に格下げし、スコープ外にするか判断を仰ぐ

---

## 4. スコープ仕分け

全ての機能・要件を以下の3つに分類する。

| 分類 | 意味 | 扱い |
|---|---|---|
| **IN SCOPE** | MVPに含める | SRS に記載、実装対象 |
| **OUT OF SCOPE** | 今回やらない | SRS に「対象外」として明記 |
| **DEFER** | 将来やるかもしれない | SRS に「延期」として明記、Phase 2以降で再検討 |

### スコープ表テンプレート

```markdown
## スコープ表

### IN SCOPE（MVP対象）
- [ ] 機能A: 台本テキストから動画を自動生成
- [ ] 機能B: 字幕の自動付与
- [ ] 機能C: BGMの自動付与

### OUT OF SCOPE（対象外）
- サムネイル自動生成（今回は手動）
- YouTube自動アップロード（手動で対応）

### DEFER（延期）
- 複数言語対応（英語字幕等）
- テンプレート切り替え機能
```

## 6. Phase 0 完了条件

以下の全てを満たした場合のみ、Phase 1（リサーチ）へ進む。

### 完了チェックリスト

- [ ] 初期7問の全てに回答がある（Laterは2個以下）
- [ ] P1-P3（目的・利用者・スコープ）が確定している
- [ ] P4-P6（機能・データ・外部連携）の主要項目が確定または仮置き
- [ ] 仮置き（★）が5個以下
- [ ] 矛盾が全て解消済み
- [ ] スコープ表（IN/OUT/DEFER）が作成済み
- [ ] 社長が「これで進めて」と承認した

### 完了できない場合

- 仮置きが6個以上 → 追加質問で確定を増やす
- 矛盾が残っている → 矛盾を指摘して社長判断を仰ぐ
- スコープが不明確 → 「最小MVP」を提案して合意を取る

---

## 7. 注意事項

- **質問攻めにしない**: 1回のメッセージで聞くのは3-5問まで
- **例を出す**: 抽象的な質問には具体例を添える
- **社長の言葉をそのまま記録**: 言い換えず、原文を保持する
- **迷ったら選択肢**: 社長が答えに困ったら、2-3個の選択肢を提示する
- **早めにスコープを切る**: 「全部やりたい」は危険信号。MVPを絞る
