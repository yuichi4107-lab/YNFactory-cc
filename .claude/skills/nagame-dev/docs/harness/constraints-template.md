# CONSTRAINTS.md テンプレート（6セクション構成）

プロジェクト固有の CONSTRAINTS.md を自動生成する際の雛形。
SRS/SDD 分析に基づいてプロジェクト固有の制約を追加する。

---

## 使い方

1. H-NEW 実行時に `~/claude-harness/templates/CONSTRAINTS.md.template` からコピーされる
2. SRS/SDD の内容を分析し、プロジェクト固有の制約（`[project-specific]` 部分）を追加する
3. `~/claude-harness/knowledge/failure_patterns.md` から関連する FP-XXX を参照し、過去の失敗に基づく制約を追加する
4. 追加した制約には必ず根拠（FP-XXX または SRS/SDD の要件番号）を紐付ける

---

## テンプレートからの生成手順

### 手順 1: テンプレートをコピー
H-NEW 実行時に `~/claude-harness/templates/CONSTRAINTS.md.template` をプロジェクトルートにコピーする。

### 手順 2: プロジェクト情報を埋める
- `[VERSION]` → `v1.0.0`
- `[YYYY-MM-DD]` → 生成日
- `[PROJECT_NAME]` → プロジェクト名
- `[TEMPLATE_VERSION]` → テンプレートの現在バージョン

### 手順 3: SRS/SDD 分析から制約を追加
SRS の各機能要件（FR-XXX）と SDD のアーキテクチャを分析し:
- 認証が必要 → C-SEC に認証関連の制約を追加
- DB を使う → C-DATA にDB関連の制約を追加
- 外部API連携 → C-SEC にAPI連携の制約を追加
- リアルタイム処理 → C-CODE に並行処理の制約を追加

### 手順 4: 過去の失敗パターンを確認
`~/claude-harness/knowledge/failure_patterns.md` を参照し:
- 類似プロジェクトで発生した FP-XXX がないか確認
- 該当するものがあれば、対応する C-XXX が既にテンプレートに含まれているか確認
- 含まれていなければ追加する

### 手順 5: 変更履歴を記入
初版の変更履歴を記入する。

---

## 制約の追加・変更ルール

- **追加**: プロジェクト進行中に新しい失敗が発生したら、即座に制約を追加する
- **変更**: 制約の変更は人間（社長）の承認が必要（C-AI-006）
- **削除**: 制約の削除は原則禁止。不要になった場合は「deprecated」マークを付ける
- **番号**: 一度付けた C-XXX 番号は再利用しない（欠番は許容）
