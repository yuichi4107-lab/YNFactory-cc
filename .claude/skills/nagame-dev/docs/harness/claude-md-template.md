# CLAUDE.md 13パート構成テンプレート

プロジェクト固有の CLAUDE.md を自動生成するためのテンプレートと運用ルール。
200行以下に収める。超過する場合は docs/harness/ に詳細を移動して参照する。

---

## 使い方

1. H-NEW 実行時に `~/claude-harness/templates/CLAUDE.md.template` からコピーされる
2. `[PLACEHOLDER]` 部分をプロジェクト情報で埋める
3. SRS/SDD の分析結果に基づいてプロジェクト固有の項目を追加する
4. 200行を超えたら詳細を別ファイルに移動する

---

## テンプレート本体

```markdown
# [PROJECT_NAME] — CLAUDE.md

## PART A: プロジェクト情報 ★毎セッション確認
- プロジェクト名: [PROJECT_NAME]
- 目的(1文): [このプロジェクトが何を実現するか]
- 技術スタック: [言語 / フレームワーク / DB / インフラ]
- 現在フェーズ: Phase [N] — [フェーズ名]
- 現在セッション: [N]

## PART B: 完了基準 (Definition of Done)
1. [ ] 全 Must 機能が実装済み（SRS の IN SCOPE 全件）
2. [ ] 全テスト通過（カバレッジ 80%以上）
3. [ ] E2E シナリオ全 PASS
4. [ ] セキュリティチェック完了（PART F 全項目）
5. [ ] スペックドリフトなし（SD-01 で HIGH ドリフト 0件）
6. [ ] レビュー GO 判定
7. [ ] PROGRESS.md 最新

## PART C: 作業ルール
- 承認制: コード変更は必ず人間の確認を取る
- 1コミット1変更: 1つのコミットに複数の無関係な変更を含めない
- スペックドリフト防止: ドリフト発見時は SD-ALERT 形式で即報告
- ファイルに書く: 会話での合意はその場でファイルに反映する

## PART D: 絶対禁止事項
- 本番DB直接操作禁止（dry-run → ステージング → マイグレーション経由）
- テスト削除・改ざん禁止（テストが通らない場合は実装を修正する）
- force push 禁止（変更履歴は保持する）
- SRS 未記載機能の追加禁止（新機能は SRS 追記 → 承認後に実装）
- APIキー・シークレット直書き禁止（環境変数経由のみ）
- CONSTRAINTS.md の無断変更禁止（変更は人間の承認後のみ）
- 50往復超のセッション継続禁止（→ session-mgmt.md）

## PART E: セッション管理
- 開始時: PROGRESS.md 読了 → 前回の続きから再開
- 終了時: PROGRESS.md 更新 → git commit
- 50往復超: 即座にセッション切替（例外なし）
- 詳細: → docs/harness/session-mgmt.md

## PART F: セキュリティチェックリスト
- [ ] 認証・認可設計済み
- [ ] データ保護（暗号化・マスキング）設計済み
- [ ] 外部連携の安全設計済み（API キー管理・通信暗号化）
- [ ] 入力検証設計済み（型チェック・範囲チェック・サニタイズ）
- [ ] 依存パッケージの脆弱性チェック済み

## PART G: 本番移行チェックリスト（Google SRE PRR 準拠）
- [ ] アーキテクチャレビュー完了
- [ ] 容量計画策定済み（想定負荷・スケーリング戦略）
- [ ] 監視・アラート設定済み
- [ ] ロールバック手順文書化済み
- [ ] 運用ドキュメント完備

## PART H: RYG ゲート
- **Green**: 次フェーズへ進行 OK。全チェック項目クリア
- **Yellow**: sandbox / PoC のみ許可。本番操作禁止。注意事項あり
- **Red**: 停止。再設計・再リサーチが必要。進行禁止

## PART I: スペック検証スケジュール
- 週1回: SD-01（定期チェック）実行
- 実装完了時: SD-02（受入条件検証）実行
- テスト変更時: SD-03（テスト改ざん検出）実行
- 詳細: → docs/harness/spec-drift.md

## PART J: ハーネス設計
- dry-run: 破壊的操作は必ず dry-run を先に実行
- sandbox: 本番と分離された環境でテスト
- rollback: ロールバック手順を事前に用意
- 承認フロー: 重要操作は人間の承認を得てから実行
- 操作ログ: 全操作を記録（PROGRESS.md + git log）

## PART K: テスト計画概要
- Unit テスト: 各モジュールの単体テスト
- Integration テスト: モジュール間連携テスト
- E2E テスト: エンドツーエンドシナリオテスト
- dry-run テスト: 本番相当環境での事前確認
- Acceptance テスト: SRS の受入条件に基づく検証
- Regression テスト: 変更による既存機能への影響確認
- 詳細: → docs/TEST_PLAN.md

## PART L: 成長型ハーネス
- 知識蓄積: ~/claude-harness/knowledge/ に失敗・成功パターンを記録
- テンプレート進化: ~/claude-harness/templates/ を常に最新に保つ
- プロジェクト完了時: H-UPDATE を必ず実行（知識の移行）
- 詳細: → docs/harness/three-layers.md

## PART M: 変更履歴
| 版 | 日付 | 変更内容 |
|---|---|---|
| v1.0.0 | [YYYY-MM-DD] | 初版作成（テンプレートから生成） |
```

## 200行ルール

CLAUDE.md は Claude Code が毎セッション開始時に読むファイル。
長すぎると読了に時間がかかり、重要な指示が埋もれる。

### 判断基準

各パートについて以下を自問する:
**「この記述を CLAUDE.md から削除すると、Claude がミスをするか?」**

- **YES** → CLAUDE.md に残す
- **NO** → docs/harness/ に移動し、CLAUDE.md からは参照リンクだけ残す

### 移動の例

| 内容 | CLAUDE.md に残す | docs/harness/ に移動 |
|---|---|---|
| 禁止事項の一覧 | 残す（毎回確認が必要） | - |
| 禁止事項の詳細な根拠 | - | 移動（根拠は別ファイルで十分） |
| DoD のチェックリスト | 残す（完了判定に必須） | - |
| テスト計画の詳細 | - | 移動（概要だけ残す） |
| セッション管理の手順概要 | 残す（50往復ルールの存在を知らせる） | - |
| セッション管理の詳細手順 | - | 移動（手順書は別ファイル） |

### 参照リンクの書き方

```markdown
- 詳細: → docs/harness/session-mgmt.md
```

CLAUDE.md 内で「→」の後にファイルパスを書く。
Claude は必要に応じて参照先を読みに行く。

## プロジェクト固有カスタマイズのガイドライン

### 必ずカスタマイズするパート

| パート | カスタマイズ内容 |
|---|---|
| PART A | プロジェクト名・目的・技術スタック |
| PART B | プロジェクト固有の完了条件（カバレッジ目標等） |
| PART D | プロジェクト固有の禁止事項 |
| PART F | プロジェクトのセキュリティ要件 |

### カスタマイズ不要なパート（テンプレートのまま使う）

| パート | 理由 |
|---|---|
| PART C | 作業ルールは全プロジェクト共通 |
| PART E | セッション管理は全プロジェクト共通 |
| PART H | RYG ゲートの定義は全プロジェクト共通 |
| PART L | 成長型ハーネスの仕組みは全プロジェクト共通 |

---

## PART A の更新タイミング

PART A はプロジェクトの「現在地」を示す。以下のタイミングで更新する:

- **フェーズ遷移時**: `現在フェーズ` を更新
- **セッション切替時**: `現在セッション` を更新
- **技術スタック変更時**: `技術スタック` を更新（稀）

他のパートはプロジェクト開始時に設定し、基本的に変更しない（変更する場合は PART M に記録）。
